# 界面设计

> 安装器的画面该长什么样：颜色与符号的含义、状态的写法、各类画面的版式要点、深浅色与无颜色时的要求。内容取自任务 `10-09-oxy-tools-installer` 的 `ui-direction.md`（维护者 2026-10-09 选定的视觉方向），**任务归档后以本文件为准**。
> 呈现层怎么实现这些规则、交互库有哪些要配合的脾气，见 [终端输出](./terminal-output.md)。
> 用词：正文说「宿主」；界面文案里它显示为「AI Agent」（见 `GLOSSARY.md`）。

---

## 方向：账本

像一丝不苟的库管员递来的清单——每样东西在哪一栏、什么状态，一眼扫到底。

- 通栏横线分区，标题嵌在线里；条目排成表格，一条一行；本机信息、提醒、出错的原因与下一步都写成“键 值”对齐的行。**没有边框。**
- 黑白为主，颜色很少，状态一律用词表达。
- 交互库是 `@inquirer`（只装用到的四个提示子包：`select`、`checkbox`、`password`、`confirm`）。选它是因为提示的前缀、图标、活动行、禁用样式、说明、按键提示都能由呈现层来配，不可选的行能直接给原因，列表下方有位置放光标所在行的说明全文。

美观的边界：只在配色、符号、间距、横线、标题区这些静态元素上发挥，且限于交互库在真实终端里做得出来的效果。不为好看自写交互控件，不做全屏界面；除了加载与进行中的那一个转动符号，没有任何动画。

**要改画面，先改本文件，再改实现**，然后生成界面预览页对照（见文末）。别让两边各走各的。

## 版式的总规则

- **按 80 列设计**，正文每行右侧留一列不用（通栏横线和分区标题线除外，它们正好到第 80 列；整条写在一行上的网址和路径也不受这条限制，见下面「折行」一条）。更窄的终端不专门适配。
- **宽度按显示宽度算**：汉字和全角标点占两列，其余占一列，对齐和截断都按这个算。
- **折行由呈现层做**：西文按词断，中文可在任意两字之间断，行首不放收尾标点。不依赖终端自己折。例外只有网址和路径——它们整条写在一行上，折开了就没法照着复制。
- **截断用 `…` 收尾**，只截列表里的说明；名字、状态、路径、命令从不截断。
- **栏宽按内容定**：每一栏取这一栏里最长的一格再加两格间隔，剩下的宽度给说明。不写死栏宽。
- **不用表情符号**：不同终端对它的宽度算法不一致，会把对齐打乱。
- **不做全屏界面**：所有输出顺着往下打，已回答的提问收成一行留在屏幕上。

## 颜色的含义

只用终端的标准命名色，真实色值由用户自己的终端配色决定。唯一的例外是大标志的渐变，见下面「大标志的颜色」。

| 颜色 | 含义 | 用在哪 |
|------|------|--------|
| 洋红 `magenta` | 当前焦点 | 提问标记 `?`、光标 `▸`、已勾选的框 `■`、进行中的转动符号。**只用在符号上，不用在文字上**。和大标志是一个色系；安装器的输出里没有青色 |
| 绿 `green` | 已就绪 | 已装、已配置、已安装、已可用、检测到的 `✓`、成功 |
| 黄 `yellow` | 需要留意 | 版本不同、非本工具安装、覆盖、命令里的 key 占位符、注意 |
| 红 `red` | 失败与出错 | 失败、`✗`、出错的标题 |
| 暗淡 `dim` | 次要信息 | 表头、横线、键值行的键、未装、未配置、不支持、未安装、按键提示里的动作词、不可选的行 |
| 粗体 `bold` | 主要信息 | 产品名、提问、分区标题、光标所在行；黄色和红色的词一律同时加粗 |
| 下划线 `underline` | 链接 | 申请地址、应用项目的链接 |

表里的词指的是状态栏里的状态词、结果行的结果词和行首的标记。合计行里的「成功」「失败」、汇总的备注（`0.9.0 → 1.0.0`、`非本工具安装，另行确认`）、结果行里跟在「已安装」后面的版本，都是默认前景色；「目录」「合计」两行里的 `·` 也是默认色，暗淡的 `·` 只在已回答的提问和按键提示里。

四条硬规则，来自对比度的实测（两套代表性配色，近似 VS Code 默认的深色与浅色终端；4.5:1 是正文字号下通行的可读门槛）：

| | 正文 | 暗淡 | 红 | 绿 | 黄 | 蓝 | 洋红 | 青 |
|---|---|---|---|---|---|---|---|---|
| 深色背景 | 11.1 | 3.7 | 3.4 | 7.2 | 13.1 | 3.6 | 3.9 | 6.3 |
| 浅色背景 | 11.2 | 2.7 | 5.1 | 5.4 | 3.1 | 7.7 | 5.4 | 3.4 |

1. **名字、说明、命令和汇总里的位置一律用终端的默认前景色**，颜色只落在状态词和符号上。除了绿，没有一种命名色在两种背景上都达到 4.5:1。
2. **只用八个基本色**，不用亮色变体，也不显式指定黑和白：亮色在浅色背景上发虚，白字在浅色背景上看不见。次要信息用 `dim`，不用灰（亮黑）。例外只有大标志的渐变，它用 24 位色。
3. **`dim` 只给真正次要的东西**：它在浅色背景上只有 2.7:1。一句话说明不算次要；不可选的行的原因是用户最需要读的字，保持正常亮度。
4. **黄色和红色的词同时加粗**：黄在浅色背景上只有 3.1:1，加粗后才不至于比旁边的普通字更弱。

### 大标志的颜色

大标志是全屏唯一不用命名色的东西（维护者 2026-10-10 选定）：

| 情况 | 标志的颜色 |
|------|------------|
| 环境变量 `COLORTERM` 是 `truecolor` 或 `24bit` | **从左到右的渐变**，24 位色：粉 `#E255C0` → 紫 `#8B5CF6` → 蓝 `#3D8FE6`。按列算，同一列的方块同色；最左一列正好是粉，正中一列是紫，最右一列是蓝。O 偏粉，X 是紫，Y 偏蓝 |
| 别的终端 | 整个标志是**洋红**（八个基本色之一），和焦点符号同色。不做 256 色的近似 |
| 不显示颜色（环境里有 `NO_COLOR`，或输出不是终端） | 不上色，和别的输出一样 |
| 没有 Unicode | ASCII 字符画，粗体，不上色：不画渐变，也不用洋红 |

三个色标在那两套代表性配色上的对比度：

| | `#E255C0` | `#8B5CF6` | `#3D8FE6` |
|---|---|---|---|
| 深色背景 `#181818` | 5.3 | 4.2 | 5.3 |
| 浅色背景 `#ffffff` | 3.3 | 4.2 | 3.3 |

标志是图形不是正文，按图形对象通行的 3:1 来看两边都够。渐变只用在标志上：正文、状态词、符号仍然只用上表的命名色。

**已知的弱点，尚未解决**：「未装」「未配置」「不支持」和不可选的行的名字是暗淡的，黄色的词即使加粗也只有 3.1:1，它们在浅色背景上都偏淡。这是有意的取舍——暗淡表示“退后”，含义不靠它传达——但历次视觉评审都指出了它，维护者没有就这一点表过态。可行的改法：这几个状态词改用默认前景色；黄色的词改成默认色粗体，黄色只留在行首的标记上。

**在真实终端里看到的两条（2026-10-10，macOS「终端.app」的 Pro 深色与 Basic 浅色，工单 12）**，同样没有改，等维护者表态：

- 大标志的实心方块在行距比字高大的字体下，行与行之间露出背景，OXY 读成几排横条（Pro 配色下最明显）。这是终端字体与行距的事，界面预览页里看不到。
- Basic 浅色配色的绿比上表那套代表性配色更淡：不加粗的「已安装」「已配置」「已可用」和 `✓` 是除暗淡之外最淡的字。含义靠词，仍读得出；要不要给绿色的词也加粗，没有定。

## 深色、浅色、不显示颜色、没有 Unicode

| 情况 | 要求 |
|------|------|
| 深色与浅色终端 | 同一份输出在两种背景上都要清晰；靠上面四条硬规则保证，不为某一种背景另写一套 |
| 不显示颜色（环境里有 `NO_COLOR`，或输出不是终端） | 颜色、粗体、暗淡、下划线都没有，**文字一字不变**，每种状态仍然读得出来：状态是词不是色，占位符靠尖括号认，不可选的行靠行首的符号和行里的原因认 |
| 没有 Unicode 的终端（Windows 旧式控制台、Linux 的内核控制台） | 符号整体退成 ASCII（下面“符号的含义”右栏），大标志换成 ASCII 字符画，按键提示里的 `↑↓`、`⏎` 换成文字（中文「上下键」「回车」，英文 `up/down`、`enter`）。维护者已过目并认可（2026-10-09） |

上不上色、用不用 Unicode 是怎么判断的，见 [终端输出](./terminal-output.md)。

## 状态的写法

状态一律用词表达，放在自己的一栏里。状态栏里用短词「已装」省栏宽；结果行说的是刚做完的动作，写「已安装」。

| 对象 | 状态 | 写法 | 颜色 |
|------|------|------|------|
| skill | 未安装 | `未装` | 暗淡 |
| skill | 已安装（本工具装的） | `已装 2.16` | 「已装」绿，版本号默认色 |
| skill | 已安装且与 skill 清单的版本不同 | `2.0.0 → 2.1.0`（已装的在左，清单的在右） | 黄，粗体 |
| skill | 已存在但不是本工具装的 | `非本工具安装` | 黄，粗体 |
| MCP | 未配置 | `未配置` | 暗淡 |
| MCP | 已配置 | `已配置` | 绿 |
| MCP | 未知（读不了宿主的配置） | `未知` | 默认色 |
| MCP | 这个宿主不支持 | `不支持` | 暗淡 |
| 工具 | 未安装 | `未安装` | 暗淡 |
| 工具 | 已安装 | `已安装` | 绿 |

skill 和 MCP 每个所选的宿主各占一栏，栏名就是宿主的名字；工具只有一栏「状态」。

## 符号的含义

| 符号 | 含义 | 没有 Unicode 时退成 |
|------|------|---------------------|
| `?` `✓` | 提问中 / 已回答 | `?` `+` |
| `▸` | 光标所在行 | `>` |
| `■` `□` `–` | 多选：已勾选 / 未勾选 / 不可选 | `[x]` `[ ]` `[-]` |
| `-` | 单选里不可选的行（交互库写死的行首） | 不变 |
| `✓` `✗` `–` | 成功 / 失败 / 跳过 | `+` `x` `-` |
| `✓` `–` | 本机信息里的宿主：检测到 / 未检测到 | `+` `-` |
| `⠋ ⠙ ⠹ ⠸ ⠼ ⠴ ⠦ ⠧ ⠇ ⠏` | 进行中，每 80 毫秒一帧 | `-` `\` `\|` `/` |
| `──` | 分区横线，标题嵌在线里 | `--` |
| `→` `·` `…` | 版本变化 / 分隔 / 截断 | `->` `-` `...` |
| `$` | 正在执行的命令 | 不变 |
| 实心方块 | OXY 大标志：渐变，终端不支持 24 位色时是洋红 | ASCII 字符画，粗体，不上色 |

## 标题区：OXY 大标志

```

                            ██████  ██   ██ ██    ██
                           ██    ██  ██ ██   ██  ██
                           ██    ██   ███     ████
                           ██    ██  ██ ██     ██
                            ██████  ██   ██    ██

                                oxy-tools 0.1.0

```

- 启动后最先打出，**一次运行只出现一次**：回到主菜单时不重复；没有交互式终端时不打印；`--help`、`--version` 和参数无法识别时也不打印。
- 五行实心方块，从左到右由粉到紫到蓝；终端不支持 24 位色时整个是洋红，不显示颜色时不上色（见「大标志的颜色」）。字形宽 25 列，每一行左边补 27 格，整个标志在 80 列里居中（左右空白差不超过一列）。**按 80 列居中，不看终端的实际宽度**：窗口再宽，它也不和下面靠左排的内容脱开。
- 标志上方空一行；下方空一行，然后是同样按 80 列居中的产品名（粗体）加版本号（暗淡）；再空一行。
- 标志四周是留白：下面不画通栏横线，旁边也没有一句话说明。「策展式 AI 工具链安装器」只留在包的 README 和包描述里，不上终端。
- 标题区自己以空行收尾：紧跟其后的是分区标题时（启动后立刻出错），分区标题上方不再另空一行，免得连着两行空行。
- 没有 Unicode 时换成 ASCII 字符画，粗体，不上色，同样的摆法（字形宽 20 列，左边补 30 格）：

```

                                ___  __  ____   __
                               / _ \ \ \/ /\ \ / /
                              | | | | \  /  \ V /
                              | |_| | /  \   | |
                               \___/ /_/\_\  |_|

                                oxy-tools 0.1.0

```

## 横线、分区与键值行

- **通栏横线**：80 列、暗淡。只用在两处：本机信息下方、结果与合计之间。大标志下方不画。
- **分区标题**：`── 标题 ───…` 到行尾，标题粗体、线暗淡，上方空一行（画面的第一行除外；紧跟在标题区后面时也不另空，标题区自己以空行收尾）。汇总、将执行的命令、key 的说明、正在安装与结果、每个工具的执行、应用项目详情、出错，各是一个分区。出错的标题是红色粗体，以「出错：」开头。
- **键值行**：缩进两格，键占 10 列、暗淡，值用默认色；值过长时折行，续行与值的左缘对齐。提醒用键值行表达，键是黄色粗体的「注意」。
- **表格**：表头一行暗淡的列名，之后每行各栏按显示宽度补齐；同一条目的后续行不重复名字。表头永远只有一行。
- **已回答的提问**收成一行：绿色的 `✓`、提问、暗淡的 `·`、回答。
- **按键提示**：按键本身（`↑↓`、`⏎`、空格…）用默认前景色，动作词和中间的 `·` 暗淡。整行必须在 79 列以内。
- 一条线只做一件事，不叠双线。

## 各类画面的版式要点

下面的画面取自界面预览页，是安装器真实的输出（为了短，有的删了几行条目或几行命令的输出）；条目是预览用的样例。

### 启动与加载

标题区之后一行：缩进两格，洋红的转动符号、「正在读取目录」、暗淡的省略号。读完后这一行被本机信息取代。输出不是终端时不转。

### 主菜单

```
  AI Agent  Claude Code ✓   Codex ✓
  目录      8 skill
────────────────────────────────────────────────────────────────────────────────

? 选择分组
  分组   数量  说明
▸ Skill     8  装进 AI Agent 的能力包

  退出

   ↑↓ 移动 · ⏎ 选择
```

- 上方是本机信息的键值行，再用一条通栏横线收住，空一行：
  - 「AI Agent」：每个宿主一格，之间空三格。检测到的后面跟绿色的 `✓`；没检测到的写「– 未检测到」，名字照常、只有短横暗淡。
  - 「目录」：各类的数量，用 `·` 隔开，只数有条目的分组。
  - 「注意」（有才写，一件事一行）：只检测到一个宿主时说明另一个被跳过、组件只装进检测到的那个；一个都没检测到时说明暂时装不了组件；目录里有写坏的条目时说明跳过了几条。
- 菜单是三栏的表：分组、数量（右对齐）、说明。**只列有条目的分组**；「退出」与分组之间空一行。
- 光标所在行整行加粗，行首是洋红的 `▸`。
- 从某个分组回到主菜单、或在汇总里选「返回修改」回到列表时，新一轮的提问与上面已回答的几行之间空一行。

一个宿主都没检测到时，三类组件的分组不可进入，只有应用项目进得去：

```
  AI Agent  Claude Code – 未检测到   Codex – 未检测到
  目录      8 skill · 4 应用项目
  注意      没有检测到 Claude Code 或 Codex，暂时装不了组件；应用项目仍可浏览
────────────────────────────────────────────────────────────────────────────────

? 选择分组
  分组      数量  说明
- Skill        8  装进 AI Agent 的能力包 · 需要 AI Agent
▸ 应用项目     4  需要自行部署，这里只给链接

  退出

   ↑↓ 移动 · ⏎ 选择
```

- 不可进入的分组整行暗淡，行首是 `-`，行尾注明「需要 AI Agent」，这几个字保持正常亮度。
- 光标起始落在第一个进得去的项上（有应用项目就是它，没有就是「退出」）。目录里没有应用项目时，「注意」不写后半句「；应用项目仍可浏览」。
- 光标移得到不可进入的行上，这时行首换成洋红粗体的 `▸`（和别的行上的光标同一个样子，三类组件的列表里也一样）、其余仍暗淡；按确认进不去，列表下方多一行黄色粗体的「注意」加「这一项现在选不了」，再按别的键这一行就消失。

### 选择宿主

```
? 装进哪些 AI Agent
▸■ Claude Code  ~/.claude/skills
 ■ Codex        ~/.agents/skills

   ↑↓ 移动 · 空格 选择 · a 全选 · i 反选 · ⏎ 确认（不选则返回）
```

- 只在检测到两个宿主、且要装的是 skill 或 MCP 时出现；多选，两项默认全选。
- 没有表头。装 skill 时名字后面暗淡地写它的 skill 目录，装 MCP 时不写。
- 回答后收成一行，列出勾选的名字。

✓ 装进哪些 AI Agent · Claude Code、Codex
? 选择要安装的 skill

 ■ explanation         0.9.0 → 1.0.0  已装 1.0.0    把任何内容改写到聪明的 12…
 □ if5                 已装 1.0.0     未装          像给 5 岁小孩那样解释一个…
 ■ pr                  非本工具安装   未装          撰写 PR（合并请求）描述
▸■ wizard              未装           未装          生成交互式 bash 向导，带人…

   说明  生成交互式 bash 向导，带人走完只能由人完成的步骤
   ↑↓ 移动 · 空格 选择 · a 全选 · i 反选 · ⏎ 确认（不选则返回）
```

三类组件的列表是同一个画法：

- 栏：名称、状态（skill 和 MCP 每个所选的宿主一栏，工具一栏）、说明。说明过长则截断。
- 光标所在行整行加粗，状态词也跟着加粗。
- 列表下方：光标所在行的说明全文（缩进三格，以暗淡的「说明」开头，标签后空两格，过长则折行），再下一行是按键提示。「这一项现在选不了」那一行是同一个画法。说明里的要紧信息（如体积提示）在列表里可能被截掉，但勾选时光标必然在这一行，全文此时就在下方。
- 条目一次全部列出，不分页；多到一屏放不下时才让交互库滚动。状态每次进列表都现探测。
- **返回**：一个都不勾就确认，回到上一步；按键提示末尾用括号写明「不选则返回」（英文 `none = back`）。回答后收成的一行列出勾选的名字，用顿号隔开（英文用逗号）；一个都没勾就写「返回」。
- **不可选的条目**：整行暗淡，勾选位是 `–`，原因保持正常亮度。光标移得到它上面，按空格勾不上，下方多一行「注意  这一项现在选不了」。原因写在哪，一张表里只用一种：

| 列表 | 什么时候不可选 | 原因写在哪 |
|------|----------------|------------|
| MCP | 所选的宿主一个都不支持它 | 行尾，接在说明后面：`… · 需要别的 AI Agent` |
| 工具 | 当前系统不支持；或它要的宿主一个都没检测到 | 状态栏的位置：`不支持 macOS`、`需要别的 AI Agent` |

- **部分支持的 MCP 仍可选**（维护者已定）：条目只支持所选宿主中的一部分时只装进支持的那些，不支持的那一栏写暗淡的「不支持」，汇总里只列会装的。
- 读不到某个宿主的配置时，已回答的提问和 MCP 列表之间多一行「注意」，那一栏每一条都是「未知」。
- 工具不问装进哪个宿主；已安装的照样可选。

### 填写 key

```
── exa 需要 key ────────────────────────────────────────────────────────────────
  变量      EXA_API_KEY（必填）
  用途      Exa 搜索 API 的密钥；注册后有免费额度，在控制台的 API Keys 页创建
  申请      https://dashboard.exa.ai/api-keys
  提示      输入不会显示在屏幕上；留空回车将跳过 exa

? EXA_API_KEY (输入不显示，粘贴后回车)
```

- 每个 key 一个分区。标题必填的是「<MCP> 需要 key」，可选的是「<MCP> 可选的 key」；四行键值：变量（注明必填或可选）、用途、申请地址（下划线，整条写在一行上）、提示（留空会怎样）。
- 输入时屏幕上不显示任何字符，也不暴露长度；提问后面是一句暗淡的固定提示。
- 回答之后提问整个擦掉，留下一行结局，和已回答的提问同一个画法。**填了的不写值，也不写长度**：

```
✓ EXA_API_KEY · 已填写
– CONTEXT7_API_KEY · 可选，已跳过
– EXA_API_KEY · 必填，未填写；将跳过 exa
✓ EXA_API_KEY · 本次运行已填写，不再询问
```

### 汇总确认

skill：

```
── 将安装 3 个 skill ───────────────────────────────────────────────────────────
  条目    AI Agent     操作  位置                     备注
  if5     Claude Code  覆盖  ~/.claude/skills/if5     重装 1.0.0
  pr      Claude Code  覆盖  ~/.claude/skills/pr      非本工具安装，另行确认
  wizard  Claude Code  新装  ~/.claude/skills/wizard

  注意      覆盖即整目录替换，目录内的本地改动会丢失

? 开始安装吗
▸ 开始安装
  返回修改
  取消

   ↑↓ 移动 · ⏎ 选择
```

MCP（表之后多一个「将执行 N 条命令」分区）：

```
── 将安装 1 个 MCP ─────────────────────────────────────────────────────────────
  条目  AI Agent     操作
  exa   Claude Code  新装

── 将执行 1 条命令 ─────────────────────────────────────────────────────────────
   1  claude mcp add --scope user exa -e EXA_API_KEY=<EXA_API_KEY> -- npx -y
      exa-mcp-server

  注意      key 以占位符显示，执行时才代入真实的值

? 执行这些命令吗
```

- 标题数的是条目的个数，不是行数。选了两个宿主时每个条目在每个宿主下各一行，后一行不重复名字；某个宿主不支持的 MCP，那个宿主没有它的行。
- **操作**：「新装」默认色；「覆盖」黄色粗体；MCP 状态未知时写「添加」，默认色。
- **备注**用默认色。skill：版本不同写 `2.0.0 → 2.1.0`，版本相同写「重装 2.1.0」，不是本工具装的写「非本工具安装，另行确认」。MCP：已配置的写「已配置，先移除再添加」，状态未知的写「状态未知，先尝试移除同名配置」。
- **备注整张表一个放法**：每一条都放得下才成一栏；有一条放不下就全部另起一行，表头不写「备注」。一条备注都没有时表头也不写。另起一行时，skill 的备注与「位置」的左缘对齐；MCP 的从「操作」一栏的左缘起，那里放不下就整张表的备注一起往左挪。
- skill 的表多一栏「位置」，逐行写出将装到的目录。有覆盖项时表后空一行，一行「注意」说明覆盖即整目录替换；全是新装时没有这一行。
- **将执行的命令**：每条前面是暗淡的右对齐序号，完整写出；过长时折行，续行与命令的左缘对齐，从不截断。命令里的 key 一律是黄色粗体的占位符 `<变量名>`。
- 命令之后空一行，要提醒的事各占一行「注意」：因为必填的 key 没填而不安装的 MCP、key 以占位符显示、Codex 添加远程地址的 MCP 时可能当场打开浏览器登录（维护者已定）。
- 确认是一个单选，三类组件同一个画法：开始安装（MCP 和工具是「执行」）、返回修改、取消。
- 不是本工具装的目录在选了「开始安装」之后逐个另问，是否题，默认否，紧接在已回答的那一行下面：`? ~/.claude/skills/pr 不是本工具装的，要覆盖它吗？ (y/N)`。输入了别的再回车不结束提问，下方多一行「注意  请输入 y 或 n」。

### 执行中与结果

```
── 结果 ────────────────────────────────────────────────────────────────────────
  ✓  explanation  Claude Code  已安装 0.9.0 → 1.0.0
  ✓  explanation  Codex        已安装 1.0.0
  –  pr           Claude Code  跳过 未同意覆盖，保持原样
  ✓  pr           Codex        已安装 1.0.0
  ✗  wizard       Claude Code  失败 下载中断（HTTP 503），目标目录未改动
  ✗  wizard       Codex        失败 下载中断（HTTP 503），目标目录未改动
────────────────────────────────────────────────────────────────────────────────
  合计      3 成功 · 2 失败 · 1 跳过
```

- skill 和 MCP 共用一个分区：执行中标题是「正在安装」，结束后改写成「结果」。每行：结果符号、名字、宿主、结果词加版本或原因。
- 成功是绿色的「已安装」（MCP 是「已配置」，没有版本号）；「失败」红色粗体；「跳过」默认色且行首是暗淡的 `–`。原因过长时折行，续行与原因的左缘对齐。
- 进行中的那一行以洋红的转动符号开头，写「正在下载…」（MCP 是「正在配置…」）；这一项结束后整行改写成结果。安装 skill 之前先有一行转动的「正在查询 skill 的文件列表…」。
- 结束后一条通栏横线，下面一行「合计」：成功、失败、跳过三项固定都写，是 0 也写；数的是行数。之后回到主菜单。
- MCP 也有「跳过」：必填的 key 没填的那个 MCP，每个宿主一行 `–  exa  Claude Code  跳过 未填写必填的 EXA_API_KEY`。勾上的全都因此被跳过时，没有汇总、不问执行不执行，已回答的那几行之后直接是「结果」分区。
- **失败的原因只写我们自己的话**：哪一步、退出状态或错误码（`失败 添加命令退出状态 1；此前已执行移除`）。不转述宿主命令或安装命令自己打出来的话。

   1  uv        curl -LsSf https://astral.sh/uv/install.sh | sh
   2  openspec  npm install -g @fission-ai/openspec@latest

✓ 执行这些命令吗 · 执行

  ✓  uv        已可用，在 PATH 中找到 uv

────────────────────────────────────────────────────────────────────────────────

```

- 先用一个分区列出全部命令（序号、工具名、命令），命令是一整行，**原样写出、不加引号**；再问一次。
- 每个工具一个以它名字为标题的分区，第一行是暗淡的 `$` 加命令；**命令自己的输出原样透传，顶格、不加任何样式**。
- 结束后空一行，一行结论，以复核为准：「已可用」绿，「失败」红色粗体。命令非零退出但复核通过算已可用，退出状态照实写在后面。
- 装了不止一个时，合计之前用「结果」分区把各项的结论原样再列一遍（维护者已定：前面的结论早被输出顶出屏幕了）；只装一个时不重复。
- 执行中没有转动符号，标题也不回头改写：命令的输出在往同一个终端上写。

### 应用项目

```
── open-webui ──────────────────────────────────────────────────────────────────
  说明      自托管的大模型对话界面，可接 Ollama 与各家 API
  链接      https://github.com/open-webui/open-webui
  ✓  已在默认浏览器打开；打不开时请复制上面的链接
```

- 列表是单选的两栏表（名称、说明），末尾一项「返回」，与条目之间空一行，和主菜单的「退出」同一个画法。
- 选中后是一个以它名字为标题的分区：说明全文、带下划线的链接，再一行结局。**链接再长也整条写在一行上**，超过 80 列时由终端自己折。

- 打不开**不算出错**：那一行换成黄色粗体的「注意」键值，写「没能打开浏览器，请复制上面的链接自行打开」。没有红色，没有出错分区。

### 出错

```
── 出错：无法读取目录 ──────────────────────────────────────────────────────────
  原因      读不到 index.json（ENOTFOUND）
            https://raw.githubusercontent.com/LFT-OXY/oxy-Tools/main/index.json
  下一步    检查网络连接后重新运行
            网络正常的话，可能是目录数据暂时取不到，稍后再试
```

- 所有出错共用这一个版式：红色粗体的「出错：是什么」，下面是键值行「原因」和「下一步」，出路不止一条时各占一行。**不出现堆栈。**
- 出问题的网址或路径单独占一行，接在「原因」下面、与值的左缘对齐，不截断也不折行。
- 括号里的技术原因只放错误码和 `HTTP 503` 这类不需要翻译的东西。
- 出错说明写到标准错误。不让安装器退出的出错（GitHub 限流、无法查询 skill 的文件列表）说明之后空一行回到主菜单。
- 让用户照着敲的示例里的 `<你的令牌>` 用默认前景色；黄色的占位符只用在将执行的命令里。

### 帮助

`--help` 的输出：第一行只有粗体的产品名和暗淡的版本号，顶格；之后「用法」「选项」「环境变量」各一个分区：「用法」只有一行，另两个分区里是两栏的表，第一栏按最长的一格定宽，第二栏过长时折行。

### 英文界面

版式不变，文字换成英文；宿主仍显示为 `AI Agent`，四个分组依次叫 `Skills`、`MCP`、`Tools`、`Apps`（中文是 `Skill`、`MCP`、「工具」、「应用项目」；`Apps` 和 `catalog.json` 的键名一致）。英文的词更长：列表里的说明截得更多，skill 汇总的备注基本都是另起一行。按键提示要自己算着写在 79 列以内（多选末尾是 `confirm (none = back)`）。文案都在 `cli/src/messages.ts`，中英各一份。

## 界面预览页

观感不靠自动化测试把关——测试断言文字内容，不断言版式；颜色只卡规格点名的两样：大标志的三档颜色、焦点符号是洋红且输出里没有青色（见 [入口与测试](./installer-entry.md) 的「Tests Required」）。把关的是界面预览页加视觉评审。

```bash
cd cli && npm run preview   # 输出：N 个画面 → …/cli/.preview/index.html
```

它经安装器入口按预设场景驱动安装器，把**真实的终端输出**连同样式渲染成一个离线的 HTML 页面：每个画面一格，标题下面左为深色终端、右为浅色终端。直接用浏览器打开 `cli/.preview/index.html` 看。它是生成物，不提交，也不随 npm 包发布；预览页从不碰真实的主目录和网络，不真的执行命令，不真的打开浏览器。

怎么用：

1. **改了任何画面就生成并看一遍**，拿每一格对照本文件：颜色与符号的用法、间距、横线、标题区。深色和浅色两边都要看。
2. **加了画面就加场景**：默认状态和“按了某个键之后”各一个；英文、不显示颜色、没有 Unicode 的变体拍默认状态。场景怎么写（样例目录、假的下载与命令、按键）见 [终端输出](./terminal-output.md) 的「界面预览页」。
3. 样例里要有一条长名字、一条长链接、一条长命令：折行和“备注另起一行”只有这时才看得到。画面再长也是整格都在：预览页读的是整个终端缓冲区，连同滚出屏幕的部分。
4. 带 key 的场景生成之后，在 `cli/.preview/index.html` 里搜假装粘贴的那个值，应当一处都没有。

## 实现时定下、维护者还没有看过的画法

下面这些是实现者为补全设计稿没画到的地方定的，照此落地了，但维护者没有逐条确认过。维护者提出异议时改这里，再改实现。

- 「一次运行只出现一次大标志、没有交互式终端时不打印」。
- 只检测到一个宿主时，主菜单上方每次启动都有的那一行「注意」（嫌吵的话可以改成只在汇总里说）。
- 在不可选的行上按确认或空格时的「这一项现在选不了」；是否题输入了别的时的「请输入 y 或 n」。
- 多选列表「不选则返回」的画法；在 skill 列表上不选就确认，回到的是宿主选择而不是主菜单。
- 不可选的 MCP 行尾写「需要别的 AI Agent」而不是「仅支持 Codex」（一个都不支持的宿主可能是这一版还不认识的）；工具把宿主的原因也写在状态栏的位置，系统的原因英文是 `not for macOS`。
- 多选列表没法指定光标的起始位置：光标可能一开始就停在不可选的行上。
- 可选 key 的分区标题和提示；回答之后擦掉提问、另写一行结局；四行说明在回答之后仍留在屏幕上。
- skill 汇总的操作与备注的写法、「注意」只在有覆盖项时出现、另问覆盖的那一句。
- MCP 状态未知时操作写「添加」、备注写「状态未知，先尝试移除同名配置」。
- 工具结论的说法（`已可用，在 PATH 中找到 uv`、`失败 命令已正常结束，但在 PATH 中找不到 uv；可能要重开终端才找得到`）。
- 应用项目：列表末尾的「返回」、浏览器打不开时的「注意」、链接整条写在一行上、回到列表时光标留在刚看的那一项。
- 出错说明里的 `<你的令牌>` 用默认前景色。
- 应用项目和 MCP 的英文文案；英文的分组名 `Skills`（工单 12 为了和 `Tools`、`Apps` 一致，从 `Skill` 改的）。
- 光标停在不可选的行上时 `▸` 加粗（工单 12 为了和别的行一致加的）。

发布前对照时发现、**没有统一**的一处，等维护者定：提问末尾带不带问号。中文的「开始安装吗」「执行这些命令吗」不带，「`<路径>` 不是本工具装的，要覆盖它吗？」带；英文的 `Install into which AI Agents` 不带，`Start installing?`、`Run these commands?`、`Overwrite it?` 带。这几句都原样记在选定视觉方向时的记录里，统一就要改其中一边的文案。

视觉评审提过、认为是口味问题而没有改的：结果词与原因之间只隔一格，「跳过」又和原因同色，容易连读；工具名很长时命令被挤得很窄（可以改成名字独占一行）；应用项目详情里已打开的那一行与键值行不同左缘；key 的四行说明可以在回答后收成一行。
