# 网页界面的设计

> 安装器的网页界面该长什么样：颜色与含义、字号与间距、各个画面的版式要点、深浅色、不可选与出错的画法、放不下时的退路、开场动画和开场引导。内容取自任务 `10-11-installer-web-ui` 的 `ui-direction.md`（维护者 2026-10-11 在对比页上选定的视觉方向），**任务归档后以本文件为准**。
> **本文件只管网页界面。** 终端界面的画法见 [界面设计](./ui-design.md)；两套界面共用的只有那份文档里「状态的写法」的词、「条目的标记」的词，和成功、失败、跳过这三个结果的符号（`✓` `✗` `–`）。
> 这些画面是任务 `10-11-installer-web-ui` 逐张工单做出来的，**现在都已实现**：三栏的浏览（左栏、条目的卡片、外部项目、右栏的已选）、开场动画、开场引导、几种结束画面、左栏最下面的切换语言、顶上那一条里能改的宿主与安装范围、含多个 skill 的第三方 Skill 卡片上挑 skill 的清单、填 key 的对话框、汇总、安装中、结果；工具也勾得上，轮到它时进度里那一行写明去终端看。各样是哪张工单做的见文末「各个画面是哪张工单做的」。改页面都对着网页界面的预览看（`npm run preview:web`）。数值起初取自选定的那张对比页，实现时以真实的画面为准——照实现改过的几处在各节里写明。
> 用词：正文说「宿主」；界面文案里它显示为「AI Agent」。「用途」只指 `GLOSSARY.md` 里的那个词；key 的那一句叫「说明」。

## 方向：利落

一切都退到最细的线和最准的字后面，只剩用户要看的东西。参照的是 Linear、Vercel 这一类当下的开发工具。

- 三栏：左边用途，中间条目，右边已选。条目是卡片。
- 黑白灰。**彩色只有说状态的那三种**（就绪、留意、失败）；按钮和选中用前景色。
- 深色与浅色各一套，跟随系统。

维护者明确不要的（四轮对比页里否掉的），实现和以后改版时都别走回去：

| 不要 | 说的是什么 |
|------|------------|
| 紫色系 | 紫、蓝紫的强调色，淡紫的背景，粉到紫到蓝的渐变按钮——「很像 AI 做的样式」 |
| 成排的圆角标签当导航 | 用途排成一两排自动换行的胶囊 |
| 复古 | 等宽字铺满、印刷品的纸色与衬线、机器面板与拨动开关 |
| 汇总里列出将执行的命令 | 见下面「汇总」 |

**要改画面，先改本文件，再改实现**，然后生成网页界面的预览对照（`npm run preview:web`，见文末「网页界面的预览」）。

## 颜色的含义

颜色都是具名的变量，深色、浅色各一份；样式里不直接写色值。

| 变量 | 浅色 | 深色 | 用在哪 |
|------|------|------|--------|
| 底色 | `#FFFFFF` | `#08090A` | 中间一栏的底 |
| 侧栏底色 | `#FAFAFA` | `#0D0E0F` | 左栏、右栏的底 |
| 卡片底色 | `#FFFFFF` | `#101112` | 卡片、盖在上面的面板、次要按钮 |
| 抬一档的底色 | `#F2F2F2` | `#1A1B1D` | 选中的卡片、分段控件里选中的那一格 |
| 当前的用途的底色 | `#E6E6E6` | `#26282C` | **只给左栏里当前的用途那一行**；别处不用 |
| 前景色 | `#111111` | `#F7F8F8` | 名字、标题、正文；**也是唯一的强调色**：主按钮的底、选中卡片的描边、已勾的勾选框、「推荐」标记的底 |
| 次要文字 | `#5C5F66` | `#A2A6AD` | 说明、未选中的用途名、分区的小标题 |
| 最淡的文字 | `#8A8F98` | `#6C7078` | 条目数、宿主的名字（状态前面的那个）、版本号、链接的网址、未装这类「退后」的状态词 |
| 线 | `#E8E8E8` | `#202225` | 分栏的线、卡片的边、列表项之间的线 |
| 就绪 | `#1F7A3A` | `#7BD88F` | 已装、已配置、已安装、已填、成功的 `✓` |
| 留意 | `#8A5A00` | `#E5C04B` | 版本不同、非本工具安装、覆盖、要填 key、现在装不了、「注意」 |
| 失败 | `#B3261E` | `#F2777A` | 失败、`✗` |
| 留意的底色 | `#FBF3D9` | `#231E0D` | 汇总里「覆盖它」那一条、收到新的一份汇总时顶上那一条、工具正在终端里装的那一行的底 |
| 开场的底色、开场的字 | `#000000`、`#F7F8F8` | 同左 | 只给开场那一层（开场动画和开场引导）：深色、浅色下它都是黑底白字。开场引导里的控件照深色那一套画——那一层把抬一档的底色、次要文字、最淡的文字、线、留意这五个变量换成深色那一列的值（另起了名字的五个变量 `--intro-raised`、`--intro-secondary`、`--intro-faint`、`--intro-line`、`--intro-attention`，值和深色那一列相同；**深色那一列改了，这五个跟着改**），底色和前景色换成这一行的两个，所以主按钮是白底黑字。卡片底色、侧栏底色没有换：那一层里现在用不到，要往里放次要按钮之类的先补上 |

变量在 `cli/web/style.css` 的开头（`--ground`、`--side`、`--card`、`--raised`、`--current`、`--ink`、`--secondary`、`--faint`、`--line`、`--ready`、`--attention`、`--failed`、`--attention-ground`、`--scrim`、`--intro-ground`、`--intro-ink`，和上表开场那一行说的另外五个 `--intro-*`）。`--scrim` 是盖着面板时底下压暗的那一层：黑，浅色下 32% 不透明，深色下 60%（工单 07 定的，对比页上没有给数）。

规则：

1. **彩色只有就绪、留意、失败这三种，只用来说状态**：状态的词、结果的符号、合计里失败的那个数字、必填的 key 没填时那一句后果、已选里装不了的原因、留意的底色的那三处（见上表）。名字、说明、路径一律前景色或次要文字色。卡片上不可选的原因是个例外，它用前景色粗体：那张卡片的名字退了一档，原因要比周围都亮才读得到。
2. **没有第四种彩色**。要强调就用前景色的实心，或者粗一档的字。
3. **「留意」和「失败」的词同时加粗**，和终端界面一样。
4. 选中、当前项、焦点都不单靠颜色：选中是描边加底色加勾，当前的用途是底色加粗一档，焦点是一圈 2px 的前景色描边（离元素 2px）。

对比度（按 WCAG 的算法算的，对着卡片底色；4.5:1 是正文字号下通行的可读门槛）：

| | 前景色 | 次要文字 | 最淡的文字 | 就绪 | 留意 | 失败 |
|---|---|---|---|---|---|---|
| 浅色 | 18.9 | 6.4 | **3.2** | 5.4 | 5.9 | 6.5 |
| 深色 | 17.8 | 7.7 | **3.8** | 10.9 | 10.8 | 6.9 |

当前的用途的底色是压在侧栏底色上的，量的是这两块底色之间的对比度：浅色 **1.20:1**，深色 **1.31:1**。**不许低于 1.15:1**——这是给「不放大也认得出是哪一行」定的一个量得出的数，不是哪份标准里的门槛。它原先用的是抬一档的底色，只有 1.07:1 和 1.12:1，维护者 2026-10-12 在真实的页面上看不出哪一行是当前的（任务 `10-11-installer-web-ui` 工单 15）。抬一档的底色别的用处没有跟着变：选中的卡片另有前景色的描边和实心的勾；分段控件里选中的那一格有外框、有旁边没选中的那一格比着、字也粗一档（左栏最下面切换语言的那一格同样是压在侧栏底色上的，对比度还是 1.07 和 1.12，认得出靠的是这几样，不靠底色）。

**已知的弱点**：最淡的文字两边都不到 4.5:1。它只许用在真正次要的东西上——条目数、宿主的名字、网址；**不可选的原因、提醒、出错说明不许用它**。「未装」「未配置」用它是沿用终端界面「暗淡表示退后」的做法，含义靠词不靠色。维护者没有就这一点表过态。当前的用途那一行的条目数也是最淡的文字，压在更深的那一档灰底上只有 **2.6:1（浅色）和 3.0:1（深色）**，比别处的条目数（压在侧栏底色上是 3.1 和 3.9）还低一截；同一个数在中间一栏顶上的标题旁边还写着一遍（「24 项」）。工单 15 没有动它——工单只定了底色；维护者 2026-10-12 认可行高和底色时听说了这一处，没有要求改，也没有单独就它表态。

### 大标志

网页界面里的 OXY 大标志是**单色**的，用前景色：深色下是白的，浅色下是黑的（维护者 2026-10-11 选定）。它是照终端里那五行方块画成的像素图形，不是文字。

它横向 25 格、纵向 10 格。**宽取 25 的整数倍**，每个方块才落在整像素上、方块之间看不到缝：左上角的是 50px，开场里的是 450px（窗口很窄时是窗口宽的 60%）。图形按像素对齐来画，不做边缘的柔化。对比页上是 58px 和 440px，放大了看得到方块之间的细缝，实现时改的。

站点图标是大标志里的那个 O：深色的圆角方块上一个白的 O，在浏览器的深色、浅色标签栏上都看得清。

终端里的大标志不变，仍是粉到紫到蓝的渐变（[界面设计](./ui-design.md) 的「大标志的颜色」）。两处不一样是有意的：网页界面里不要紫色。

## 字

- **字体**：系统自带的无衬线字（macOS 上是苹方与 SF，Windows 上是微软雅黑与 Segoe UI）。**不加载任何外面的字体**——网页界面不许向互联网发请求。路径、第三方 Skill 里各个 skill 的名字、key 的变量名、让用户照着敲的命令（`npx oxy-tools`）用系统的等宽字；夹在一句话里的命令用前景色，才认得出是要敲的东西。
- 字距略收（约 -0.003em）。

| 角色 | 字号 / 行高 | 字重 |
|------|-------------|------|
| 界面的基准（用途、控件、已选） | 13px / 1.55（用途的行是 18px，写成整像素，见「间距与圆角」） | 400；当前项 500 |
| 用途的标题（中间一栏顶上） | 16px | 600 |
| 分区的小标题（Skill、第三方 Skill、MCP、工具、外部项目） | 12px | 500；后面跟的那句话 400 |
| 条目的名字（卡片上的，和外部项目的） | 14px / 1.4 | 600 |
| 条目的说明 | 13px / 1.6 | 400 |
| 状态、标记 | 12px、11px | 400；留意与失败加粗；「推荐」500 |
| 外部项目的网址 | 11.5px / 1.5，等宽 | 400 |
| 左栏最下面的本机信息 | 12px | 400；「本机」两个字 500 |
| 面板的标题（汇总、填 key、结果） | 18px / 1.3 | 600 |
| 结果的合计数字 | 26px | 600 |

**说明从不截断**：没有省略号，没有固定高度，没有「展开」。放不下就折行、卡片跟着变高。名字、路径、网址允许在任意位置断开，免得撑出横向滚动条。**状态的词和标记不折行、不被挤窄**：「已装」「要填 key」这样的词要么整个在这一行，要么整个到下一行。

## 间距与圆角

| | 值 |
|---|---|
| 三栏的宽 | 左 228px，右 296px，中间吃掉剩下的；窗口不足 1100px 时左 196px、右 256px |
| 中间一栏的左右留白 | 24px（窄时 16px） |
| 卡片 | 内边距上 13、左右 14、下 11；卡片之间 8px；圆角 8px；边 1px |
| 控件（按钮、勾选宿主的小块、分段控件、用途的行） | 圆角 6px |
| 用途的行 | 内边距上下各 9px、左右 8px，行高 18px：用途名只占一行时正好 36px 高，折成两行时 54px。**不低于 36px**。行高写成整像素而不是 1.4（那是 18.2px）：十一行攒出三个多像素，1024×768、英文界面下左栏正好多出一像素（见「踩过的坑」） |
| 标记、勾选框 | 圆角 4px；勾选框 16px 见方 |
| 盖在上面的对话框 | 圆角 12px |
| 分区之间 | 小标题上方 22px、下方 8px |

没有阴影，没有渐变。层次靠线和底色的三档（底色、侧栏、抬一档）；当前的用途另有一档更深的，只给它用。

### 共用的部件

各个画面共用这几样，加新画面时接着用，不另画一套（样式在 `cli/web/style.css`）：

| 部件 | 画法 |
|------|------|
| 按钮 | 缺省是次要的：卡片底色、线的边、前景色的字、500、内边距 7px 14px。主按钮（`.primary`）是前景色实心、底色的字。**一个画面上只有一个主按钮**。不可点时整个 40% 的不透明度 |
| 勾选框 | 真正的 `<input type="checkbox">`，画成 16px 见方、1.5px 最淡的边、圆角 4px；勾上是前景色实心加一个勾。宿主的小块里的是 14px。不可选的是虚线的边 |
| 分段控件 | 两个真正的单选，各画成一格；选中的那一格是抬一档的底色、前景色的字、500 |
| 标记 | 11px、线的边、圆角 4px、次要文字色；「推荐」是前景色实心（`.solid`） |
| 状态的词 | 照含义上色：就绪（`.ready`）、留意（`.attention`，加粗）、失败（`.failed`，加粗）、退后（`.faint`）；不上色的就是前景色。一个宿主一段，段里不折行。**这四个类名只给词用**：别拿状态的名字当一行、一段的类名（`<li class="failed">` 会让整行变成失败色粗体——工单 07 的第一版结果行就是这样） |
| 盖在上面的面板（`.scrim` 里的 `.panel`） | 从右边出来，宽 720px、至少给底下留 280px，卡片底色、左边一条线；底下压暗（`--scrim`）。上中下三段：标题一段，中间自己滚动，底部的按钮不动、靠右。打开时焦点落到面板上，底下的三栏点不到也聚焦不到（`inert`）。没有滑出的动画 |
| 盖在上面的对话框（`.scrim.centered` 里的 `.panel.dialog`） | 填 key 用。和面板同样的上中下三段（同一个部件），画成居中的一块：宽 680px（窗口窄时两边各留 24px）、最高到离窗口上下各 40px、四边一条线、圆角 12px。标题右边是关掉它的 ×（和已选里去掉一项的那个同一个画法） |
| 写成一行字的按钮（`button.text`） | 没有边和底，带下划线：填 key 里的「换一个」 |
| 一区上方的提醒（`.list .notice`） | 12px；行首留意色粗体的「注意」，话用前景色。现在只有 MCP 那一区有 |
| 等宽字（`.mono`） | 条目的名字（面板里的）、位置；可以在任意位置断开 |
| 小字（`small`） | 12px、最淡的文字：已选里的类型、面板里名字后面的类型。说的是用户要知道的事时另给颜色（汇总里的备注是次要文字色） |
| 一栏、居中的版式（`.solo`） | 宽 520px，上方留视口高度的 18%：还没连上时的那一句，和几种结束画面 |

## 版式

### 三栏

| 栏 | 里面有什么 |
|----|------------|
| 左 | 大标志、产品名与版本号（不许折行；窗口窄时把间隔收到 8px）；「推荐」，一条线，然后是各个用途，每行右边是条目数；最下面是本机信息，再下面是切换语言 |
| 中 | 顶上一条贴着不动：用途的标题与条目数，后面是「装进哪些 AI Agent」和「装到哪里」——放得下就和标题同一行、靠右，放不下就**两样一起**折到下一行，不拆开（连两样并排都放不下时除外，见「放不下时的退路」）；下面是条目，按类型分区；最后是外部项目 |
| 右 | 「已选」和数量；每个已选的条目一行；最下面固定着「去汇总」 |

每一栏各自滚动，整页不滚。**已选的数量、名字和「去汇总」任何时候都在屏幕上。**（三栏那一行的高钉死成窗口的高：`grid-template-rows: minmax(0, 1fr)`。不写它，哪一栏的内容够高就可能把整行撑出窗口。）

- **用途是一竖列**，不排成横向的标签。没有条目的用途不出现。**每一行不低于 36px 高**（用途名只占一行时正好 36px；原先约 30px，维护者 2026-10-12 验收时嫌小），字号不变；行与行之间不另留空。**当前的用途是只给它用的那一档更深的灰底**（颜色表里的「当前的用途的底色」）、前景色的字、粗一档——**不用前景色的底加反白的字**（那是全页最重的一种画法，留给主按钮），**不加竖线**。用途名放不下就折成两行，这一行跟着高，条目数留在第一行的右边。每一行是一个按钮；鼠标移上去字变成前景色，底色不变——所以移上去的那一行和当前的那一行分得开；键盘焦点照旧是那一圈前景色的描边。左栏放不下时自己滚动，最下面的本机信息和切换语言不被裁掉。

### 条目的卡片

两张一排（窄时仍是两张）。从上到下：

1. 名字，右上角是勾选框。
2. 标记（有才有）：「推荐」是前景色实心；「要填 key」「可选的 key」是线框（要 key 的 MCP：有必填的变量是前一个，只有可选的是后一个；它说的是条目，填过了也不变——这一批填没填看右栏）。
3. 说明，完整的。
4. 最下面一行是状态，**一栏一段**（任务 `10-12-installer-add-pi-omp-hosts` 工单 06，维护者 2026-10-12 定的；原先是每个所选的宿主一段）：段名用最淡的文字，后面是状态的词（词照 [界面设计](./ui-design.md) 的「状态的写法」）。
   - **Skill 和第三方 Skill 一组宿主一段**：所选的宿主里共用同一个 skill 目录的合成一段，段名把它们的名字照界面上的先后并列起来，状态只写一份——「Claude Code 已装 2.16　Codex、Pi、omp 已装 2.16」。选了 Codex 和 Pi 是一段「Codex、Pi」，三个宿主是「Claude Code」「Codex、Pi」两段，四个都选是「Claude Code」「Codex、Pi、omp」两段；只选 Claude Code、选了 Claude Code 和 Codex 时和归组之前一样。第三方 Skill 条目用 `hosts` 限定了宿主时，一组里有它支持的宿主就照目录写状态，一个都不支持才写「不支持」。
   - **MCP 每个装得了 MCP 的宿主一段**，各看各的配置；**没有 omp 的那一段**（安装器不装它的 MCP，那一区上方的「注意」讲了原因和出路）。四个宿主都选了时是 Claude Code、Codex、Pi 三段；选了 Claude Code 和 omp 时只有 Claude Code 一段（带着名字）；只选 omp 时卡片是不可选的画法。
   - 只选了一个宿主时不写段名。工具只有一个状态。
   - 分成哪几段、段名怎么写都随画面状态来（[网页界面的契约](./web-ui-contract.md) 的「卡片的状态怎么分段」），**页面不自己归组**：`.status` 里照原样画段名、词、词后面的字。

| 状态 | 画法 |
|------|------|
| 未选 | 线的边，卡片底色，空的勾选框 |
| 选中 | **前景色的边**，抬一档的底色，实心的勾选框 |
| 不可选 | **虚线的边**，没有底色；名字和说明都用次要文字色（名字比可选的卡片退一档，说明不变）；勾选框是虚线、勾不上；状态的位置写**原因**，前景色、粗体（需要 AI Agent、需要别的 AI Agent、只能装到全局、不支持 macOS）。原因直接在卡片上，不靠鼠标悬停 |

**不可选的卡片不用最淡的文字**（维护者 2026-10-11 定的）。选定的对比页上不可选卡片的名字和说明是最淡的，那里只画了一张；一个宿主都没检测到时整栏都是这样的卡片，名字和说明只有 3.2:1，读不清。「装不了」靠三样一起说：虚线的边、虚线的勾选框、粗体的原因——不靠把字调淡。

  - 段名「Codex、Pi、omp」在两种窗口、两种语言下都完整，没有被截断、没有从中间折开的。
- **含多个 skill 的第三方 Skill** 勾上之后卡片占一整行，说明下面多一块：终端界面那一问的话（「paper-kit 里有 3 个 skill，选择要装的」，随画面状态来），然后是各个 skill 的清单，三栏（窄时两栏）。每个 skill 是一个小格：勾选框和名字（等宽、600）一行，下面是完整的说明，最下面是它自己的状态，和卡片底部同样的几段（一组宿主一段：未装、已装、不支持，词和卡片底部的一样，字再小半档；小格窄，两段时一段一行）；挑了的小格是前景色的边。起初一个都没挑。去掉条目之后清单收起，再勾上时挑过的还在。（工单 09 照实现定的：对比页上只画了「已装」一个词，这里每个 skill 都写状态——工单要求每个 skill 带说明和状态。）
- **MCP 那一区的小标题下面可以有提醒**，每条一行，行首是留意色粗体的「注意」，话用前景色（和左栏本机信息里的提醒同一个画法），照这个先后：选了项目而哪个宿主的 MCP 只能装到全局（「Codex 的 MCP 只能装到全局：没有把 MCP 写进项目的命令」）、所选的宿主里哪个的 MCP 安装器不装（工单 04：「安装器装不了 omp 的 MCP：请在 omp 里用 /mcp add 添加」——卡片上没有 omp 的那一段（工单 06；工单 04 时是一段最淡的「不支持」）；只选了 omp 时卡片都是不可选的画法、原因「需要别的 AI Agent」，这一句照样在，预览「浏览 · 四个宿主 · MCP 那一区」「浏览 · 四个宿主 · 装到项目 · MCP 那一区」「浏览 · 选了 Claude Code 和 omp · MCP 那一区」「浏览 · 只检测到 omp」）、哪个宿主的配置读不了（「读不到 Codex 的配置，无法判断哪些 MCP 已配置」）。话随画面状态来，和终端界面列表上方那几行是同一份；夹在句子里的 `/mcp add` 不是等宽字（和别处夹在句子里的命令一样，见「看过、留给维护者定的」）。
- **`Skill`（或「第三方 Skill」）那一区的小标题下面也可以有一条提醒**（任务 `10-12-installer-add-pi-omp-hosts` 工单 03），同一个画法：所选的宿主里有 Codex、Pi 或 omp 时的那一句「Codex、Pi、omp 共用同一个 skill 文件夹：装给一个，另外两个也看得到」。它只出现一次——这张列表里两区都有时在排在前面的 `Skill` 那一区，只有第三方 Skill 时在它那一区；只选 Claude Code 时没有。1280 和 1024 两种窗口下中文、英文都是一行，再窄就照普通的段落折行（预览「浏览 · 共用 skill 目录的说明 · Codex 和 Pi」「… · 用途下既有 Skill 又有第三方 Skill」「浏览 · 三个宿主 · 1024×768」「英文 · 浏览 · 三个宿主 · 1024×768」）。页面画各区提醒的那段代码原样能用，没有为它加部件。
- 分区的小标题后面可以跟一句说明（「第三方 Skill　内容直接来自作者」）。它和小标题同是次要文字色，只细一档——对比页上是最淡的，但它说的是用户该知道的事，不许用最淡的文字。
- 卡片第一次出现时的先后（开场之后依次浮上来）跨着分区数，不是每个分区各数各的。

### 外部项目

在所有组件的后面单独一区，小标题后面写「只给链接，不安装」。**不是卡片，没有勾选框**：两栏的列表，每项是名字（粗体，后面一个 ↗）、完整的说明、最淡的小字写出整条网址，项与项之间一条线。名字是链接，在新标签页打开，不带来源信息；鼠标移上去加下划线。带推荐标记的，名字后面跟一个「推荐」的标记（和卡片上的同一个画法）。

用途下只有外部项目时没有组件的分区，顶上那一条下面直接是这一区。

### 已选（右栏）

标题是「已选」和数量（数量用前景色、600）。**已选为空时**标题下面一条线，一句次要文字色的「还没有选任何条目」；「去汇总」不可点。

每行：名字（500），下面一行最淡的小字是类型，后面可以跟「3 个 skill 里挑了 2 个」（和类型之间一个「·」，这句话随画面状态来）「要填 key」（留意色）「key 已填」（就绪色）；行的右边是去掉它的 ×（一个 24px 见方、没有边的按钮，读屏软件念「去掉 <名字>」）。行与行之间一条线，**照勾选的先后**排：新勾的落在最后。

最下面固定着两个按钮，上下排：主按钮「去汇总 →」，和次要的「完成」（点了安装器退出）。「完成」在对比页的这一栏里没有——见文末「实现时定下、维护者还没有看过的画法」。

这一轮不会装的条目**留在这里**——改了宿主或安装范围之后装不了的，和含多个 skill 而一个都没挑的第三方 Skill：名字划掉、退到次要文字色（不用最淡的：原因要读得清），下面那行小字换成原因（留意色，随画面状态来：装不了的和卡片上是同一句，没挑的是「一个 skill 都没挑，这一条不装」），标题旁边写「其中 N 项这次不会装」（留意色小字；工单 09 从「现在装不了」改的，因为没挑的那一种不是装不了）。已选里一个会装的都没有时「去汇总」不可点，和已选为空一样。

### 填 key

盖在上面的对话框，底下压暗。**它是去汇总路上的一步**：点了「去汇总」，已选里有要 key 的 MCP 就先出来，没有就直接是汇总（先后见 [网页界面的契约](./web-ui-contract.md) 的「MCP 与填 key」）。

- 标题「填 key」，右边一个关掉它的 ×；下面一句：key 只留在这次运行的内存里，交给安装命令；不显示、不保存、不进网址。
- 底部只有一个主按钮「好了」：去汇总。必填的没填也点得了——那个 MCP 这次不装，汇总里会写明。× 和 Esc 是回去接着挑。
- 打开时焦点落在第一个输入框上（一个输入框都没有时落在对话框上）。

每个要 key 的 MCP 一段（名字是等宽粗体，后面最淡的小字是它所在的那个用途的名字），段与段之间一条线。每个变量：

- 变量名（等宽粗体）和「必填」或「可选」的线框标记。
- 一句说明；**下面另起一行**是「去申请」和网址（链接，等宽、前景色、下划线只在网址下面，在新标签页打开，不带来源信息；后面的 ↗ 跟着网址的末尾，不单独掉到下一行——网址末尾的六个字和箭头不拆开）。对比页上「去申请」接在说明后面，说明稍长时它留在上一行行尾、网址掉到下一行，同一个对话框里有的接着有的另起；另起一行之后每个变量的链接都从行首起（工单 10 的视觉审查之后改的）。
- 输入框：**不显示输入的内容**——打进去的字画成圆点（前景色的边、圆角 6px），里面的提示是「粘贴 key，输入不显示」。必填的没填时下面一行留意色粗体的字「不填就不装 <MCP>，其余照常装」；可选的是最淡的「留空则不设置这个变量」（这一行的类名是 `.consequence`，必填的再加 `.required`，不借状态的词的类名）。
- 填过的不再是输入框，是一行「✓ 已填」（就绪色）和右边的「换一个」（线的边、圆角 6px 的一条）。**不显示值，也不显示长度。**
- **填了就发**：输入框的内容变了（失去焦点，或按回车）就交给安装器，输入框当场清空；这一行换成「已填」是等安装器推来的画面状态。按回车发出去的，输入框没有了之后**焦点接到「换一个」上**（不然焦点掉到页面上，Esc 和 Tab 都接不上）；焦点已经去了别处的不动它。点「换一个」给回输入框、焦点落进去；什么都没填就走开，原来填的还在，仍是「已填」。
- 输入框不让浏览器记住或自动填，写法和防不住的那一点见 [网页界面的契约](./web-ui-contract.md) 的 Design Decision 表。

### 汇总

贴着右边的面板（没有滑出的动画），宽约 720px（至少给底下留 280px），底下压暗。

- 标题「将安装 N 项」，下面一句：开始之前安装器会再查一遍这台机器上的状态，状态变了就给看新的汇总。
- **MCP 一个条目一段**，段名后面只有类型；段里每个装得了它的所选宿主一行，**没有位置**：宿主、操作（新装；已配置的是留意色粗体的「覆盖」；状态未知的是「添加」），位置那一栏只有备注（已配置，先移除再添加；状态未知，先尝试移除同名配置），没有备注就空着。MCP 没有「覆盖它」：再装一次就是覆盖。必填的 key 没填的 MCP 不在段里，在下面的「注意」里。
- 每个要装的条目一段（名字是等宽粗体，后面最淡的小字是类型和要装的版本，中间一个「·」），段与段之间一条线，最后一段下面没有线。**段数要和标题里的 N 对得上**：第三方 Skill 一个条目一段，段名是条目的名字，后面只有类型、没有版本（装的是作者当时的最新版）；里面每个要装的 skill 一小组（skill 的名字，等宽、600，下面是它在各个 skill 目录下的行——共用一个目录的几个宿主合成一行；只有一组、名字又和条目相同时不重复写）。段里每一项一行（本仓库的 skill 和第三方 Skill 是每个 skill 目录一行，MCP 是每个宿主一行）：宿主、操作（新装；覆盖是留意色粗体）、位置（等宽），位置下面一行小字是备注（`1.0.0 → 1.0.1`、重装、非本工具安装、已有同名目录、已配置先移除再添加）。
- **工具一个条目一段**（工单 12），排在 MCP 之后，段名后面只有类型；段里只有一行「执行安装命令」，前景色，从这一段的左缘起、占满三栏——没有宿主、位置和备注，**也不列那一行命令**。
- **要逐项决定的覆盖就在那一行下面**：一条留意底色的横条，一个勾选框和「覆盖它」；没勾时后面写「没勾：这一项跳过，保持原样」（前景色，不用最淡的）。缺省不勾；**每次进汇总都从不勾起**。
- 一行三栏：宿主（次要文字色，96px）、操作（72px，英文的 overwrite 也放得下）、位置，三栏的字照基线对齐（位置是等宽字，不照基线会比旁边高出两像素）。两栏的宽是定死的，各段的位置才上下对得齐。备注用次要文字色——它说的是这一项会怎样，不用最淡的文字。
- **收到新的一份汇总时**（确认的时候对不上，没有装）：各段的上面多一条留意底色的话，行首是留意色粗体的「注意」。
- 按 Esc 等于「返回修改」。
- 最后是一个小标题「注意」，下面每条提醒一行；行首不再重复「注意」两个字。提醒的话和终端界面是同一份，只少「key 以占位符显示」那一条（见下）。
- 面板底部固定着两个按钮：「返回修改」（次要）和「开始安装」（主按钮）。

**汇总里不列将执行的命令**（维护者 2026-10-11 定的：「这个用户根本不关心，所以不需要展示给他看」）。随之没有的还有「key 以占位符显示」那一条提醒——它说的是命令里的占位符。终端界面照旧列出每一条命令，那边没有变。

### 安装中与结果

同一个面板的位置。

- **安装中**：标题「正在安装」和「7 / 17」（装完了几项、一共几项，次要文字色、靠右）；一条 6px 高的进度条（前景色）；下面每一项一行（skill 和第三方 Skill 是每个 skill 目录一行，共用一个目录的几个宿主合成一行；MCP 是每个宿主一行）：符号、名字（等宽）、宿主、结果的词加原因，行与行之间一条线。底部一句提醒和不可点的「完成」。提醒是两句（工单 11 起）：「装完之前请不要关掉终端。关掉这一页，这一批也会装完，结果打在终端里。」（英文 `Keep your terminal open until this finishes. If you close this page, this batch still finishes and its results are printed in your terminal.`）——后半句说的是页面的生命周期，见 [网页界面的契约](./web-ui-contract.md) 的「生命周期」。放不下一行时折行，按钮不被挤走。
- 正在向 GitHub 查询时，各行的最上面多一行：小圆环和「正在查询 skill 的文件列表…」。
- **结果**：标题「结果」；三格合计（成功、失败、跳过，各是一个线框的格子，数字 26px；**有失败的时候**失败的数字是失败色）；同样的行；有没装上的才有「下一步」一段；底部「继续挑选」（次要）和「完成」（主按钮）。
- 原因放不下就折行（英文的原因常是两行），名字、宿主留在第一行。

| 行的状态 | 符号 | 词 |
|----------|------|-----|
| 装好了 | 就绪色的 `✓` | 就绪色的「已安装」（skill、第三方 Skill）「已配置」（MCP），后面前景色的版本（MCP 没有） |
| 没装上 | 失败色的 `✗` | 失败色粗体的「失败」，后面前景色的原因 |
| 跳过 | 最淡的 `–` | 前景色的「跳过」加原因（未同意覆盖，保持原样；未填写必填的 <变量>） |
| 正在装 | 转动的小圆环（前景色），贴着这一行的第一行，和别的符号一样；系统开了「减少动态效果」时不转 | 终端界面进行中那一行的词加「…」：本仓库的 skill 是「正在下载…」，第三方 Skill 是「正在安装…」，MCP 是「正在配置…」 |
| 正在终端里装（工具） | 同上，转动的小圆环 | 一整句「这一项正在终端里安装，请看终端」（英文 `this item is installing in your terminal; watch it there`），前景色、600，**不带「…」**；整行是**留意底色的一条**（圆角 6px，左右各伸出 10px，字不往里缩、和上下的行对齐；这一行下面没有线，并往上多盖一像素，把上一行的底线盖住——那条线只有内容那么宽，露在上缘会像半截描边） |
| 等待 | 最淡的 `·` | 最淡的「等待」；名字不加粗 |

- **宿主那一格可以是几个名字**（任务 `10-12-installer-add-pi-omp-hosts` 工单 03）：共用一个 skill 目录的 Codex 和 Pi 合成一行，那一格写「Codex、Pi」（英文 `Codex, Pi`），字是安装器连好随画面状态来的，页面不拆它。它和单个宿主的名字同一个画法（次要文字色），**完整显示，不截断、不加省略号**：汇总里那一栏是定死的 96px，「Codex、Pi」和「Claude Code」都放得下（预览「汇总 · Codex 和 Pi 合成一行」「汇总 · 三个宿主」「汇总 · 有第三方 Skill · 三个宿主」的 1280 与 1024）；进度和结果里那一栏随面板伸缩，同样放得下（预览「安装中 · Codex 和 Pi 合成一行」「结果 · Codex 和 Pi 合成一行」「结果 · 三个宿主」）。汇总的那 96px 是照工单 03 时最长的一格定的：放不下时格子里的字会折行而不是被裁掉。**工单 04 加上 omp 之后量过：中文的「Codex、Pi、omp」在页面的字体下是 102.6px，比这一栏宽 6.6px，折成「Codex、Pi、」和「omp」两行**（1280 与 1024 都是；预览「汇总 · 四个宿主」「汇总 · 有第三方 Skill · 四个宿主」）；英文的 `Codex, Pi, omp` 是 91.3px，一行放得下（预览「英文 · 汇总 · 四个宿主」）。三个名字都完整显示、没有被截断，规格要的是这一条；**栏宽没有改**（它是定死的、别的段靠它对齐，改它算动版式），要不要加宽到放得下这一格留给维护者定，见文末。进度和结果里那一栏随面板伸缩，「Codex、Pi、omp」一行放得下（预览「结果 · 四个宿主」）。合计的三格按行数算。
- **工具的行没有宿主**（工单 12）：宿主那一格空着，不合并——各行的词才上下对得齐。装好了是就绪色的「已可用」，后面前景色的是查到了什么（「在 PATH 中找到 pandoc」）；没装上是「失败」加原因，原因常要折成两行。
- **轮到工具的那一行要和别的「正在装」分得开**：这时用户要看的不是这一页，是终端（命令可能在那边等他输密码）。所以用了留意底色——和汇总里「覆盖它」那一条是同一种底色、同一个含义：这里有要你留意的事。一批里同一时刻至多一行是这样的。小圆环留着：它确实还在装。
- 有没装上的工具时「下一步」里是另一句（「没装上的工具：原因看终端里那条命令自己的输出。排除后点「继续挑选」，重新勾选再装一次。」），随画面状态来。

成功、失败、跳过的符号和词照 [界面设计](./ui-design.md) 的「符号的含义」，两套界面一个说法。等待的 `·` 和正在装的小圆环是网页界面自己的：终端界面里没有「等待」这一种行，`·` 在那边是分隔符。

### 出错

出错说明和终端界面是同一份话、同一个结构（[界面设计](./ui-design.md) 的「出错」）：一个标题，下面「原因」「下一步」各一行。在网页界面里它是面板里的一块，不另开对话框：

- 标题是失败色粗体，以「出错：」开头；「原因」「下一步」两个词用最淡的文字，后面的话用前景色。**出错说明不许用最淡的文字写。**
- 出在一批里的某一步（比如向 GitHub 查询失败）：放在结果的合计和各行之间，是一个线框的块；受它影响的条目不出现在行里，其余照常。出问题的网址或路径写在原因下面，等宽。只装本仓库的 skill 而查询失败时，合计是三个 0、一行都没有。
- 出在整个网页界面上（安装器已退出、连接断了、口令不对）：整个画面换成一句说明，上面没有还能点的操作。**它们是结束画面，不照上面出错那一块的画法**（不以「出错：」开头，没有「原因」「下一步」两行）：画法见文末的「结束画面」。

这一节是照终端界面的出错画法推的，对比页上没有画，维护者没有看过。工单 07 做出了一批里出错的那一种（预览里的「结果 · 向 GitHub 查询失败」）。

## 开场动画

网页界面第一次打开时先播一段，约两秒，然后是开场引导，答完才是挑选的画面（动画是维护者 2026-10-11 要的，演法是他在对比页上选的那一种；后面接开场引导是他 2026-10-12 验收时要的）。动画和开场引导是盖在页面上面的**同一层**（`cli/web/intro.tsx`），下面叫它「开场那一层」。

| 时刻 | 画面 |
|------|------|
| 0.15 – 0.95 秒 | 黑底，正中偏左一行等宽字 `$ npx oxy-tools`，像有人在敲，一个字一个字出来，行尾一个闪的光标 |
| 1.05 秒起 | 大标志一行行打出来，五行，每行隔 0.11 秒，行里从左到右略有先后 |
| 1.75 秒 | 标志下面淡淡的一行 `oxy-tools 0.4.0` |
| 2.2 秒起 | **不淡出**。命令、大标志、版本号留在原处，下面依次出现开场引导的三样：第一行提问（2.2 秒）、第二行提问（2.35 秒）、按钮那一行（2.5 秒，目录那一行和它一起），每样 0.2 秒由透明到实 |
| 2.7 秒 | 都到位，光标收掉，开场引导可以操作（焦点进到里面）。之后停着等用户答，没有倒计时 |

一个宿主都没检测到时没有开场引导（没有可选的），照原先的样子收场：

| 时刻 | 画面 |
|------|------|
| 2.2 – 2.6 秒 | 整个开场淡出 |
| 2.3 秒起 | 底下的画面已经在了：卡片一张张浮上来（从下面 12px 处、由透明到实，0.4 秒），每张隔 50 毫秒，最多错开九张 |

规矩：

- **不拖慢网页界面本身**：开场是盖在上面的一层，底下照常连上安装器、拿画面状态。开场播完时底下还没准备好，就接着等，不让用户对着空白。
- **动画只在这次运行第一次打开时播**。刷新、断开重连、再开一个标签页都不重播（播过没有记在安装器那边，见 [网页界面的契约](./web-ui-contract.md)）。
- **可以跳过，跳过的只是动画**：点一下或按任意键，画面直接到开场引导静止的样子；没有开场引导时立刻进去——盖着的那一层当场收掉，卡片不再做浮上来的动作，所有东西直接到位。跳过的那一下点击不会落到底下的页面上，也**不落到开场引导的控件上**，三道一起守着（少了哪一道都在真实的浏览器里重现过，见「踩过的坑」）：动画那一段里引导的控件点不到、拿不到焦点（`inert`）；跳过用的是回车或空格时那一下不再往下传（`preventDefault`，别的键照常），**按着不放时系统自动重复的回车、空格在引导开着的整段时间里都不算数**；跳过用的是点的那一下时，抬手补发的那一次 `click` 被吞掉（触屏上它是抬手之后才定落在哪的）。没有开场引导时这几道都不设，和原先一样。
- 开场播着的时候换了一张列表，新出现的卡片不做浮上来的动作。
- **动画那一段是纯装饰**，不读给读屏软件（命令、大标志、版本号那一块带 `aria-hidden`）；没有开场引导时读屏软件直接读底下的页面。开场引导是要用户答的，照下面「开场引导」读。
- **走到下一段靠动画自己播完的那一下（`animationend`），不另设定时器**：没有开场引导时是那一层自己淡出完；有开场引导时是引导里最后一样（按钮那一行）出现完，这时才可以操作；答完之后又是那一层自己淡出完。时刻全在样式里（`style.css` 的「开场」）。这样把动画定格、放慢来看的时候，收场也跟着停，不会画面还定着格、那一层却到点没了。
- 还没连上安装器时的那一句「正在连接安装器…」等 0.4 秒还没连上才显出来（通常一闪而过，不让它闪）；系统开了「减少动态效果」时直接显示。
- **系统开了「减少动态效果」时不播动画**，卡片也不做浮上来的动作，所有东西直接到位；**开场引导照样出现**（它是要用户答的，不是装饰），直接是静止的样子，答完那一层当场收掉、不淡出。
- 开场里的大标志是单色的（白），和左上角的那个一样。
- 除了开场、卡片第一次浮上来、进行中的小圆环，网页界面里**没有别的装饰性动画**。「正在连接安装器…」晚 0.4 秒显出来（上面「规矩」的最后一条）不算装饰：它是为了不让那一句闪一下。

「只播一次」「可以跳过」「减少动态效果时不播」这三条是定方向时替维护者假定的，说给他听过，他没有反对，也没有逐条确认。

### 开场引导

开场动画之后、进入挑选的页面之前，在同一层上问「装进哪些 AI Agent」「装到哪里」（工单 16；什么时候出现、答过没有怎么记，见 [网页界面的契约](./web-ui-contract.md) 的「开场引导答过没有」）。照维护者那句话（「这个动画效果再继续延伸出一个让用户选择…」）和选定的方向推的画法，没有经对比页选过；做出来之后维护者 2026-10-12 看过预览里的那几格，答的是「没问题」。

**版式**

- 和动画是同一个黑底白字的画面，深色、浅色下都是；那一层不透明，底下的三栏一点都看不到。
- 命令、大标志、版本号留在原处，引导接在它们下面 28px 处，和大标志一样宽（450px，窗口很窄时是窗口宽的 60%）、左边对齐。**这几样合在一起竖着居中**，而且从动画一开始就是这样排的——所以有开场引导时命令和大标志比窗口正中高一些，引导出现时它们不挪。
- 从上到下三样：
  1. **两行提问**，像终端里的提问：行首一个最淡的等宽的 `?`（纯装饰，不读给读屏软件），然后是提问的话（次要文字色），后面是控件。两行的控件不对齐成一列：各跟在自己那句话后面，和终端里的提问一样。一行「装进哪些 AI Agent」和各个宿主的勾选，一行「装到哪里」和「全局｜项目」，两行之间 12px。**宿主的几个勾选是一整组**：在提问旁边排不下时（四个宿主）整组到提问的下一行，和提问的字从同一处起，见下面「控件」。
  2. **目录那一行**：选了「项目」时写明是哪个目录（那句话次要文字色，目录等宽字、长了在任意处断开、从不截断）。它说的是上面那一行「装到哪里」，所以**贴着它**（上面只留 4px）、缩进 16px 和提问的字从同一处起，离下面的按钮远一些（18px）。**这一行一直占着一行的位置**（20px），没选项目时是空的：点「项目」的时候上面的控件不跟着挪。**只在目录一行放得下时成立**：路径长到折成两三行时这一行比 20px 高，上面的几样跟着往上挪（工单 17 在真实的浏览器里看到的，见「看过、留给维护者定的」）。
  3. **按钮那一行**：主按钮「开始挑选 →」（白底黑字），旁边一句次要文字色的话「进去之后在页面顶上还能改」。
- 字号和页面一样是 13px；只有命令、版本号和行首的 `?` 是等宽字。

**控件**

- **三个宿主时三个勾选和提问在同一行里**，中文、英文都排得下（预览「开场引导 · 三个宿主」和英文的一格；英文的那一行正好排到大标志的右缘）。
- **宿主的几个勾选是一整组，排不下时整组到提问的下一行**（任务 `10-12-installer-add-pi-omp-hosts` 工单 07；维护者 2026-10-12 定的，见该任务规格「四个宿主时的版式」第 3 条）：几个勾选包在一个不拆开的组里（`browse.tsx` 的 `Target` 里的 `.options`），提问旁边放得下这一组就和提问同一行，放不下就**整组**到下一行，不让最后一个单独掉下去。引导只有大标志那么宽（450px）：**两个、三个宿主时和提问同一行**（中文、英文都是，和改动前逐像素相同）；**四个宿主时四个勾选在提问的下一行**，一行排完（中文、英文都是；预览「开场引导 · 四个宿主」和英文的一格，1280 与 1024 都是）。到了下一行的那一组**缩进 16px、和提问的字从同一处起**（行首的 `?` 挂在外面；和目录那一行同一个缩进），两行之间 8px。这一组自己比引导还宽时才在组里折行——眼下四个宿主的英文是三百多像素，没有到这一步。改之前是前三个勾选跟在提问后面、omp 一个落到第二行的左缘（`screenshots/04-web-onboarding-four-hosts-omp-wraps-1280-*.png`），工单 04 记下「工单要的四个宿主排得下、不换行挤压没有做到」的那一处**已经了结**。预览的机械检查里加了两条：哪一格里同一组的勾选不在同一行就不生成；开场引导里两个、三个宿主的勾选没有和提问在同一行，或四个宿主的没有整组在提问的下一行，也不生成。
- 和中间一栏顶上那一条里的是**同一个部件**（`browse.tsx` 的 `Target`，两处各给一个名字来分开控件的 `id` 和单选的组名）：宿主是带勾选框的小块，安装范围是两格的分段控件；想把最后一个宿主也去掉时同样出那一句「至少留一个」。颜色照这一层的黑底白字来（见「颜色的含义」表里开场那一行）。
- 提问的话、各个选项的名字、目录那一句都随画面状态来（`target`）；页面自己的只有按钮上的字、旁边那一句和对话框的名字（`TEXT` 的 `startPicking`、`guideHint`、`guideName`），中英各一份。
- **只检测到一个宿主时**那一行写成一句「装进 Claude Code」（没检测到的合成一句写在旁边，最淡的文字：「Codex、Pi、omp 未检测到」，英文 `Codex, Pi, omp not detected`——画面状态里合好的那一项，页面不自己拼；中文、英文、检测到的是哪一个都和「装进 …」在同一行里），没有勾选；它不是提问，行首没有 `?`，位置留着，两行的字因此仍从同一处起（试过在那里放一个最淡的 `✓`：只有六像素见方，像个噪点，还容易被看成勾选，去掉了）。只有安装范围可选。
- **开场引导里没有切换语言**：语言先跟系统语言或 `--lang`，进去之后在左栏最下面换。
- 用户不点就一直停着：没有倒计时，不会自己进去。

**答完之后**

- 点「开始挑选」（或焦点在它上面时按回车）只是告诉安装器答完了；那一层等推来的画面状态里成了答过才淡出（0.4 秒），0.1 秒起底下的卡片依次浮上来——就是原先开场淡出时的那一套，只是从这一刻起算。
- 进去之后顶上那一条里的宿主和安装范围就是刚选的，位置和原来一样、照旧能改。

**读屏与焦点**

- 引导那一块是一个有名字的对话框（`role="dialog"`、`aria-modal`，名字是「开始之前」/ Before you start）。可以操作的那一刻**焦点落在「开始挑选」上**：什么都不改的人按回车就进去。按 Tab 在它的几个控件之间走。
- 它开着时底下的三栏不可操作、也不读给读屏软件（和盖着面板时一样是 `inert`）：Tab 走不到底下的页面上。
- 焦点那一圈照旧是 2px 的前景色描边，在这一层里是白的。

**放不下时**

- 英文界面那两句提问更长（Install into which AI Agents）：一行里放不下时提问和它的控件上下排（那一行自己折行），不横着溢出。宿主的勾选上下排时是**整组**下去（见「控件」），到了下一行的控件缩进 16px、和提问的字从同一处起。
- 1280×800、1024×768 下命令、大标志、版本号、两行提问、目录那一行、按钮都在一屏里，没有滚动条。窗口矮得连这些都放不下时，那一层自己上下滚动，不把哪一样裁掉、不让按钮够不着。

## 深色与浅色

跟随系统的设置，不另设开关，也不记住选择（安装器不为这些写任何文件）。两套颜色见上表；版式、字号、间距两边完全一样。

原生的控件也跟着走（`:root` 上的 `color-scheme: light dark`）。各栏自己的滚动条另定了颜色（`scrollbar-color`）：轨道不铺底色，滑块用最淡的文字色——只跟着 `color-scheme` 的话，深色下 Chrome 的轨道是一条比底色亮的灰带。macOS 用触控板时滚动条平时不显示，看不到这些；接了鼠标、或在 Windows、Linux 上看得到。

## 放不下时的退路

目标视口是桌面 1280×800；1024×768 不能坏（没有横向滚动条，「去汇总」看得见）。不为手机和平板设计。

| 情形 | 怎么办 |
|------|--------|
| 窗口不足 1100px | 左栏 196px、右栏 256px；卡片仍是两张一排；第三方 Skill 里的清单由三栏变两栏 |
| 用途名太长（英文界面常见） | 折成两行，条目数留在第一行右边 |
| 宿主和安装范围在顶上那一条放不下 | 折到标题的下一行，仍在贴着不动的那一条里。连两样并排一行都放不下时（1024 宽、两个宿主、英文界面：Install into which AI Agents 很长；四个宿主时 1280 宽的英文界面和 1024 宽的中文界面也到了这一步；只检测到一个宿主、1024 宽的英文界面也是——`Installs into Claude Code　Codex, Pi, omp not detected` 连安装范围要 561px）才拆开，宿主一行、安装范围一行——选定的对比页上也是这样。**宿主的几个勾选是一整组**（`.options`，工单 07）：宿主那一行里名字旁边放不下这一组时整组到下一行，不让最后一个单独掉下去；1280 和 1024 两种窗口下四个勾选自己一行都放得下 |
| 几段状态在卡片底部放不下 | 放不下的那一段整个到下一行，词不折开、段名不截断（见「卡片」的「状态一栏一段」；维护者 2026-10-12 定的，画面不动）。Skill 和第三方 Skill 最多两段：放不下就是一段一行（1024 宽下四个宿主时每张都是；1280 宽下中文只有两段都宽的、英文是两段都带版本的）。MCP 最多三段：1024 宽下前两段一行、第三段一行；1280 宽下英文里有两段是长词时第三段到下一行 |
| 名字、路径、网址很长 | 在任意位置断开；从不截断 |
| 左栏的内容比窗口高 | 左栏自己滚动，最下面的本机信息和切换语言滚得到，不裁掉哪一样。滚动条一出来这一栏窄十来像素，用途名会折得更多，可能有折成三行的行（72px），条目数仍在第一行右边。2026-10-12 拿仓库里那时的目录（十个用途）量的余量——用途列表和本机信息之间还空着多少：1280×800 中文 178px、英文 88px；1024×768 中文 110px、**英文只有 2px**（工单 15 之前是 65px 上下，加高用掉了）。所以 1024×768、英文界面下窗口矮一点、本机信息里多一行「注意」、或用途再多一个，左栏就要滚。目录是运行时现拉的，用途一变这几个数就变 |
| 已选很多 | 右栏里的列表自己滚动；数量和「去汇总」不动 |
| 条目很多 | 中间一栏往下滚；不分页，不折叠 |

## 键盘与焦点

全部操作可以只用键盘完成。焦点是一圈 2px 的前景色描边，离元素 2px，深浅色下都看得见。勾选框、分段控件、按钮都是真正的表单控件，不是只会响应点击的色块。

## 网页界面的预览

观感不靠自动化测试把关：页面本身不写自动化测试，经入口的测试断不到版式（见 [网页界面的契约](./web-ui-contract.md) 的「Tests Required」）。把关的是网页界面的预览加视觉评审，和终端界面的做法一样（[界面设计](./ui-design.md) 的「界面预览页」）。

```bash
cd cli && npm run preview:web   # 输出：N 格 → …/cli/.preview/web/index.html
```

`cli/scripts/preview-web.ts` 经安装器入口按预设场景把安装器驱动到要看的状态，让**本机装着的 Chrome** 打开它的网页界面，把**真实的页面**拍下来：每个场景一格，标题前面是序号、后面是窗口的大小，下面左为深色、右为浅色（图下写着是哪一份、哪个文件），点开是原图；每格下面折着这一格页面上的文字。直接用浏览器打开 `cli/.preview/web/index.html` 看。它是生成物（一个 `index.html` 加每格两张 `NN-dark.png`、`NN-light.png`），不提交，也不随 npm 包发布，不进 CI。

预览**从不碰真实的主目录和网络，不真的执行命令**：目录是样例，主目录、项目目录、可执行路径都是临时目录，外部命令执行器一律不真的执行（缺省拒绝，场景可以假装它的结局，见下面的 `commands`），链接打开器只记下网址；Chrome 用的是一份临时的用户数据目录，除了本机回环地址哪里都连不上（见下面「用什么驱动浏览器」）。它和终端界面的预览（`npm run preview`）是两条命令，各生成各的，互不影响。

怎么用：

1. **改了页面就生成并看一遍**（样式、版式、页面自己的文字、画面状态里多了一块），对照本文件；**加了一种状态就加场景**。
2. 每格拍 1280×800，深色、浅色各一份。要看 1024×768 下坏没坏，给同一个场景再写一条、带上 `viewport: NARROW`；要看一张比窗口高的列表从头到尾，带上 `whole: true`（窗口拉到列表那么高）。
3. **样例里要有一条长名字、一条长说明、一条长链接**，并且就在条目最多的那张列表里：折行、卡片变高只有这时才看得到。现在是「文档处理」，二十多条，四种组件加外部项目都有；长说明要落在一张**卡片**上（现在是 docling，四五行，它旁边还有一张），只落在外部项目上的话卡片变高、同一排一样高就没被考到。
4. 中文、英文各拍：英文的词长，放不下的地方先在英文里出事（1024 宽、两个宿主、英文是最挤的一格）。
5. **带 key 的场景，假装填的那个值在生成物里一处都不许有**——这条规矩和终端界面的预览是同一条，这里由**脚本自己查**（工单 10）：每一格拍完，把页面的整份 HTML、每个输入框里现在的值、这一路从安装器收到的全部东西（每一份画面状态的原文、每个答复）拿去搜 `FAKE_KEY`，最后再搜一遍生成的 `index.html`；搜到就报错停下，**已经拍下的图连同整个生成目录一并删掉**。`index.html` 里每格存的只是页面上看得见的文字，所以不能只靠人去那里搜。大多数场景的 key 是脚本扮演浏览器直接发给安装器的，没有经过真实页面的输入框；**有一格是真的在页面里打进去的**（场景带 `typing`：「填 key · 正在输入」）——拍的是输入框里只有圆点，拍完让它失去焦点、等这一行换成「已填」再查，「发出去就从输入框里清掉」靠这一格守着。图上仍要看一眼：填过的那一行只有「已填」，正在输入的只有圆点。
6. **每一格在两种窗口下都不许有放不下的地方**，同样由脚本自己查（工单 14）：每格拍完，在拍的那种窗口和另一种（1280×800、1024×768）下各看一遍——整页比窗口宽、不让内容溢出的一块（自己滚动的、裁掉的都算）里内容比它宽（会冒出横向滚动条，或横着被裁掉）、竖着把内容裁掉的一块（说明被截断）、顶上那一条里的目录那一行在整条放得下它的时候折了行（任务 `10-12-installer-add-pi-omp-hosts` 工单 02 加的：拿一份不折行的拷贝量它要多宽，和整条的宽比），同一组的宿主勾选没有排在同一行里（工单 07 加的：`.options` 里各个勾选的上缘不在同一处——在提问旁边排不下时该整组到下一行，不许有哪一个单独掉下去）、开场引导里两个或三个宿主的勾选没有和提问在同一行、四个宿主的没有整组排到提问的下一行（工单 07：引导只有 450px 宽，这两样是照宿主的个数卡的，宿主的个数或名字变了要跟着改）、没检测到的宿主合成的那一句里「未检测到」排在了一行的开头（工单 07：它和最后一个名字拆开了），有哪一样就报出是哪一块并停下。开场里的那条命令除外：它是靠裁掉来一个字一个字敲出来的。开场那一层比窗口高（它放不下时自己滚动，可在这两种窗口里不该滚）也算一样（工单 16）。所以 1024×768 不用每个场景都另写一条才查得到；另写一条（带 `viewport: NARROW`）是为了**看**它在窄窗口里的样子。
7. 生成物不提交。要留给评审看的那几格，拷到任务目录的 `screenshots/` 里。

### 场景怎么写

场景表在 `cli/scripts/preview-web.ts`，一条是一格：

| 字段 | 说的是什么 |
|------|------------|
| `title`、`note` | 这一格的标题，和它要看什么 |
| `lang` | 页面的语言，缺省中文；`'en'` 是英文（安装器带着 `--lang` 起，浏览器的语言也跟着换——口令不对的画面没有画面状态，照浏览器的语言说） |
| `catalog` | 目录，缺省是那份最坏的样例（`worst`） |
| `onPath`、`home`、`links`、`project` | 这台机器事先的样子：可执行路径上有哪些命令（有 `claude`、`codex`、`pi`、`omp` 就是「检测到了」）、主目录和项目目录里有什么。缺省是 `LIVED_IN`：Claude Code 和 Codex 两个宿主（Pi 和 omp 写着未检测到），各种状态都有；三个都检测到的给 `...THREE`，只检测到 Pi 的给 `...PI_ONLY`，只检测到 Codex 和 Pi（共用一个 skill 目录、合成一行的那几格）给 `...SHARING`（宿主的那份样例 `CODEX_AND_PI` 在 `preview-samples.ts`，和终端界面的预览共用）；要 Pi 的用户级配置里配过一个 MCP（markitdown）再加 `...PI_CONFIGURED` |
| `drive` | 打开浏览器**之前**，扮演浏览器给安装器发意图，把它驱动到要看的状态（用的是测试架子的 `cli/test/browser.ts`）。状态在安装器这边，真实的页面一连上看到的就是它。`toPurpose('documents')` 是换到那个用途的列表上 |
| `intro` | 开场动画。数字是定格在第几毫秒；`'played'` 是让它播完；`'skipped'` 是播着的时候按了一下键；`'reduced-motion'` 是系统开了「减少动态效果」，不播。不给就是这次运行里已经播过了（脚本先替页面发了 `intro-seen`） |
| `guide` | 开场引导留着不答，页面停在它上面（脚本等到它静止了才拍，`intro` 是数字的除外）。**不给就是这次运行里已经答过了**（脚本先替页面发了 `guide-answered`），页面直接出现——所以别的场景都不用管它。和 `drive` 一起给就是「改了选项、没答完就刷新」的样子 |
| `leaving` | 页面停在开场引导上之后替它答掉，把那一层的淡出定格在第几毫秒 |
| `ending` | 页面画出来之后让它走到哪种结束画面：`'finished'`（发「完成」）、`'switched'`（终端上按了 `t`，改用终端界面）、`'exited'`（安装器退出，页面重连不上）、`'denied'`（拿着不对的口令打开） |
| `tabs` | 页面画出来之后按几下 Tab：看键盘焦点落在哪、看不看得见 |
| `reveal` | 页面画出来之后把名字是它的那张卡片滚到窗口中间：要看的东西在一张长列表的下半截时用（不可选的卡片多半在） |
| `typing` | 页面画出来之后，在填 key 的对话框里有焦点的那个输入框里打进假装的 key（`FAKE_KEY`）再拍；拍完让它失去焦点、等「已填」多出一行，然后才查假装的 key 有没有留下 |
| `commands` | 外部命令的结局。缺省是没能运行（预览不执行命令，MCP 的行因此是「失败 添加命令没能运行」）；`'succeed'` 是假装它们都正常结束了——同样什么都不执行，只是答一个退出状态 0；`'tool-running'`（工单 12）是别的命令都正常结束、**工具的那一行命令一直不结束**（认的是「整行交给 shell」），画面停在它在终端里跑的时候。工具的复核看的是场景的可执行路径：`pandoc` 在上面所以是「已可用」，`docling` 不在所以 `'succeed'` 下它是「命令已正常结束，但在 PATH 中找不到」的失败 |
| `viewport`、`whole` | 见上面「怎么用」的第 2 条 |

- 「这台机器事先的样子」的四个字段，场景给了哪一个就**整个换掉** `LIVED_IN` 的那一个，不是往里添：只给 `onPath: ['claude', 'pandoc']` 的场景，主目录仍是 `LIVED_IN` 的。
- **要到一个新状态，先想它在哪一边**。在安装器这边的（看哪张列表、勾选、宿主、安装范围、填的 key、汇总）用 `drive` 发意图；只在页面上有的（开场动画、开场引导停在哪一段、键盘焦点、结束画面）才给场景加字段、在脚本里对着真实的页面做。
- 样例条目和「这台机器事先的样子」怎么布置，两份预览共用，在 `cli/scripts/preview-samples.ts`；只有一份预览用的样例留在那份预览自己的脚本里。
- 开场动画只在一次运行第一次打开时播，所以每个场景各起一个安装器、各开一个标签页。
- 页面的静态文件由脚本自己先打一遍（`buildWeb`），不用另外 `npm run build:web`。

### 用什么驱动浏览器

**本机装着的 Chrome（或 Chromium、Edge），经它自带的调试协议**；`cli/scripts/chrome.ts` 是那一小层：起一个没有窗口的 Chrome，开网址、定窗口大小、定系统的样子（深浅色、减少动态效果）和语言、在页面里算一个式子、按键、截图。协议走启动时接上的两条管道，不开端口。**没有为它加任何依赖**（工单 05 定的，维护者没有逐条确认）。

没有选的：

| 没有选 | 为什么 |
|--------|--------|
| 加一个浏览器自动化的库当开发依赖（Playwright、Puppeteer） | 预览要的只有上面那几样，自己写是两百行上下的一个文件。库本身不带浏览器：要么仍然用本机的 Chrome，要么另下一两百 MB；CI 从不生成预览，却每次 `npm ci` 都要装它 |
| 本机全局的 `playwright-cli`（工单 04 截图用的） | 它不在 `package.json` 里，换一台机器就没有；它是另一个进程，场景表却要和安装器在同一个进程里（每格各起一个安装器），两边只能靠临时文件传话；它还在当前目录留 `.playwright-cli/` |

代价和限制：

- 开发机上要有 Chrome、Chromium 或 Edge。找不到时脚本说明并以 1 退出；装在别处就用环境变量 `OXY_TOOLS_CHROME` 给出可执行文件的路径（给了就只认它，那个路径上没有东西同样说明并以 1 退出）。
- 只在 macOS 的 Chrome 上跑过。Windows、Linux 上的安装位置是照常见的写的，**没有实测**。
- 预览拍的是 Chrome 里的样子；别的浏览器（Safari、Firefox）里的样子它看不到。
- 某一格没拍成，整个生成就停下并以非零状态退出，报出是哪一格、为什么；不留半份 `index.html`。收场时（关标签页、等安装器退出）再出的错不报。Chrome 中途没了的话，要等两个 15 秒的超时才报出来。
- **图上各栏的滚动条是一直画着的**（内容比栏高时），占着十来像素的宽：没有窗口的 Chrome 就是这样，Windows 上、macOS 接了鼠标时也是这样；macOS 用触控板时它平时不显示。留着它是有意的：哪一栏冒出了横向滚动条，图上一眼看得见。
- Chrome 起来时带着这几样：没有窗口；用户数据目录是临时的（不碰真实的书签、登录、扩展）；不走系统的代理；回环地址以外的名字一律解析不到（`--host-resolver-rules`），所以页面万一向外发请求，在预览里是失败的，Chrome 自己的后台更新也发不出去；截图上一个点就是页面上的一个像素。

### 踩过的坑

| 现象 | 原因与办法 |
|------|------------|
| 截图底部把页面顶部又画了一遍，左下、右下的东西被切掉 | 改了窗口大小紧接着就截。脚本每次改完窗口、换完深浅色都等两帧再加一百来毫秒（`SETTLED`），并核对页面的宽高正好等于要的窗口 |
| 要某一时刻的定格 | `for (const a of document.getAnimations()) { a.pause(); a.currentTime = 毫秒 }`。开场的各段动画是同时开始的，同一个时刻对它们都成立 |
| 定格往回拨了一下，开场那一层没了 | 动画从「进行中」拨回「还没开始」也会发 `animationend`，页面把它当成淡出完了。**时间只许往前拨**：脚本发现页面已经播过了要定格的那一刻就报错，不往回拨 |
| 大标志放大了，方块之间有细缝 | 宽不是 25 的整数倍，方块落不到整像素上。见「大标志」 |
| 换了深浅色，「减少动态效果」的模拟没了 | Chrome 的 `Emulation.setEmulatedMedia` 每次都是整份替换：只给深浅色，上一次给的别的几样就清掉了。`chrome.ts` 的 `system(scheme, reducedMotion)` 因此两样一起给 |
| 口令不对的那一格，中英文跟着开发机的浏览器变 | 这个画面没有画面状态，照 `navigator.language` 说。脚本用 `Emulation.setUserAgentOverride` 的 `acceptLanguage` 把浏览器的语言定成场景的语言 |
| 脚本出错时没人接的拒绝让进程当场退出，临时目录和 Chrome 都留下了 | 同时等两样（`Page.navigate` 的答复和加载完的事件）时用 `Promise.all`，哪一样先出错都有人接；每格开了什么都记进收场的清单，出错也照相反的先后收掉 |
| 选中的卡片里的字比旁边的卡片偏右两像素 | 卡片选中用的类名和右栏已选那一块撞了（都叫 `.picked`），卡片吃到了右栏的内边距。样式是一整份，类名全页共用：卡片的选中叫 `.selected`，右栏那一块叫 `.picked`。起新类名先在 `style.css` 里搜一遍 |
| 装到项目时标题下面的目录掉到了那句话的下一行（工单 08） | 同一个坑：那一行起的类名 `.where` 和汇总面板里位置那一栏的 `.where`（网格布局）撞了。改叫 `.directory` |
| 只检测到一个宿主、装到项目时，顶上的目录从中间折开（`~/work/my-` / `app`；任务 `10-12-installer-add-pi-omp-hosts` 工单 02 的视觉审查看到的） | 加了第三个宿主才有的：只有一个宿主时宿主和安装范围和标题同一行，那一块里「未检测到」的由一个变成两个、宽了七十多像素，标题那一格从二百九十来像素缩到二百一十来像素，而目录那一行原先是照标题那一格排的。拿任务开始前的提交 `c7f68aa` 对照过：那时不折（证据在那个任务目录的 `screenshots/baseline-c7f68aa-web-browse-project-*-only-1280-*.png`，修之前的是 `baseline-ce8f933-…`）。改成照整条的宽度排（见「三栏」里安装范围那一条），预览加了机械检查和「浏览 · 只检测到 Claude Code · 装到项目」「浏览 · 只检测到 Pi · 装到项目」两格 |
| 勾了勾选框，安装器没照办，框却留着勾 | 浏览器点一下就把框勾上了，而画面状态没变时 Preact 不会把它改回去。卡片和「覆盖它」的勾选框因此在点的那一下先把自己改回画面状态里的样子，再发意图：勾没勾上只照画面状态 |
| 重新构建了页面，预览里还是旧的 | 页面的静态文件是起本机的网页时读进内存的。`npm run preview:web` 每次自己先打一遍，不会遇到；手工起安装器看页面时要重起 |
| `reveal` 指定的卡片没滚到窗口中间，图上还是列表的顶部（工单 09 发现，之前「有不可选的条目」那几格也是这样） | 页面刚画出来时「换了一张列表就回到顶部」那个效果（`browse.tsx` 里的 `scrollTo(0, 0)`）还没跑，紧接着滚会被它拨回去。脚本在滚之前先等两帧 |
| 1024×768、英文界面下左栏冒出滚动条，有一行用途名折成了三行（工单 15） | 内容只比窗口高一像素，可滚动条一出来就占掉十来像素的宽，用途名折得更多，于是变成高出四十多像素。量一栏放不放得下，别只看 `scrollHeight`：先把这一栏的 `overflow` 临时设成 `hidden` 再读，得到的才是没有滚动条时内容的高（macOS 用触控板时滚动条不占宽，看到的是这个数） |
| 预览里左栏放得下，真实的目录里却放不下（工单 15） | 预览的样例目录里只有四个用途有条目，左栏连「推荐」五行；仓库里真实的目录是十个用途、十一行。**动左栏的高矮，要拿十个用途都有条目的目录量**：一次性的脚本里把 `catalog.json` 和 `index.json` 读进来交给 `catalogOf`，或给样例里空着的六个用途各补一条。预览里至今没有这样的一格 |

| 点击核对的脚本里，刚冒出来的输入框打不进字、`blur()` 之后页面没反应（工单 10） | 页面是在画完之后的下一拍才把焦点给新出来的输入框的（`useEffect`）。脚本一等到输入框出现就 `document.execCommand('insertText', …)`，字打给了页面本身；这时 `blur()` 的也是一个没有焦点的框，浏览器不发任何事件。**等 `document.activeElement` 就是那个输入框再动手**。没有窗口的 Chrome 里页面是有焦点的（`document.hasFocus()` 为真），打字、失去焦点时浏览器自己会发 `change` 和 `blur`，不用脚本代发 |
| 要在点击核对的脚本里按回车 | `chrome.ts` 的 `press` 只有 Tab 和 Escape。回车对输入框的效果是「内容变了、焦点还在」：对它发一个 `new Event('change', { bubbles: true })`，不调 `blur()` |
| `<input type={条件 ? 'text' : 'password'}>` 过不了页面的类型检查（工单 10） | Preact 给 `<input>` 的属性是按 `type` 分开的几种，一个「两者之一」的 `type` 哪一种都对不上。把它写成两个定死的对象里挑一个再展开：`const FIELD = 条件 ? ({ type: 'text' } as const) : ({ type: 'password' } as const)`，`<input {...FIELD} />` |
| 标题下面多了一行（装到项目时的目录），同一行右边的控件掉到两行中间（工单 14） | 外面那一条是 `align-items: center`，而左边的标题块自己会折成两行。一行里有会长高的一块时照基线对齐（`baseline`），别的东西才跟着它的第一行 |
| 进度里的小圆环在折成两行的行里掉到两行正中，旁边的 `✗` 却贴着第一行（工单 14） | 那一行是照基线对齐的网格，小圆环是个空元素、没有基线，原先另写了 `align-self: center`——单行时看不出来。空元素要贴着第一行就 `align-self: start` 加一点上边距（现在是 4.5px，正好在 13px / 1.55 的第一行中间），不要居中 |
| 深色下各栏的滚动条轨道是一条比底色亮的灰带，`color-scheme: light dark` 早就写了（工单 14） | `color-scheme` 只是让原生控件换成深色的那一套，Chrome 深色的轨道是 `#2c2c2c`，底色是 `#08090A`。要轨道不显出来得另写 `scrollbar-color: <滑块> transparent` |
| 按住回车或空格跳过开场动画，直接进了挑选的页面（工单 16 的审查发现，真实的浏览器里重现了） | 第一下 `keydown` 跳过了动画，焦点随后落到「开始挑选」上；键还按着，系统自动重复的 `keydown` 就落在按钮上。只拦第一下不够：引导开着的整段时间里，`event.repeat` 的回车、空格都 `preventDefault`。在调试协议里重现要给 `Input.dispatchKeyEvent` 带上 `autoRepeat: true` |
| 触屏上轻点一下跳过开场动画，顺手改了选项或直接进去了（工单 16，同上） | 鼠标没有这个问题：按下时控件还是 `inert`，按下和抬起不落在同一个东西上，`click` 发给了它们共同的上一层。触屏的 `click` 是抬手之后才定落在哪的，那时控件已经可以操作了。跳过用的是 `pointerdown` 时把接下来的那一次 `click` 在捕获阶段吞掉；再有一次 `pointerdown` 就不再吞（那一下根本没有补发 `click` 的话，不至于吞掉用户下一次真的点击）。重现用 `Emulation.setTouchEmulationEnabled` 加 `Input.dispatchTouchEvent` |
| 「开场引导 · 答完了，淡出」那一格深色和浅色不是同一刻（工单 16） | 卡片是在那一层开始淡出的**下一拍**才带上浮上来的动作的（页面先知道引导答完了，下一拍才告诉中间一栏）。脚本一看到那一层在淡出就定格，卡片的动画那时还不存在，没被定住，接着照真实的时间走。等 `.list.rising` 也出现了再定格 |
| 开场引导刚静止就按 Tab，焦点跑到了页面之外（工单 16） | 焦点是画完之后的下一拍才落到「开始挑选」上的（`useEffect`），和填 key 的输入框是同一个坑。脚本等的是 `.intro.still :focus`，不是 `.intro.still` |
| 想量开场从出现到收掉多久，从脚本这边掐表得到八秒多（工单 14） | 掐进去的是刚起来的 Chrome 开第一张页面的时间。照页面自己的时钟量：那一层出现的时刻是 `performance.now() - 淡出那段动画的 currentTime`，收掉的时刻是它不在了的那一刻的 `performance.now()` |
| 有开场引导时照上一行的办法量不出来：找不到淡出的那段动画（工单 17） | 检测到宿主时那一层不自己淡出，`intro-out` 要到答完才有。量「从那一层出现到开场引导可以操作」：出现的时刻是 `performance.now()` 减去按钮那一行（`.intro-actions`）上那段 `appear` 动画的 `currentTime`（开场各段动画是同时开始的），可以操作的时刻是那一层带上 `still`、焦点落到「开始挑选」上的那一刻。两种情形都要量时先找 `.intro-actions` 上的 `appear`，没有再找 `intro-out` |
| 要在真实的浏览器里试「跳过的那一下有没有落到控件上」「只用键盘走一遍」，页面里的 `click()`、`dispatchEvent` 试不出来（工单 16、17） | 那几道守卫认的是真实的 `pointerdown`、`keydown` 和浏览器补发的 `click`。要经调试协议发：`Input.dispatchMouseEvent`（`mouseMoved`、`mousePressed`、`mouseReleased`，坐标取控件的 `getBoundingClientRect()` 的中心）和 `Input.dispatchKeyEvent`。`chrome.ts` 的 `Tab` 只露出了 Tab、Escape 和 `evaluate`：一次性的脚本把它拷一份到仓库外面的临时目录，在 `newTab` 返回的对象上多加一个 `raw: tab`，仓库里的那一份不为一次核对改。**回车要带 `text: '\r'`、空格带 `text: ' '`**，不带的话按钮和勾选框不会被按动（方向键、Tab 不用带） |
| 要「只检测到一个宿主」「一个都没检测到」的真实运行（工单 17） | 检测看的是可执行路径上有没有 `claude`、`codex`：给安装器的子进程一份自己列的 `PATH`，留哪个宿主就带上它所在的目录。预览里是场景的 `onPath`，同一个道理 |
| 驱动 Chrome 的那一层偶尔报「一直没有等到 `Page.loadEventFired`」（工单 17：起过浏览器的十九次运行里两次） | **原因没有查明**。其中一次页面其实已经画出来了（三栏和开场引导都在），只是「加载完」的事件 15 秒里没有来；同一种情形重跑就过。遇到先重跑一次；反复出现再查是不是页面有哪个请求迟迟不结束 |
| 预览里装到项目的目录那一行排得好好的，真实运行里却从词的中间折开（工单 17） | 预览的样例目录是 `~/work/my-app`，短。真实运行里项目目录不在主目录下时是 `/` 开头的整条路径，长了就折（见「看过、留给维护者定的」）。**发布前核对用的临时项目目录正好是这样一条长路径**，装到项目的那几步顺带看一眼目录那一行；预览里至今没有长路径的一格 |

预览里没有的、要看就在真实的浏览器里另外看的：一路按 Tab 焦点依次落在哪、开场从出现到收掉（或到开场引导可以操作）多久、按键和点一下是不是立刻跳过动画而又没有落到开场引导的控件上、链接是不是在新标签页打开、鼠标移上去的样子。预览只把画面状态画出来拍下，**不点页面上的任何东西**——页面上哪个按钮没接上意图，它查不出来。

**加了会点的东西，就在真实的浏览器里点一遍**（工单 07 这样核对过：点卡片的名字勾上、去汇总、勾「覆盖它」、开始安装、继续挑选、Esc 返回、× 去掉、完成；工单 10：勾 MCP、去汇总先到填 key、打字后离开输入框紧接着点「好了」、「换一个」、什么都不填就走开、按回车之后 Esc、×，并查了输入框的类型、圆点的样式、页面上没有密码框、页面和答复里搜不到打进去的值）：写一个一次性的脚本放在仓库外面的临时目录里，照预览脚本的办法起安装器和 Chrome（`chrome.ts`、`preview-samples.ts` 的 `stageWorld`），用 `tab.evaluate` 在页面里 `click()`，等页面上出现该有的东西，再把读到的字打出来看。脚本不提交。等页面变的时候**等的是安装器推来的那一份画出来的东西**（比如那句「没勾…」不见了），不是勾选框自己的 `checked`。

### 一个任务收尾时整体核对一遍

逐张工单各看各的那几格，放在一起才看得出的不一致要另查一遍（任务 `10-11-installer-web-ui` 工单 14 这样做的，验收后加了开场引导、改了左栏，工单 17 又做了一遍；记录在那个任务的 `research/final-check-record.md`）：

1. **每个必须有的画面对到一格**：拿规格里列的画面与状态逐个去找格子，对不上的补场景。
2. **把字抽出来数**：`index.html` 里每格的 `<pre>` 是这一格页面上的文字。中文的格、英文的格分开，数每一句出现在几格里——同一种东西两种说法、英文格里的汉字、被截断的「…」，一眼看得出来。
3. **对着源码看每一种东西是哪个部件、哪个类名画的**（状态的词、原因、标记、提醒、按钮）：同一种东西由两处各画各的，就是不一致的来处。
4. **数颜色**：把全部的图缩小，数有彩度的像素落在哪个色相上——应当只有黄、绿、红，青蓝紫是 0。
5. **改样式前后各留一份图，逐张比哈希**：变了的应当只有打算改的那几格（带转动的小圆环的格每次拍到的角度不同，除外）。
6. 放不下的地方和假装填的 key 由脚本自己查（上面「怎么用」的第 5、6 条）。
7. 最后把图交给没看过代码的人（或子代理）看一遍：这次自己归拢时漏掉的一处对齐，是那样看出来的。

### 看过、留给维护者定的

立预览时（工单 05）和之后各张工单的视觉审查在图上看到的，都是页面本身的事。工单 14 整体核对时逐条过了一遍，**下面五条不在表里了**。前两条页面没有动，改的是本文件——是让规范照着实现说，维护者没有看过；后三条改了页面：

- 英文界面只有一个宿主时宿主和安装范围折到标题的下一行——放不下，「三栏」一节的那一句改成了「放得下就同一行」。
- 用途下只有外部项目时顶上那一条照样有宿主和安装范围——实现者定为就是这样，写进了「三栏」一节。
- 深色下各栏原生滚动条的轨道是一条亮带——`color-scheme: light dark` 从一开始就有，轨道仍是 Chrome 深色的灰（`#2c2c2c`），压在近乎全黑的底色上发亮。改成轨道不铺底色、滑块用最淡的文字色（`:root` 上的 `scrollbar-color`）。
- 只检测到一个宿主、又选了项目时，右边的宿主和安装范围掉到标题与目录两行之间——改成照基线对齐。
- 进度里正在装的小圆环在后面的话折成两行时掉到两行中间，而 `✗` 是贴着第一行的（工单 14 的视觉审查看到的，英文、1024 宽、轮到工具的那一格）——小圆环改成贴着第一行。

## 结束画面

已完成、已改用终端界面、安装器已退出、口令不对。用一栏、居中的版式：

- 整页只有一个标题（18px、600、前景色）和下面一句说明（次要文字色），**没有任何控件**。标题前面是一个符号，四种画面的符号占同样宽的一格：已完成是就绪色的 `✓`，口令不对是失败色的 `✗`，安装器已退出和已改用终端界面是次要文字色的 `–`。彩色只落在符号上，标题不上色。
- 它们不照「出错」一节的画法（不以「出错：」开头，没有「原因」「下一步」两行）。
- **已改用终端界面**（工单 11）：终端上按了 `t`。它不是出错、也不是装完了，所以和「安装器已退出」同一个符号、同一种不上色的画法；不同的只是话——那一页告诉用户安装器还在、去终端接着用，这一页不让他重新运行。

  | | 标题 | 说明 |
  |---|------|------|
  | 中文 | 已改用终端界面 | 请回到终端继续。这一页已经失效，可以关掉了。 |
  | 英文 | Switched to the terminal UI | Go back to your terminal to continue. This page no longer works and can be closed. |

  页面是从最后一份画面状态的 `stage: 'terminal'` 得知的；之后连接断开不改口成「安装器已退出」。

截图在任务目录的 `screenshots/03-skeleton-*.png`、`04-ended-*.png` 和 `11-ended-switched-*.png`。

## 实现时定下、维护者还没有看过的画法

对比页上没有画、本文件照着推的。实现到那一步时做出来给维护者看，看过的从这里划掉：

- 一个宿主都没检测到时的画面：顶上那一条不写宿主、也没有安装范围，组件的卡片都是不可选的画法，原因是「需要 AI Agent」；外部项目照常；左栏的本机信息里多一行「注意」。（工单 04 做出来了，`04-browse-no-host-*.png`）
- 用途下只有外部项目时的画面：没有组件的分区，直接是外部项目一区。（工单 04，`04-browse-no-host-apps-only-*.png`）
- 已选为空时的右栏：一句空状态的话「还没有选任何条目」，「去汇总」不可点。（工单 04）
- **右栏底部多了一个次要的「完成」按钮**（工单 04 加的，对比页上这一栏只有「去汇总」）：只逛不装的人要有个地方让安装器退出——加它的时候关掉页面还不会让安装器退出（那是工单 11 做的），不留这个按钮就只剩回终端按 Ctrl+C。现在关掉页面也退得出，这个按钮留不留由维护者定。
- 目录里一个条目都没有时的画面：左栏没有用途，中间一栏只有那一句「没有可用的条目」。（工单 04，`04-browse-empty-catalog-*.png`）
- 带推荐标记的外部项目在名字后面跟一个「推荐」的标记：对比页上外部项目没有画标记，终端界面里它们是标的。
- 站点图标的样子（深色圆角方块上一个白的 O）。
- 工单 04 照实现改掉的对比页上的数值：大标志的宽（58px → 50px，440px → 450px）；控件的名字和分区小标题后面那句话的颜色（最淡的 → 次要文字色）；外部项目的名字（13.5px → 14px）。
- 结束的三种画面（已完成、安装器已退出、已改用终端界面）和口令不对的画面：一句说明，上面没有还能点的操作。工单 03 做出了其中三种，工单 11 补上了「已改用终端界面」（符号和「安装器已退出」一样是次要文字色的 `–`，那两句话是实现者写的），画法是实现者定的，见「结束画面」：标题不上色、彩色只落在行首的符号上，没有照「出错」一节用失败色的标题。
- 工单 11 给安装中底部的提醒补的后半句（「关掉这一页，这一批也会装完，结果打在终端里。」）：话是实现者写的。
