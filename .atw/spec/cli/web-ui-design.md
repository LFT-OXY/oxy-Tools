# 网页界面的设计

> 安装器的网页界面该长什么样：颜色与含义、字号与间距、各个画面的版式要点、深浅色、不可选与出错的画法、放不下时的退路、开场动画。内容取自任务 `10-11-installer-web-ui` 的 `ui-direction.md`（维护者 2026-10-11 在对比页上选定的视觉方向），**任务归档后以本文件为准**。
> **本文件只管网页界面。** 终端界面的画法见 [界面设计](./ui-design.md)；两套界面共用的只有那份文档里「状态的写法」的词、「条目的标记」的词，和成功、失败、跳过这三个结果的符号（`✓` `✗` `–`）。
> **逐张工单实现**（任务 `10-11-installer-web-ui`）：工单 09 之后有的是三栏的浏览（左栏、条目的卡片、外部项目、右栏的已选）、开场动画、几种结束画面、左栏最下面的切换语言、装本仓库的 skill 和第三方 Skill 的那条线——卡片的选中、含多个 skill 的第三方 Skill 卡片上挑 skill 的清单、汇总、安装中、结果——和顶上那一条里能改的宿主与安装范围；MCP、工具的勾选和填 key 还没有，见文末「现在做到哪了」。工单 05 立了网页界面的预览（`npm run preview:web`），之后改页面都对着它看。数值起初取自选定的那张对比页，实现时以真实的画面为准——已经照实现改过的几处在各节里写明。
> 用词：正文说「宿主」；界面文案里它显示为「AI Agent」。「用途」只指 `GLOSSARY.md` 里的那个词；key 的那一句叫「说明」。

## 方向：利落

一切都退到最细的线和最准的字后面，只剩用户要看的东西。参照的是 Linear、Vercel 这一类当下的开发工具。

- 三栏：左边用途，中间条目，右边已选。条目是卡片。
- 黑白灰。**彩色只有说状态的那三种**（就绪、留意、失败）；按钮和选中用前景色。
- 深色与浅色各一套，跟随系统。

维护者明确不要的（四轮对比页里否掉的），实现和以后改版时都别走回去：

| 不要 | 说的是什么 |
|------|------------|
| 紫色系 | 紫、蓝紫的强调色，淡紫的背景，粉到紫到蓝的渐变按钮——「很像 AI 做的样式」 |
| 成排的圆角标签当导航 | 用途排成一两排自动换行的胶囊 |
| 复古 | 等宽字铺满、印刷品的纸色与衬线、机器面板与拨动开关 |
| 汇总里列出将执行的命令 | 见下面「汇总」 |

**要改画面，先改本文件，再改实现**，然后生成网页界面的预览对照（`npm run preview:web`，见文末「网页界面的预览」）。

## 颜色的含义

颜色都是具名的变量，深色、浅色各一份；样式里不直接写色值。

| 变量 | 浅色 | 深色 | 用在哪 |
|------|------|------|--------|
| 底色 | `#FFFFFF` | `#08090A` | 中间一栏的底 |
| 侧栏底色 | `#FAFAFA` | `#0D0E0F` | 左栏、右栏、提醒条的底 |
| 卡片底色 | `#FFFFFF` | `#101112` | 卡片、盖在上面的面板、次要按钮 |
| 抬一档的底色 | `#F2F2F2` | `#1A1B1D` | 当前的用途、选中的卡片、分段控件里选中的那一格 |
| 前景色 | `#111111` | `#F7F8F8` | 名字、标题、正文；**也是唯一的强调色**：主按钮的底、选中卡片的描边、已勾的勾选框、「推荐」标记的底 |
| 次要文字 | `#5C5F66` | `#A2A6AD` | 说明、未选中的用途名、分区的小标题 |
| 最淡的文字 | `#8A8F98` | `#6C7078` | 条目数、宿主的名字（状态前面的那个）、版本号、链接的网址、未装这类「退后」的状态词 |
| 线 | `#E8E8E8` | `#202225` | 分栏的线、卡片的边、列表项之间的线 |
| 就绪 | `#1F7A3A` | `#7BD88F` | 已装、已配置、已安装、已填、成功的 `✓` |
| 留意 | `#8A5A00` | `#E5C04B` | 版本不同、非本工具安装、覆盖、要填 key、现在装不了、「注意」 |
| 失败 | `#B3261E` | `#F2777A` | 失败、`✗` |
| 留意的底色 | `#FBF3D9` | `#231E0D` | 汇总里「覆盖它」那一条的底 |
| 开场的底色、开场的字 | `#000000`、`#F7F8F8` | 同左 | 只给开场动画：深色、浅色下它都是黑底白字 |

变量在 `cli/web/style.css` 的开头（`--ground`、`--side`、`--card`、`--raised`、`--ink`、`--secondary`、`--faint`、`--line`、`--ready`、`--attention`、`--failed`、`--attention-ground`、`--scrim`、`--intro-ground`、`--intro-ink`）。`--scrim` 是盖着面板时底下压暗的那一层：黑，浅色下 32% 不透明，深色下 60%（工单 07 定的，对比页上没有给数）。

规则：

1. **彩色只有就绪、留意、失败这三种，只用来说状态**：状态的词、结果的符号、合计里失败的那个数字、必填的 key 没填时那一句后果、已选里装不了的原因、汇总里「覆盖它」那一条的底。名字、说明、路径一律前景色或次要文字色。卡片上不可选的原因是个例外，它用前景色粗体：那张卡片的名字退了一档，原因要比周围都亮才读得到。
2. **没有第四种彩色**。要强调就用前景色的实心，或者粗一档的字。
3. **「留意」和「失败」的词同时加粗**，和终端界面一样。
4. 选中、当前项、焦点都不单靠颜色：选中是描边加底色加勾，当前的用途是底色加粗一档，焦点是一圈 2px 的前景色描边（离元素 2px）。

对比度（按 WCAG 的算法算的，对着卡片底色；4.5:1 是正文字号下通行的可读门槛）：

| | 前景色 | 次要文字 | 最淡的文字 | 就绪 | 留意 | 失败 |
|---|---|---|---|---|---|---|
| 浅色 | 18.9 | 6.4 | **3.2** | 5.4 | 5.9 | 6.5 |
| 深色 | 17.8 | 7.7 | **3.8** | 10.9 | 10.8 | 6.9 |

**已知的弱点**：最淡的文字两边都不到 4.5:1。它只许用在真正次要的东西上——条目数、宿主的名字、网址；**不可选的原因、提醒、出错说明不许用它**。「未装」「未配置」用它是沿用终端界面「暗淡表示退后」的做法，含义靠词不靠色。维护者没有就这一点表过态。

### 大标志

网页界面里的 OXY 大标志是**单色**的，用前景色：深色下是白的，浅色下是黑的（维护者 2026-10-11 选定）。它是照终端里那五行方块画成的像素图形，不是文字。

它横向 25 格、纵向 10 格。**宽取 25 的整数倍**，每个方块才落在整像素上、方块之间看不到缝：左上角的是 50px，开场里的是 450px（窗口很窄时是窗口宽的 60%）。图形按像素对齐来画，不做边缘的柔化。对比页上是 58px 和 440px，放大了看得到方块之间的细缝，实现时改的。

站点图标是大标志里的那个 O：深色的圆角方块上一个白的 O，在浏览器的深色、浅色标签栏上都看得清。

终端里的大标志不变，仍是粉到紫到蓝的渐变（[界面设计](./ui-design.md) 的「大标志的颜色」）。两处不一样是有意的：网页界面里不要紫色。

## 字

- **字体**：系统自带的无衬线字（macOS 上是苹方与 SF，Windows 上是微软雅黑与 Segoe UI）。**不加载任何外面的字体**——网页界面不许向互联网发请求。路径、第三方 Skill 里各个 skill 的名字、key 的变量名、让用户照着敲的命令（`npx oxy-tools`）用系统的等宽字；夹在一句话里的命令用前景色，才认得出是要敲的东西。
- 字距略收（约 -0.003em）。

| 角色 | 字号 / 行高 | 字重 |
|------|-------------|------|
| 界面的基准（用途、控件、已选） | 13px / 1.55 | 400；当前项 500 |
| 用途的标题（中间一栏顶上） | 16px | 600 |
| 分区的小标题（Skill、第三方 Skill、MCP、工具、外部项目） | 12px | 500；后面跟的那句话 400 |
| 条目的名字（卡片上的，和外部项目的） | 14px / 1.4 | 600 |
| 条目的说明 | 13px / 1.6 | 400 |
| 状态、标记 | 12px、11px | 400；留意与失败加粗 |
| 外部项目的网址 | 11.5px / 1.5，等宽 | 400 |
| 左栏最下面的本机信息 | 12px | 400；「本机」两个字 500 |
| 面板的标题（汇总、填 key、结果） | 18px / 1.3 | 600 |
| 结果的合计数字 | 26px | 600 |

**说明从不截断**：没有省略号，没有固定高度，没有「展开」。放不下就折行、卡片跟着变高。名字、路径、网址允许在任意位置断开，免得撑出横向滚动条。**状态的词和标记不折行、不被挤窄**：「已装」「要填 key」这样的词要么整个在这一行，要么整个到下一行。

## 间距与圆角

| | 值 |
|---|---|
| 三栏的宽 | 左 228px，右 296px，中间吃掉剩下的；窗口不足 1100px 时左 196px、右 256px |
| 中间一栏的左右留白 | 24px（窄时 16px） |
| 卡片 | 内边距上 13、左右 14、下 11；卡片之间 8px；圆角 8px；边 1px |
| 控件（按钮、勾选宿主的小块、分段控件、用途的行） | 圆角 6px |
| 标记、勾选框 | 圆角 4px；勾选框 16px 见方 |
| 盖在上面的对话框 | 圆角 12px |
| 分区之间 | 小标题上方 22px、下方 8px |

没有阴影，没有渐变。层次靠线和底色的三档（底色、侧栏、抬一档）。

### 共用的部件

后面的工单接着用这几样，不另画一套（样式在 `cli/web/style.css`）：

| 部件 | 画法 |
|------|------|
| 按钮 | 缺省是次要的：卡片底色、线的边、前景色的字、500、内边距 7px 14px。主按钮（`.primary`）是前景色实心、底色的字。**一个画面上只有一个主按钮**。不可点时整个 40% 的不透明度 |
| 勾选框 | 真正的 `<input type="checkbox">`，画成 16px 见方、1.5px 最淡的边、圆角 4px；勾上是前景色实心加一个勾。宿主的小块里的是 14px。不可选的是虚线的边 |
| 分段控件 | 两个真正的单选，各画成一格；选中的那一格是抬一档的底色、前景色的字、500 |
| 标记 | 11px、线的边、圆角 4px、次要文字色；「推荐」是前景色实心（`.solid`） |
| 状态的词 | 照含义上色：就绪（`.ready`）、留意（`.attention`，加粗）、失败（`.failed`，加粗）、退后（`.faint`）；不上色的就是前景色。一个宿主一段，段里不折行。**这四个类名只给词用**：别拿状态的名字当一行、一段的类名（`<li class="failed">` 会让整行变成失败色粗体——工单 07 的第一版结果行就是这样） |
| 盖在上面的面板（`.scrim` 里的 `.panel`） | 从右边出来，宽 720px、至少给底下留 280px，卡片底色、左边一条线；底下压暗（`--scrim`）。上中下三段：标题一段，中间自己滚动，底部的按钮不动、靠右。打开时焦点落到面板上，底下的三栏点不到也聚焦不到（`inert`）。没有滑出的动画 |
| 等宽字（`.mono`） | 条目的名字（面板里的）、位置；可以在任意位置断开 |
| 小字（`small`） | 12px、最淡的文字：已选里的类型、面板里名字后面的类型。说的是用户要知道的事时另给颜色（汇总里的备注是次要文字色） |
| 一栏、居中的版式（`.solo`） | 宽 520px，上方留视口高度的 18%：还没连上时的那一句，和几种结束画面 |

## 版式

### 三栏

| 栏 | 里面有什么 |
|----|------------|
| 左 | 大标志、产品名与版本号（不许折行；窗口窄时把间隔收到 8px）；「推荐」，一条线，然后是各个用途，每行右边是条目数；最下面是本机信息，再下面是切换语言 |
| 中 | 顶上一条贴着不动：用途的标题与条目数，后面是「装进哪些 AI Agent」和「装到哪里」——放得下就和标题同一行、靠右，放不下就**两样一起**折到下一行，不拆开；下面是条目，按类型分区；最后是外部项目 |
| 右 | 「已选」和数量；每个已选的条目一行；最下面固定着「去汇总」 |

每一栏各自滚动，整页不滚。**已选的数量、名字和「去汇总」任何时候都在屏幕上。**（三栏那一行的高钉死成窗口的高：`grid-template-rows: minmax(0, 1fr)`。不写它，哪一栏的内容够高就可能把整行撑出窗口。）

- **用途是一竖列**，不排成横向的标签。没有条目的用途不出现。当前的用途是抬一档的底色、前景色的字、粗一档。用途名放不下就折成两行，条目数留在第一行的右边。每一行是一个按钮；鼠标移上去字变成前景色。
- **本机信息**（左栏最下面，次要文字色）：一个小标题「本机」；一行宿主——检测到的名字后面一个就绪色的 `✓`，没检测到的后面是最淡的「未检测到」；一行「目录」和各类条目的数量；有提醒时每条再一行，行首是留意色粗体的「注意」，话用前景色（提醒不许用最淡的文字）。提醒有两种，话和终端界面的本机信息是同一份：一个宿主都没检测到（「没有检测到 Claude Code 或 Codex，暂时装不了组件；外部项目仍可浏览」），和有条目被跳过。宿主和它的状态、每一类的数量，要么整个在这一行，要么整个到下一行。
- **切换语言**（左栏最下面，本机信息下方 14px）：一个两格的分段控件「中文」「English」，和安装范围用的是同一个部件，靠左、不撑满这一栏；当前的语言是抬一档的那一格。两项的字各自写在自己的语言里（`lang` 属性也是），不随界面语言变；控件的名字（读屏软件念的）是终端界面语言提问的那一句「Language / 语言」，不显示出来。名字和两项都随画面状态来，页面不另写。点了另一格只是告诉安装器，画面由安装器按新的语言重发；所在的用途不变，终端上的语言不变（见 [网页界面的契约](./web-ui-contract.md) 的「页面上换语言」）。
- **顶上那一条里的字**：条目数（「21 项」）用最淡的文字；「装进哪些 AI Agent」「装到哪里」这两个控件的名字用次要文字色——对比页上是最淡的，它们是读懂控件要看的字，实现时提了一档。两个宿主时每个宿主是一个带勾选框的小块（线的边、圆角 6px）。
- 1280 宽、两个宿主时，宿主和安装范围放不进标题那一行，**两样一起**在第二行；只有一个宿主时它们和标题同一行。同一种宿主配置下，换用途不会让这一条忽高忽低（标题留了至少 200px）。
- 这两个控件的名字和各个安装范围的名字随画面状态来，是终端界面那两个提问的文案；页面不另写。
- **只检测到一个宿主时**没有可勾的小块，写一句「装进 Codex」，没检测到的那个写在旁边（「Claude Code 未检测到」，最淡的文字）。
- **一个宿主都没检测到时**顶上那一条只有标题和条目数，不写宿主，也没有安装范围：没有要装进的地方。
- **安装范围**是一个两格的分段控件：全局、项目。选了项目时标题下面写明是哪个目录：自己占一行，那句话用次要文字色（「只对当前目录生效：」，和终端界面「项目」那一项后面的是同一句），目录是等宽字，长了在任意处断开、从不截断。只检测到一个宿主时照样有这一行。
- **两个宿主的小块**是真正的勾选框，点了只告诉安装器，勾没勾上照画面状态画。想把最后一个也去掉时安装器不照办，小块后面出一句留意色的「至少留一个」，宿主变了这句就收掉。

### 条目的卡片

两张一排（窄时仍是两张）。从上到下：

1. 名字，右上角是勾选框。
2. 标记（有才有）：「推荐」是前景色实心；「要填 key」「可选的 key」是线框。
3. 说明，完整的。
4. 最下面一行是状态：每个所选的宿主一段，宿主的名字用最淡的文字，后面是状态的词（词照 [界面设计](./ui-design.md) 的「状态的写法」）。只选了一个宿主时不写宿主的名字。工具只有一个状态。

| 状态 | 画法 |
|------|------|
| 未选 | 线的边，卡片底色，空的勾选框 |
| 选中 | **前景色的边**，抬一档的底色，实心的勾选框 |
| 不可选 | **虚线的边**，没有底色；名字和说明都用次要文字色（名字比可选的卡片退一档，说明不变）；勾选框是虚线、勾不上；状态的位置写**原因**，前景色、粗体（需要 AI Agent、需要别的 AI Agent、只能装到全局、不支持 macOS）。原因直接在卡片上，不靠鼠标悬停 |

**不可选的卡片不用最淡的文字**（维护者 2026-10-11 定的）。选定的对比页上不可选卡片的名字和说明是最淡的，那里只画了一张；一个宿主都没检测到时整栏都是这样的卡片，名字和说明只有 3.2:1，读不清。「装不了」靠三样一起说：虚线的边、虚线的勾选框、粗体的原因——不靠把字调淡。

- 同一排的两张一样高，状态那一行沉在卡片底部。
- **含多个 skill 的第三方 Skill** 勾上之后卡片占一整行，说明下面多一块：终端界面那一问的话（「paper-kit 里有 3 个 skill，选择要装的」，随画面状态来），然后是各个 skill 的清单，三栏（窄时两栏）。每个 skill 是一个小格：勾选框和名字（等宽、600）一行，下面是完整的说明，最下面是它自己在每个所选宿主下的状态（未装、已装、不支持，词和卡片底部的一样，字再小半档）；挑了的小格是前景色的边。起初一个都没挑。去掉条目之后清单收起，再勾上时挑过的还在。（工单 09 照实现定的：对比页上只画了「已装」一个词，这里每个 skill 都写状态——工单要求每个 skill 带说明和状态。）
- 分区的小标题后面可以跟一句说明（「第三方 Skill　内容直接来自作者」）。它和小标题同是次要文字色，只细一档——对比页上是最淡的，但它说的是用户该知道的事，不许用最淡的文字。
- 卡片第一次出现时的先后（开场之后依次浮上来）跨着分区数，不是每个分区各数各的。

### 外部项目

在所有组件的后面单独一区，小标题后面写「只给链接，不安装」。**不是卡片，没有勾选框**：两栏的列表，每项是名字（粗体，后面一个 ↗）、完整的说明、最淡的小字写出整条网址，项与项之间一条线。名字是链接，在新标签页打开，不带来源信息；鼠标移上去加下划线。带推荐标记的，名字后面跟一个「推荐」的标记（和卡片上的同一个画法）。

用途下只有外部项目时没有组件的分区，顶上那一条下面直接是这一区。

### 已选（右栏）

标题是「已选」和数量（数量用前景色、600）。**已选为空时**标题下面一条线，一句次要文字色的「还没有选任何条目」；「去汇总」不可点。

每行：名字（500），下面一行最淡的小字是类型，后面可以跟「3 个 skill 里挑了 2 个」（和类型之间一个「·」，这句话随画面状态来）「要填 key」（留意色）「key 已填」（就绪色）；行的右边是去掉它的 ×（一个 24px 见方、没有边的按钮，读屏软件念「去掉 <名字>」）。行与行之间一条线，**照勾选的先后**排：新勾的落在最后。

最下面固定着两个按钮，上下排：主按钮「去汇总 →」，和次要的「完成」（点了安装器退出）。「完成」在对比页的这一栏里没有——见文末「实现时定下、维护者还没有看过的画法」。

这一轮不会装的条目**留在这里**——改了宿主或安装范围之后装不了的，和含多个 skill 而一个都没挑的第三方 Skill：名字划掉、退到次要文字色（不用最淡的：原因要读得清），下面那行小字换成原因（留意色，随画面状态来：装不了的和卡片上是同一句，没挑的是「一个 skill 都没挑，这一条不装」），标题旁边写「其中 N 项这次不会装」（留意色小字；工单 09 从「现在装不了」改的，因为没挑的那一种不是装不了）。已选里一个会装的都没有时「去汇总」不可点，和已选为空一样。

### 填 key

盖在上面的对话框，底下压暗。每个要 key 的 MCP 一段（名字是等宽粗体，后面最淡的小字是它所在的那个用途的名字），每个变量：

- 变量名（等宽粗体）和「必填」或「可选」的线框标记。
- 一句说明，接着「去申请」和网址（链接，在新标签页打开；后面的 ↗ 跟着网址的末尾，不单独掉到下一行）。
- 输入框：**不显示输入的内容**，里面的提示是「粘贴 key，输入不显示」。必填的没填时下面一行留意色的字「不填就不装 <MCP>，其余照常装」；可选的是最淡的「留空则不设置这个变量」。
- 填过的不再是输入框，是一行「✓ 已填」（就绪色）和右边的「换一个」。**不显示值，也不显示长度。**

### 汇总

从右边滑出的面板，宽约 720px（至少给底下留 280px），底下压暗。

- 标题「将安装 N 项」，下面一句：开始之前安装器会再查一遍这台机器上的状态，状态变了就给看新的汇总。
- 每个要装的条目一段（名字是等宽粗体，后面最淡的小字是类型和要装的版本，中间一个「·」），段与段之间一条线，最后一段下面没有线。**段数要和标题里的 N 对得上**：第三方 Skill 一个条目一段，段名是条目的名字，后面只有类型、没有版本（装的是作者当时的最新版）；里面每个要装的 skill 一小组（skill 的名字，等宽、600，下面是它在各个宿主下的行；只有一组、名字又和条目相同时不重复写）。段里每个宿主一行：宿主、操作（新装；覆盖是留意色粗体）、位置（等宽），位置下面一行小字是备注（`1.0.0 → 1.0.1`、重装、非本工具安装、已有同名目录、已配置先移除再添加）。工具没有宿主，只写「执行安装命令」。
- **要逐项决定的覆盖就在那一行下面**：一条留意底色的横条，一个勾选框和「覆盖它」；没勾时后面写「没勾：这一项跳过，保持原样」（前景色，不用最淡的）。缺省不勾；**每次进汇总都从不勾起**。
- 一行三栏：宿主（次要文字色，96px）、操作（72px，英文的 overwrite 也放得下）、位置，三栏的字照基线对齐（位置是等宽字，不照基线会比旁边高出两像素）。两栏的宽是定死的，各段的位置才上下对得齐。备注用次要文字色——它说的是这一项会怎样，不用最淡的文字。
- **收到新的一份汇总时**（确认的时候对不上，没有装）：各段的上面多一条留意底色的话，行首是留意色粗体的「注意」。
- 按 Esc 等于「返回修改」。
- 最后是一个小标题「注意」，下面每条提醒一行；行首不再重复「注意」两个字。提醒的话和终端界面是同一份，只少「key 以占位符显示」那一条（见下）。
- 面板底部固定着两个按钮：「返回修改」（次要）和「开始安装」（主按钮）。

**汇总里不列将执行的命令**（维护者 2026-10-11 定的：「这个用户根本不关心，所以不需要展示给他看」）。随之没有的还有「key 以占位符显示」那一条提醒——它说的是命令里的占位符。终端界面照旧列出每一条命令，那边没有变。

### 安装中与结果

同一个面板的位置。

- **安装中**：标题「正在安装」和「7 / 17」（装完了几项、一共几项，次要文字色、靠右）；一条 6px 高的进度条（前景色）；下面每一项在每个宿主下一行：符号、名字（等宽）、宿主、结果的词加原因，行与行之间一条线。底部一句提醒和不可点的「完成」。提醒现在只有「装完之前请不要关掉终端」；「关掉这一页这一批也会装完，结果打在终端里」那半句等工单 11 做了那件事再加。
- 正在向 GitHub 查询时，各行的最上面多一行：小圆环和「正在查询 skill 的文件列表…」。
- **结果**：标题「结果」；三格合计（成功、失败、跳过，各是一个线框的格子，数字 26px；**有失败的时候**失败的数字是失败色）；同样的行；有没装上的才有「下一步」一段；底部「继续挑选」（次要）和「完成」（主按钮）。
- 原因放不下就折行（英文的原因常是两行），名字、宿主留在第一行。

| 行的状态 | 符号 | 词 |
|----------|------|-----|
| 装好了 | 就绪色的 `✓` | 就绪色的「已安装」「已配置」，后面前景色的版本 |
| 没装上 | 失败色的 `✗` | 失败色粗体的「失败」，后面前景色的原因 |
| 跳过 | 最淡的 `–` | 前景色的「跳过」加原因 |
| 正在装 | 转动的小圆环（前景色）；系统开了「减少动态效果」时不转 | 终端界面进行中那一行的词加「…」：本仓库的 skill 是「正在下载…」 |
| 等待 | 最淡的 `·` | 最淡的「等待」；名字不加粗 |

成功、失败、跳过的符号和词照 [界面设计](./ui-design.md) 的「符号的含义」，两套界面一个说法。等待的 `·` 和正在装的小圆环是网页界面自己的：终端界面里没有「等待」这一种行，`·` 在那边是分隔符。

### 出错

出错说明和终端界面是同一份话、同一个结构（[界面设计](./ui-design.md) 的「出错」）：一个标题，下面「原因」「下一步」各一行。在网页界面里它是面板里的一块，不另开对话框：

- 标题是失败色粗体，以「出错：」开头；「原因」「下一步」两个词用最淡的文字，后面的话用前景色。**出错说明不许用最淡的文字写。**
- 出在一批里的某一步（比如向 GitHub 查询失败）：放在结果的合计和各行之间，是一个线框的块；受它影响的条目不出现在行里，其余照常。出问题的网址或路径写在原因下面，等宽。只装本仓库的 skill 而查询失败时，合计是三个 0、一行都没有。
- 出在整个网页界面上（安装器已退出、连接断了、口令不对）：整个画面换成一句说明，上面没有还能点的操作。**它们是结束画面，不照上面出错那一块的画法**（不以「出错：」开头，没有「原因」「下一步」两行）：画法见文末的「结束画面」。

这一节是照终端界面的出错画法推的，对比页上没有画，维护者没有看过。工单 07 做出了一批里出错的那一种（预览里的「结果 · 向 GitHub 查询失败」）。

## 开场动画

网页界面第一次打开时先播一段，约两秒半，然后才是挑选的画面（维护者 2026-10-11 要的；演法是他在对比页上选的那一种）：

| 时刻 | 画面 |
|------|------|
| 0.15 – 0.95 秒 | 黑底，正中偏左一行等宽字 `$ npx oxy-tools`，像有人在敲，一个字一个字出来，行尾一个闪的光标 |
| 1.05 秒起 | 大标志一行行打出来，五行，每行隔 0.11 秒，行里从左到右略有先后 |
| 1.75 秒 | 标志下面淡淡的一行 `oxy-tools 0.3.0` |
| 2.2 – 2.6 秒 | 整个开场淡出 |
| 2.3 秒起 | 底下的画面已经在了：卡片一张张浮上来（从下面 12px 处、由透明到实，0.4 秒），每张隔 50 毫秒，最多错开九张 |

规矩：

- **不拖慢网页界面本身**：开场是盖在上面的一层，底下照常连上安装器、拿画面状态。开场播完时底下还没准备好，就接着等，不让用户对着空白。
- **只在这次运行第一次打开时播**。刷新、断开重连、再开一个标签页都不重播（播过没有记在安装器那边，见 [网页界面的契约](./web-ui-contract.md)）。
- **可以跳过**：点一下或按任意键，立刻进去——盖着的那一层当场收掉，卡片不再做浮上来的动作，所有东西直接到位。跳过的那一下点击不会落到底下的页面上。
- 开场播着的时候换了一张列表，新出现的卡片不做浮上来的动作。
- 开场那一层是纯装饰，读屏软件直接读底下的页面。
- **收掉那一层靠它自己淡出完的那一下（`animationend`），不另设定时器**；时刻全在样式里（`style.css` 的「开场动画」）。这样把动画定格、放慢来看的时候，收场也跟着停，不会画面还定着格、那一层却到点没了。
- 还没连上安装器时的那一句「正在连接安装器…」等 0.4 秒还没连上才显出来（通常一闪而过，不让它闪）；系统开了「减少动态效果」时直接显示。
- **系统开了「减少动态效果」时不播**，卡片也不做浮上来的动作，所有东西直接到位。
- 开场里的大标志是单色的（白），和左上角的那个一样。
- 除了开场、卡片第一次浮上来、进行中的小圆环，网页界面里**没有别的装饰性动画**。「正在连接安装器…」晚 0.4 秒显出来（上面「规矩」的最后一条）不算装饰：它是为了不让那一句闪一下。

「只播一次」「可以跳过」「减少动态效果时不播」这三条是定方向时替维护者假定的，说给他听过，他没有反对，也没有逐条确认。

## 放不下时的退路

目标视口是桌面 1280×800；1024×768 不能坏（没有横向滚动条，「去汇总」看得见）。不为手机和平板设计。

| 情形 | 怎么办 |
|------|--------|
| 窗口不足 1100px | 左栏 196px、右栏 256px；卡片仍是两张一排；第三方 Skill 里的清单由三栏变两栏 |
| 用途名太长（英文界面常见） | 折成两行，条目数留在第一行右边 |
| 宿主和安装范围在顶上那一条放不下 | 折到标题的下一行，仍在贴着不动的那一条里。连两样并排一行都放不下时（1024 宽、两个宿主、英文界面：Install into which AI Agents 很长）才拆开，宿主一行、安装范围一行——选定的对比页上也是这样 |
| 两个宿主的状态在卡片底部放不下 | 折成两行，一个宿主一行 |
| 名字、路径、网址很长 | 在任意位置断开；从不截断 |
| 已选很多 | 右栏里的列表自己滚动；数量和「去汇总」不动 |
| 条目很多 | 中间一栏往下滚；不分页，不折叠 |

## 键盘与焦点

全部操作可以只用键盘完成。焦点是一圈 2px 的前景色描边，离元素 2px，深浅色下都看得见。勾选框、分段控件、按钮都是真正的表单控件，不是只会响应点击的色块。

## 网页界面的预览

观感不靠自动化测试把关：页面本身不写自动化测试，经入口的测试断不到版式（见 [网页界面的契约](./web-ui-contract.md) 的「Tests Required」）。把关的是网页界面的预览加视觉评审，和终端界面的做法一样（[界面设计](./ui-design.md) 的「界面预览页」）。

```bash
cd cli && npm run preview:web   # 输出：N 格 → …/cli/.preview/web/index.html
```

`cli/scripts/preview-web.ts` 经安装器入口按预设场景把安装器驱动到要看的状态，让**本机装着的 Chrome** 打开它的网页界面，把**真实的页面**拍下来：每个场景一格，标题前面是序号、后面是窗口的大小，下面左为深色、右为浅色（图下写着是哪一份、哪个文件），点开是原图；每格下面折着这一格页面上的文字。直接用浏览器打开 `cli/.preview/web/index.html` 看。它是生成物（一个 `index.html` 加每格两张 `NN-dark.png`、`NN-light.png`），不提交，也不随 npm 包发布，不进 CI。

预览**从不碰真实的主目录和网络，不真的执行命令**：目录是样例，主目录、项目目录、可执行路径都是临时目录，外部命令执行器一律拒绝，链接打开器只记下网址；Chrome 用的是一份临时的用户数据目录，除了本机回环地址哪里都连不上（见下面「用什么驱动浏览器」）。它和终端界面的预览（`npm run preview`）是两条命令，各生成各的，互不影响。

怎么用：

1. **改了页面就生成并看一遍**（样式、版式、页面自己的文字、画面状态里多了一块），对照本文件；**加了一种状态就加场景**。
2. 每格拍 1280×800，深色、浅色各一份。要看 1024×768 下坏没坏，给同一个场景再写一条、带上 `viewport: NARROW`；要看一张比窗口高的列表从头到尾，带上 `whole: true`（窗口拉到列表那么高）。
3. **样例里要有一条长名字、一条长说明、一条长链接**，并且就在条目最多的那张列表里：折行、卡片变高只有这时才看得到。现在是「文档处理」，二十多条，四种组件加外部项目都有；长说明要落在一张**卡片**上（现在是 docling，四五行，它旁边还有一张），只落在外部项目上的话卡片变高、同一排一样高就没被考到。
4. 中文、英文各拍：英文的词长，放不下的地方先在英文里出事（1024 宽、两个宿主、英文是最挤的一格）。
5. **带 key 的场景生成之后，在 `cli/.preview/web/index.html` 里搜假装填的那个值，应当一处都没有**，图上也看一眼。带 key 的场景到工单 10 才有；这条规矩和终端界面的预览是同一条。**现在这一搜只搜得到页面上看得见的文字**（每格存的是 `document.body.innerText`）：输入框里的值、元素的属性不在里面。工单 10 加带 key 的场景时要把这一搜补实——把表单控件的值和页面的 HTML 一并存进去，或者让脚本自己查——不能拿现在这一搜零命中当作 key 没有漏。
6. 生成物不提交。要留给评审看的那几格，拷到任务目录的 `screenshots/` 里。

### 场景怎么写

场景表在 `cli/scripts/preview-web.ts`，一条是一格：

| 字段 | 说的是什么 |
|------|------------|
| `title`、`note` | 这一格的标题，和它要看什么 |
| `lang` | 页面的语言，缺省中文；`'en'` 是英文（安装器带着 `--lang` 起，浏览器的语言也跟着换——口令不对的画面没有画面状态，照浏览器的语言说） |
| `catalog` | 目录，缺省是那份最坏的样例（`worst`） |
| `onPath`、`home`、`links`、`project` | 这台机器事先的样子：可执行路径上有哪些命令（有 `claude`、`codex` 就是「检测到了」）、主目录和项目目录里有什么。缺省是 `LIVED_IN`：两个宿主，各种状态都有 |
| `drive` | 打开浏览器**之前**，扮演浏览器给安装器发意图，把它驱动到要看的状态（用的是测试架子的 `cli/test/browser.ts`）。状态在安装器这边，真实的页面一连上看到的就是它。`toPurpose('documents')` 是换到那个用途的列表上 |
| `intro` | 开场动画。数字是定格在第几毫秒；`'skipped'` 是播着的时候按了一下键；`'reduced-motion'` 是系统开了「减少动态效果」，不播。不给就是这次运行里已经播过了（脚本先替页面发了 `intro-seen`），页面直接出现 |
| `ending` | 页面画出来之后让它走到哪种结束画面：`'finished'`（发「完成」）、`'exited'`（安装器退出，页面重连不上）、`'denied'`（拿着不对的口令打开） |
| `tabs` | 页面画出来之后按几下 Tab：看键盘焦点落在哪、看不看得见 |
| `reveal` | 页面画出来之后把名字是它的那张卡片滚到窗口中间：要看的东西在一张长列表的下半截时用（不可选的卡片多半在） |
| `viewport`、`whole` | 见上面「怎么用」的第 2 条 |

- 「这台机器事先的样子」的四个字段，场景给了哪一个就**整个换掉** `LIVED_IN` 的那一个，不是往里添：只给 `onPath: ['claude', 'pandoc']` 的场景，主目录仍是 `LIVED_IN` 的。
- **要到一个新状态，先想它在哪一边**。在安装器这边的（看哪张列表，以后的勾选、宿主、安装范围、填的 key、汇总）用 `drive` 发意图；只在页面上有的（开场动画、键盘焦点、结束画面）才给场景加字段、在脚本里对着真实的页面做。
- 样例条目和「这台机器事先的样子」怎么布置，两份预览共用，在 `cli/scripts/preview-samples.ts`；只有一份预览用的样例留在那份预览自己的脚本里。
- 开场动画只在一次运行第一次打开时播，所以每个场景各起一个安装器、各开一个标签页。
- 页面的静态文件由脚本自己先打一遍（`buildWeb`），不用另外 `npm run build:web`。

### 用什么驱动浏览器

**本机装着的 Chrome（或 Chromium、Edge），经它自带的调试协议**；`cli/scripts/chrome.ts` 是那一小层：起一个没有窗口的 Chrome，开网址、定窗口大小、定系统的样子（深浅色、减少动态效果）和语言、在页面里算一个式子、按键、截图。协议走启动时接上的两条管道，不开端口。**没有为它加任何依赖**（工单 05 定的，维护者没有逐条确认）。

没有选的：

| 没有选 | 为什么 |
|--------|--------|
| 加一个浏览器自动化的库当开发依赖（Playwright、Puppeteer） | 预览要的只有上面那几样，自己写是两百行上下的一个文件。库本身不带浏览器：要么仍然用本机的 Chrome，要么另下一两百 MB；CI 从不生成预览，却每次 `npm ci` 都要装它 |
| 本机全局的 `playwright-cli`（工单 04 截图用的） | 它不在 `package.json` 里，换一台机器就没有；它是另一个进程，场景表却要和安装器在同一个进程里（每格各起一个安装器），两边只能靠临时文件传话；它还在当前目录留 `.playwright-cli/` |

代价和限制：

- 开发机上要有 Chrome、Chromium 或 Edge。找不到时脚本说明并以 1 退出；装在别处就用环境变量 `OXY_TOOLS_CHROME` 给出可执行文件的路径（给了就只认它，那个路径上没有东西同样说明并以 1 退出）。
- 只在 macOS 的 Chrome 上跑过。Windows、Linux 上的安装位置是照常见的写的，**没有实测**。
- 预览拍的是 Chrome 里的样子；别的浏览器（Safari、Firefox）里的样子它看不到。
- 某一格没拍成，整个生成就停下并以非零状态退出，报出是哪一格、为什么；不留半份 `index.html`。收场时（关标签页、等安装器退出）再出的错不报。Chrome 中途没了的话，要等两个 15 秒的超时才报出来。
- **图上各栏的滚动条是一直画着的**（内容比栏高时），占着十来像素的宽：没有窗口的 Chrome 就是这样，Windows 上、macOS 接了鼠标时也是这样；macOS 用触控板时它平时不显示。留着它是有意的：哪一栏冒出了横向滚动条，图上一眼看得见。
- Chrome 起来时带着这几样：没有窗口；用户数据目录是临时的（不碰真实的书签、登录、扩展）；不走系统的代理；回环地址以外的名字一律解析不到（`--host-resolver-rules`），所以页面万一向外发请求，在预览里是失败的，Chrome 自己的后台更新也发不出去；截图上一个点就是页面上的一个像素。

### 踩过的坑

| 现象 | 原因与办法 |
|------|------------|
| 截图底部把页面顶部又画了一遍，左下、右下的东西被切掉 | 改了窗口大小紧接着就截。脚本每次改完窗口、换完深浅色都等两帧再加一百来毫秒（`SETTLED`），并核对页面的宽高正好等于要的窗口 |
| 要某一时刻的定格 | `for (const a of document.getAnimations()) { a.pause(); a.currentTime = 毫秒 }`。开场的各段动画是同时开始的，同一个时刻对它们都成立 |
| 定格往回拨了一下，开场那一层没了 | 动画从「进行中」拨回「还没开始」也会发 `animationend`，页面把它当成淡出完了。**时间只许往前拨**：脚本发现页面已经播过了要定格的那一刻就报错，不往回拨 |
| 大标志放大了，方块之间有细缝 | 宽不是 25 的整数倍，方块落不到整像素上。见「大标志」 |
| 换了深浅色，「减少动态效果」的模拟没了 | Chrome 的 `Emulation.setEmulatedMedia` 每次都是整份替换：只给深浅色，上一次给的别的几样就清掉了。`chrome.ts` 的 `system(scheme, reducedMotion)` 因此两样一起给 |
| 口令不对的那一格，中英文跟着开发机的浏览器变 | 这个画面没有画面状态，照 `navigator.language` 说。脚本用 `Emulation.setUserAgentOverride` 的 `acceptLanguage` 把浏览器的语言定成场景的语言 |
| 脚本出错时没人接的拒绝让进程当场退出，临时目录和 Chrome 都留下了 | 同时等两样（`Page.navigate` 的答复和加载完的事件）时用 `Promise.all`，哪一样先出错都有人接；每格开了什么都记进收场的清单，出错也照相反的先后收掉 |
| 选中的卡片里的字比旁边的卡片偏右两像素 | 卡片选中用的类名和右栏已选那一块撞了（都叫 `.picked`），卡片吃到了右栏的内边距。样式是一整份，类名全页共用：卡片的选中叫 `.selected`，右栏那一块叫 `.picked`。起新类名先在 `style.css` 里搜一遍 |
| 装到项目时标题下面的目录掉到了那句话的下一行（工单 08） | 同一个坑：那一行起的类名 `.where` 和汇总面板里位置那一栏的 `.where`（网格布局）撞了。改叫 `.directory` |
| 勾了勾选框，安装器没照办，框却留着勾 | 浏览器点一下就把框勾上了，而画面状态没变时 Preact 不会把它改回去。卡片和「覆盖它」的勾选框因此在点的那一下先把自己改回画面状态里的样子，再发意图：勾没勾上只照画面状态 |
| 重新构建了页面，预览里还是旧的 | 页面的静态文件是起本机的网页时读进内存的。`npm run preview:web` 每次自己先打一遍，不会遇到；手工起安装器看页面时要重起 |
| `reveal` 指定的卡片没滚到窗口中间，图上还是列表的顶部（工单 09 发现，之前「有不可选的条目」那几格也是这样） | 页面刚画出来时「换了一张列表就回到顶部」那个效果（`browse.tsx` 里的 `scrollTo(0, 0)`）还没跑，紧接着滚会被它拨回去。脚本在滚之前先等两帧 |

预览里没有的、要看就在真实的浏览器里另外看的：一路按 Tab 焦点依次落在哪、开场从出现到收掉多久、按键和点一下是不是立刻收掉、链接是不是在新标签页打开、鼠标移上去的样子。预览只把画面状态画出来拍下，**不点页面上的任何东西**——页面上哪个按钮没接上意图，它查不出来。

**加了会点的东西，就在真实的浏览器里点一遍**（工单 07 这样核对过：点卡片的名字勾上、去汇总、勾「覆盖它」、开始安装、继续挑选、Esc 返回、× 去掉、完成）：写一个一次性的脚本放在仓库外面的临时目录里，照预览脚本的办法起安装器和 Chrome（`chrome.ts`、`preview-samples.ts` 的 `stageWorld`），用 `tab.evaluate` 在页面里 `click()`，等页面上出现该有的东西，再把读到的字打出来看。脚本不提交。等页面变的时候**等的是安装器推来的那一份画出来的东西**（比如那句「没勾…」不见了），不是勾选框自己的 `checked`。
