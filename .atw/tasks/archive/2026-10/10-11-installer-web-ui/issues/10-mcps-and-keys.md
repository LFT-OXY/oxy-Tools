# 10 — 在网页界面里装 MCP、填 key

**What to build:** MCP 可以和别的组件一起勾选、一起装。要 key 的 MCP 在页面上填：每个变量写明是做什么用的、必填还是可选、去哪申请，输入框不显示内容；同一次运行里填过的不用再填。汇总里看得到各种提醒（不列将执行的命令）。填的 key 不出现在页面的任何别处、终端、网址和任何答复里。装到项目时 Codex 的 MCP 不可选并写明只能装到全局。

**Blocked by:** 08
**Status:** ready-for-agent
**Impl:** done

- [x] 先改规范：网页界面的契约补上填 key 的意图和「填了没有」的画面状态；安装 MCP 的规范里「key 的值不许去的地方」加上网页界面的几处（网址、答复、画面状态、浏览器的记忆）。
- [x] 状态每个所选宿主一个（未配置、已配置、未知、不支持），写法不变；宿主的配置读不了时的提示页面上也有。（MCP 那一区的 `notices`，和终端界面列表上方那两行是同一份话）
- [x] 安装范围选了项目，而所选的宿主里支持它的都只能把 MCP 装到全局：不可选，原因是「只能装到全局」；有项目范围配置的宿主装进项目目录里的那一份。（只装得了一部分时仍可选，那一区上方写明原因）
- [x] 勾了要 key 的 MCP：页面上逐个变量给出说明、必填还是可选、申请链接（新标签页打开）。输入框不显示内容，不让浏览器记住或自动填。（输入框是画成圆点的文字框，不是密码框：密码框填完浏览器会问要不要保存。取舍在契约的 Design Decision 表，维护者没有表过态）
- [x] key 的值只经请求的正文传给安装器；之后的画面状态里只有「填了没有」。同一次运行里填过的写明「已填」，可以换一个；继续挑选下一批时不用再填。（意图 `key`，一个变量一个；填 key 是去汇总路上的一步，`review` 两次）
- [x] 必填的没填：页面写明这个 MCP 不会装，汇总里不算它，其余照常；可选的没填就不带。（全是这样的时汇总是「将安装 0 项」，确认后结果里是跳过）
- [x] 汇总里不列将执行的命令，画面状态里也没有（维护者 2026-10-11 定的）；执行的命令和终端界面一样。提醒齐全（「key 以占位符显示」那一条随命令一起没有了）：key 会以明文写进项目里的哪个文件（说变量名和文件，不说值）、哪个宿主要另行批准才启用、哪个宿主会当场打开浏览器登录、哪个 MCP 因为缺 key 不装。（MCP 的行没有位置；登录的那条提醒里有事后要敲的 `codex mcp login`，它不是将执行的命令）
- [x] 执行在第三方 Skill 之后；已配置的、状态未知的怎么装不变；失败的写法不变，原因里没有 key 的值。（没配置上的 MCP 在结果的「下一步」里另说一句 `afterMcpFailures`：先移除再添加，不能说原有的东西没动）
