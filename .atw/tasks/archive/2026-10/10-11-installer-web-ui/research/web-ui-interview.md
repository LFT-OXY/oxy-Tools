# 网页界面：访谈结论（2026-10-11）

维护者看了终端界面「选择条目」的画面（用途「上下文、记忆与 Token 优化」，9 行里 7 行是外部项目，说明都被截断），觉得用户看不过来，提出改成在浏览器里操作。三轮访谈定下了下面这些；决定本身记在 `docs/adr/0004-web-ui-by-default-terminal-ui-as-fallback.md`，两个新术语记在 `GLOSSARY.md` 的「界面」一节。

## 维护者定下的

| # | 决定 |
|---|------|
| 1 | 做本机的网页界面。没有选「只改终端界面的排版」和「公开的目录网站」 |
| 2 | 终端界面保留：打不开浏览器的机器（远程连接、没有桌面的虚拟机）要照顾，网页界面是多一种方式，不是替换 |
| 3 | 目标只是让正在安装的人挑得舒服，不做别人不装也能逛的公开展示页 |
| 4 | 缺省打开网页界面。终端里留一行：已在浏览器打开、网址、按哪个键改用终端界面。认出远程连接或没有桌面时自动用终端界面；另有启动参数强制用终端界面（访谈里举的例子是 `--terminal`，名字没有定死） |
| 5 | 挑选、汇总、确认、安装进度、结果全部在网页界面里，中途不切回终端。只有工具的安装命令仍在终端里跑，网页界面提示去看终端 |
| 6 | 一页到底，不照搬终端界面的逐步提问：用途、条目、「装进哪些宿主」「安装范围」都在同一页上随时能改，已选的一直看得见；可以跨用途一起挑，一次确认、一次装完。两套界面的行为因此不一样，终端界面仍是一次一个用途 |
| 7 | 终端界面这次原样不动，「把外部项目从勾选表里分出去」不做 |
| 8 | key 在网页界面里填：输入框不显示内容，只留在内存里交给安装动作，不存进浏览器，不写任何文件。维护者知道浏览器扩展理论上读得到页面里的输入，接受这个风险 |
| 9 | 退出：装完后页面不关，状态刷新，可以接着挑；页面上有「完成」按钮，点了安装器才退出。直接关掉页面，安装器等几秒（区分刷新）后自己退出。安装中关掉页面，把这一批装完，结果打在终端里。终端按 Ctrl+C，安装器退出，页面显示安装器已退出 |
| 10 | 语言：用网页界面时终端不问语言；页面先按系统语言显示，页面上有中文 / English 的切换；`--lang` 仍然有效 |
| 11 | 网页事先做好、打包在 npm 包里一起发布，不增加使用者运行时要下载的东西。页面内部用什么技术写，交给写规格时定，规格里写明选了什么和理由 |

不是选择题、直接作为硬性要求的一条：本机的这个网页能替用户执行安装命令，所以必须拒绝别的网站和别的机器发来的请求。

## 从代码里查到的

- 提问的唯一出口是 `Prompter`（`cli/src/prompter.ts`），样式在呈现层（`cli/src/ui.ts`），画面怎么走在 `cli/src/flow.ts`。`flow.ts` 的 `planEntries` 把「逐步提问」和「把勾选的条目算成要装的每一项」（`Job`、`ThirdPartyJob`、`McpJob`、`ToolJob`）写在同一个循环里，`runJobs` 经 `ui.installation` 报进度——网页界面要用到后两样，而不走前一样。
- 「用默认浏览器打开一个网址」已经有了，现在没有被调用：`LinkOpener`（`cli/src/installer.ts` 第 34–35 行），实现在 `cli/src/open-link.ts`，由 `cli/src/bin.ts` 第 42 行传入。打不开时它以拒绝告终（命令不存在，或很快以非零状态结束）。
- 标准输入或标准输出不是终端时，安装器现在直接拒绝运行（`cli/src/installer.ts` 第 88 行）。
- 启动参数现在只认 `-h`、`-v`、`--lang`（`cli/src/installer.ts` 的 `parseArguments`）。
- 工具的安装命令经 shell 执行，输入输出直接接在用户的终端上（`cli/src/installer.ts` 第 15–21 行，`cli/src/install-tool.ts` 第 33 行），搬不进网页。目录里现在一个工具都没有。宿主命令和 skills CLI 的输出都不上屏，进度可以由网页界面显示。
- key 现在只留在内存里的 `Session.keys`（`cli/src/flow.ts` 第 49–53 行），不进呈现层，不写文件。
- `cli/package.json`：6 个运行时依赖，只用 `tsc` 构建，发布的只有 `dist`，要求 Node `^22.13.0 || >=23.5.0`。`tsc` 不会把 HTML、CSS 这类文件带进 `dist`。
- ADR-0001 的三条规矩仍然管着：网页界面的全部文件要放在 `cli/` 里，从 `cli/` 发布。
- 目录规模（2026-10-11）：本仓库 skill 12、第三方 Skill 23、MCP 11、工具 0、外部项目 64，共 110 条；条目最多的用途有 20 条。

## 留给写规格和切工单时定的

这些不是还没问维护者的问题，是访谈里说好交给后面的事：

- 页面长什么样：照以往定新画面的做法，先出几种并排的样子给维护者选，选定后再实现。
- 页面用什么技术写（见上表第 11 条）。
- 怎么认出「这台机器打不开浏览器」；访谈里说的是多数情况认得出，没有实测过。
- 网页界面的观感怎么把关：现在的界面预览页只拍终端界面。
- 「不是本工具装的」目录逐项询问是否覆盖，在一页到底的页面上怎么问。
- 同一台机器上同时开着两个安装器时怎么办。
