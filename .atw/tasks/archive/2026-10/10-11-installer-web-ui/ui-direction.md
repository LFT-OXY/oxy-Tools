# 网页界面的视觉方向

> 工单 01 的结论。维护者 2026-10-11 在一次性的对比页上看了四轮、十三个方向，选定第四轮的 **J「利落」**。
> 对比页和它的生成脚本在同目录的 `prototype/`，截图在 `screenshots/`，两处都不提交（各有一份只在本机生效的忽略规则）；结论以本文件、`prd.md` 的「UI and Design」和 `.atw/spec/cli/web-ui-design.md` 为准。
> 用词：正文说「宿主」，界面文案里它显示为「AI Agent」；「用途」「网页界面」等照 `GLOSSARY.md`。引号里维护者的原话不改。

## 选定的方向：J「利落」

**北极星**：一切都退到最细的线和最准的字后面，只剩你要看的东西。参照的是 Linear、Vercel 这一类当下的开发工具。

| 项 | 选定的 |
|----|--------|
| 版面 | 三栏：左边用途（一竖列，带条目数），中间条目，右边已选 |
| 条目 | 卡片，两张一排；边角微圆（8px），线极细；右上角一个小方框勾选 |
| 选中 | 卡片描一圈前景色的边、底色抬一档；不用彩色 |
| 已选 | 右栏一直在，名字全列出，可逐个去掉；「去汇总」固定在右栏底部 |
| 宿主与安装范围 | 中间一栏顶上，和用途的标题同一条；滚动时贴在顶上 |
| 填 key | 盖在上面的对话框，每个 MCP 一段 |
| 汇总、安装中、结果 | 从右边滑出的面板，盖住右侧大半；列表留在底下、压暗 |
| 强调色 | **没有彩色**：按钮和选中用黑或白（跟随深浅色）；彩色只留给状态的词（绿、黄、红） |
| 大标志 | **单色**：深色下是白的，浅色下是黑的。终端里的大标志不动，仍是粉到紫到蓝的渐变 |
| 主色调 | 深色与浅色都做，跟随系统；维护者没有说哪个是主打 |
| 开场动画 | 第二轮 F 的演法：像在终端里敲下 `npx oxy-tools`，大标志一行行打出来，然后退场、卡片依次浮上来；全程约两秒半 |

## 维护者说过的话

按时间先后，原话：

1. 第一轮（A 货架、B 账本、C 橱窗）：「这3种我都不喜欢，都不满意。我可能更偏向喜欢C的版本，但它的多选或者背景颜色不是我太喜欢；我比较喜欢显示成卡片这类UI组件。」并提出要开场动画：「在让用户选择之前，默认打开浏览器时，它就先开始进入一个动画效果，可能是两到三秒，然后再进入选择页面。」
2. 第二轮（D 夜场、E 白墙、F 极光）：顶上两排圆角的用途标签「用这种样式这样摆放的话太丑了」；「进场动画我喜欢F」；「所有的配色我都不喜欢，都是些什么紫色，很像AI做的样式」；「从布局，再到组件样式，都需要完全的重新设计」。
3. 第三轮（G 终端窗、H 目录册、I 机柜）：「这3种UI方向都很复古，我想要现代、流行一点的UI。」
4. 随后的三道选择题：风格把「Linear / Vercel」「Apple 官网」「Raycast / Arc」「Notion / 飞书」四种全勾了；强调色选「不要彩色，黑白灰」；大标志选「单色，跟着页面走」。
5. 第四轮（J 利落、K 便当、L 浮窗、M 文档）：「选J。最后汇总的时候，会显示将执行多少条命令。这个用户根本不关心，所以不需要展示给他看。」

**喜欢的**：卡片；终端敲命令式的开场；现代、流行的长相；黑白灰。
**不喜欢的**：紫色系和一眼像 AI 做的样式；顶上成排、自动换行的圆角标签；复古风（终端、印刷、机器面板）；汇总里列出将执行的命令。

## 没选的候选

| 轮 | 方向 | 是什么 | 交给维护者选时说的代价 | 为什么没选 |
|----|------|--------|------------------------|------------|
| 1 | A 货架 | 三栏，条目一行一条，右栏已选 | 右栏常占 340px；1024 宽时中间变窄，状态改排到说明下面；已选很多时右栏要滚动 | 维护者要卡片 |
| 1 | B 账本 | 单栏，等宽字的对齐表，底栏已选 | 三种里最密，最不「好看」；已选多了底栏变成两三行 | 同上；也最密 |
| 1 | C 橱窗 | 卡片墙，顶上圆角标签，底部浮着的托盘 | 卡片高矮参差；一屏只有四到六个条目；两个宿主的状态不好上下对比；托盘只放得下前四个名字；看汇总时看不到列表 | 最接近，但勾选的样子和淡紫的背景不喜欢 |
| 2 | D 夜场 | 中性黑，渐变描边的选中 | 同一排卡片一样高，说明短的底下空一大块 | 配色仍是紫色系，像 AI 做的；顶上的标签太丑 |
| 2 | E 白墙 | 暖白，无边框的浮卡片，右栏已选 | 右栏常占一块宽度；一屏看到的卡片最少 | 同上 |
| 2 | F 极光 | 顶上一点粉蓝的光，错落排的卡片 | 阅读顺序是先竖着看完一列再看下一列，不直觉 | 同上；**开场动画被留下** |
| 3 | G 终端窗 | 等宽字、反白的选中、`[x]` | 最「极客」，不熟悉终端的人可能觉得冷 | 复古 |
| 3 | H 目录册 | 纸色、宋体、朱红、编号的目录表 | 右栏常占一块宽度；顶上的目录表占三行高 | 复古 |
| 3 | I 机柜 | 灰面板、拨动开关、信号黄 | 说明短的模块底下会空；窄屏上已选的名字只看得到两三个 | 复古 |
| 4 | K 便当 | Apple / App Store 式的大圆角大格子 | 一屏只放得下三四张卡片，23 条要滚很久；已选超过四五个就看不全 | 没选 |
| 4 | L 浮窗 | Raycast / Arc 式的浮窗和窗底操作条 | 外圈留了一圈空，能用的地方略少；最容易显得花哨 | 没选 |
| 4 | M 文档 | Notion / 飞书式的一页文档，顶上一行已选的标签 | 最没个性；卡片一样高，说明短的底下会空 | 没选 |

第四轮没选的三个，维护者没有说原因。选定的 J 当时说的代价是：字最小、最冷；右栏常占一块宽度。

## 设计说明

供后面每一张改网页界面的工单照着做。数值、部件和每个画面的版式要点写在 `.atw/spec/cli/web-ui-design.md`，这里只写做判断要用的。

- **用户的任务**：刚运行了安装器的人，在一份 110 条的目录里挑出要装的，确认，装完。多数人只来这一次，不会学习界面。
- **内容与主动作**：内容是条目（名字、完整的说明、在每个宿主下的状态）；主动作只有一条线——勾选 → 去汇总 → 开始安装 → 完成。任何时候屏幕上只有一个实心的按钮，就是这条线上的下一步。
- **视觉关系**：
  - 名字是每张卡片里最重的字；说明退一档（次要文字色）；状态再退一档，只有状态的词带颜色。
  - 选中靠「描边 + 底色抬一档 + 勾」三样一起，不靠颜色。
  - 线只做一件事：分栏用线，卡片用线，同一处不叠两条。
  - 实心（前景色的底、背景色的字）只给两样东西：主按钮、「推荐」标记和已勾的勾选框。
- **关键状态**：有宿主 / 一个都没有；一个宿主 / 两个宿主；全局 / 项目；有不可选的条目；已选为空 / 几个 / 里面有现在装不了的；第三方 Skill 里挑 skill；key 没填、已填、必填的没填；汇总里有要逐项决定的覆盖；安装中的等待、正在装、工具在终端里装；结果里全部装好、有没装上的、有跳过的；结束的三种（已完成、安装器已退出、已改用终端界面）和口令不对。
- **设备**：桌面 1280×800 为主，1024×768 不能坏；不为手机和平板设计。跟随系统的深浅色。全部操作可以只用键盘。
- **验收重点**：
  - 一个 20 多条的用途里每条说明都完整，没有一处「…」。
  - 已选的数量、名字和「去汇总」一直在屏幕上。
  - 外部项目没有勾选框，和组件一眼分得开。
  - 不可选的条目上直接看得到原因。
  - 彩色只有说状态的那三种（绿、黄、红）；没有紫色。
  - 汇总里没有将执行的命令。
  - 开场动画约两秒半，可以跳过，不拖慢网页界面本身。

## 对比页上有、正式实现时要改掉的

- 1024 宽时左上角的「oxy-tools」折成了两行：产品名不许折行。
- 1280 宽、两个宿主时，「装到哪里」单独掉到了第二行：宿主和安装范围要么都和标题同一行，要么两样一起折下去。
- 汇总里 taste-skill 的三个 skill 各成一段、不写属于哪个条目，标题却是「将安装 7 项」：要归成一段。
- 汇总里小标题和每一行行首都写了「注意」：行首的不要。
- 汇总里多出一条「docling 的安装命令在终端里执行，到时请看终端」的提醒：这条不在需求里，终端界面也没有，是画对比页时自己加的，不做。
- 挑 skill 的清单里，名字长的那一行把后面的「已装」挤成了竖排；填 key 里网址后面的 ↗ 单独掉到了下一行：状态的词和这个箭头都不许这样折。
- 对比页上的画面是静态的：按钮点了没反应，链接不跳转，开场动画每次打开都播。
- 「工具」一段的 docling 和 officecli 是借界面预览页的样例（真实目录里现在一个工具都没有），各条目的状态是为了排版摆的。
