# 01 — 视觉方向：终端界面设计稿

**What to build:** 在写任何安装器代码之前，维护者在浏览器里看到安装器每个画面在终端里会是什么样子，并从几种风格里选定一种。之后所有涉及界面的工单都按选定的方向做。

这张工单需要维护者在场：风格由维护者选定，选定之前不算完成。设计稿只用来做决定，用 `atw-prototype` 的界面流程完成，选定后不再维护。

**Blocked by:** None
**Status:** ready-for-agent
**Impl:** done

- [x] 先选定安装器要用的现成命令行交互库（需支持多选、隐藏输入、Windows 终端），并写明选它的理由；设计稿里只画这个库在真实终端里做得出来的效果。
- [x] 风格只在配色、符号、间距、边框、标题区这些静态元素上发挥；不为了好看而自写交互控件，不做全屏界面。
- [x] 一个离线可打开的 HTML 页面，并排给出三种明显不同的风格方向，每种都按终端的样子（等宽字体、终端窗口）呈现。
- [x] 每种方向都覆盖 `prd.md` 的 UI and Design 一节列出的画面：加载、主菜单、选择宿主、选择条目（含 skill 的四种状态、MCP 的三种状态、不可选条目）、填写 key、汇总确认（含覆盖项和带占位符的命令）、执行与结果（含成功与失败并存）、应用项目详情，以及四种出错提示。
- [x] 每种方向都同时给出深色背景和浅色背景两种终端下的效果，两种下文字都清晰可读。
- [x] 颜色用终端的标准命名色来表达，并说明每种颜色在界面里的含义；每种状态在不显示颜色时仍能靠文字或符号区分。
- [x] 中文和英文界面各至少展示一个画面，确认中文字符宽度不会让对齐错位。
- [x] 维护者选定一个方向；结论写进任务目录的 `ui-direction.md`：选了哪个、为什么、喜欢与不喜欢的点、颜色与符号的含义表、各画面的版式要点、选定的交互库。
- [x] `prd.md` 的 UI and Design 一节更新为指向 `ui-direction.md` 的摘要；`ui-direction.md` 已登记进 `check.jsonl`，供后续工单的视觉评审对照。
- [x] 设计稿和对比页放在任务目录内，不进 `cli/`，不随 npm 包发布。
