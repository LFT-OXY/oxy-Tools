# 04 — 目录校验命令与 CI

**What to build:** 维护者在提交前用一条命令校验仓库里真实的目录数据，推送后 CI 再校验一次，并在三个操作系统上跑安装器的测试。这样不会推上一份安装器读不了的目录，Windows 上的行为也有人看着。

**Blocked by:** 02
**Status:** ready-for-agent
**Impl:** done

- [x] 提供一条目录校验命令，用安装器自己的校验逻辑检查仓库里的 `index.json` 和 `catalog.json`；维护者和 CI 用的是同一条命令。命令是在 `cli/` 下运行 `npm run validate-catalog -- ..`，仅供开发、不随 npm 包发布；目录由参数给出，不写死（实现时定）。
- [x] 对仓库当前的目录数据，命令输出明确的通过信息并以零状态退出。`catalog.json` 里安装器还不读内容的条目（MCP、工具、应用项目，各自的工单落地前）不算失败，但会说明有几条未校验（实现时定，维护者尚未确认）。
- [x] 对一份写坏的样例，命令指明是哪一条、哪个字段出了问题，并以非零状态退出。
- [x] 校验命令有测试，覆盖通过和不通过两种情况。
- [x] CI 在 macOS、Linux、Windows 上运行安装器的全部测试。每个系统各跑 Node 22.13（包声明支持的最低版本）和 24 两个版本，另有一个作业跑类型检查（实现时补充，维护者尚未确认）。工作流要推送后才会第一次运行，Windows 上的结果届时才知道。
- [x] 目录文件有改动时，CI 运行目录校验。`cli/` 有改动时也跑，因为校验规则在 `cli/` 里（实现时定）。
- [x] CI 的工作范围限定在 `cli/` 和两个目录文件，不运行 `skills/` 下上游整包自带的测试。检出时就只取 `cli/` 和仓库根的文件。
