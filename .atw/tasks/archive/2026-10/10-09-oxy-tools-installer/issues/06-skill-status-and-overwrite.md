# 06 — skill 的状态与覆盖

**What to build:** 用户在列表里一眼看出每个 skill 在每个宿主下的现状，重装即可更新；而用户自己手动放置的同名目录不会被悄悄替换。

**Blocked by:** 05
**Status:** ready-for-agent
**Impl:** done

- [x] skill 在每个宿主下有四种状态：未安装；已安装（本工具装的，显示已装版本）；已安装且与清单版本不同（同时显示两个版本）；已存在但不是本工具装的（目录存在而没有安装标记，或是一个符号链接）。
- [x] 状态完全来自对目标目录的实时探测，不依赖任何集中的状态文件。
- [x] 对已安装的 skill 再装一次即整目录替换，并更新安装标记；汇总里注明目录内的本地改动会丢失。
- [x] 选中"不是本工具装的"条目时，需要在汇总之外单独确认覆盖，默认不覆盖；拒绝后该目录保持原样，其余选中项照常安装。
- [x] 目标是符号链接时，同意覆盖只替换链接本身，链接指向的原目录不被改动。
- [x] 以上行为都有经主接缝的测试：四种状态的显示、覆盖已装的、对"不是本工具装的"目录拒绝与同意两种走向、符号链接只替换链接本身。
- [x] UI: skill 列表 / 四种状态并存 — 每种状态有不同的文字标记，不只靠颜色区分。
- [x] UI: 汇总确认 / 含覆盖项 — 标出哪些会被覆盖以及本地改动会丢失。
- [x] UI: 界面预览页 / 本工单新增的画面与状态 / 深色与浅色 — 已作为场景加入预览页，且与 `ui-direction.md` 的选定方向一致。

## 实现时定下的事（维护者尚未逐条确认）

- 安装标记在、但读不出版本（不是 JSON、没有 `version`、版本里夹着控制字符）时，当作不是本工具装的，覆盖前单独问。另一条路是“文件在就算本工具装的”，那样版本显示不出来，还会不问就替换一个来历说不清的目录。
- 清单里的版本比已装的旧，同样按「版本不同」显示两个版本（`已装的 → 清单的`），不区分升级还是降级。
- 汇总里「注意  覆盖即整目录替换，目录内的本地改动会丢失」只在至少有一项是覆盖时出现；全是新装时不写。`prd.md` 的原话是“汇总确认时要说明这一点”，没带条件——要它固定出现，改 `ui.installSummary` 里的一个条件即可。
- 单独确认发生在汇总确认之后、查询和下载之前，一项一问（同一个 skill 在两个宿主下都不是本工具装的就问两次）。用 y / n 回答，直接回车是否；输入别的不结束提问，下方出一句「注意  请输入 y 或 n」。
- 没同意的那一项在结果里是「– … 跳过 未同意覆盖，保持原样」，计入合计的「跳过」。全都没同意时不向 GitHub 查询。
- 汇总里的备注整张表一个放法：每一条都放得下才成一栏；有一条放不下，就全部另起一行、与位置的左缘对齐，表头不写「备注」。一条备注都没有时表头也不写。这是视觉评审指出“同一张表里两种放法”之后改的。
- 状态每次要显示就现探测：进一次列表探测一轮，勾完给汇总再探测一次。
- 新增依赖 `@inquirer/confirm`（6.3.3，与已有的两个子包共用同一个 `@inquirer/core`）。

## 评审后没有改的

- 安装标记的测试夹具有四处各写了一份（预览页、两个测试文件、一处内联），字段不完全一样；建符号链接的循环在测试架子和预览页各一份。
- 对状态种类的分支散在呈现层四处和流程一处。
- 结果行里结果词与原因只隔一格，「跳过」又和原因同色（视觉评审认为是口味问题）。
- 符号链接的测试在 Windows 上建的是 junction，本机没法跑，要等 CI 的 Windows 环境验证。
