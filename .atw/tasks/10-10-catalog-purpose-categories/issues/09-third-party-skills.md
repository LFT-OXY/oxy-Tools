# 09 — 第三方 Skill：登记、勾选、静默安装

**What to build:** 维护者能在目录里登记第三方 Skill：只写它的仓库、里面有哪些 skill、各自一句说明。用户在混合列表里看到它，自成一段、段首标明「第三方」；勾了只含一个 skill 的直接进汇总，勾了含多个的先看到清单、自己勾要哪几个。确认后安装器在后台调用通用的 skill 安装程序把它装进宿主——从头到尾终端上只有安装器自己的画面。这一张只做装到全局。

**Blocked by:** 07
**Status:** ready-for-agent
**Impl:** done

- [x] `catalog.json` 可以有第三方 Skill 的数组。每项除条目共有的字段和用途、推荐之外，有：来源（GitHub 上的「所有者/仓库」）、其中的 skill 清单（至少一个，每个是 skill 自己声明的名字和中英文说明）、可选的宿主限制（写法同 MCP 的）。名字只在这个数组里唯一。
- [x] 来源和每个 skill 的名字只收安全的字符（规则见 `prd.md`「读取与校验」）；不合规则的条目被跳过并带原因，目录校验命令有对应的说法。

## Comments

2026-10-10 至 10-11 实现。规范里只有「安装 skill」的契约是动手之前写的，另外六份（安装 MCP、入口与测试、目录校验与 CI、终端输出、清单与版本、界面设计）是实现之后、评审指出之后才补齐的——没有照「先改规范」的字面全部先改。

维护者 2026-10-11 确认的（评审指出它们与规格的字面不一致，两处都问过）：

- **每个 skill、每个宿主各一条命令**，不是对比页上画的每个条目、每个宿主一条。理由：覆盖前的询问排在确认之后，合在一条命令里的话，没同意其中一个时执行的就不是展示的那一条。代价是同一个仓库勾了几个 skill 就要拉几次。
- skill 的名字只收小写的（且不以 `.` 或 `-` 结尾、连字符不连着写）：skills CLI 装出来的目录名是小写的。来源的每一段要以字母或数字开头：以 `-` 开头会被当成选项，以 `.` 开头会被当成本地路径。
- 调用 skills CLI 时清空 `CLAUDE_CONFIG_DIR`：它认这个变量，安装器的 skill 目录不认；实测不清空会装到别处。
- 「已有同名目录」包括目标位置是文件或符号链接；同意覆盖而命令失败时结果写「已安装；安装命令退出状态 N」。

实现时定下、维护者没有逐条确认的（同时记在 `.atw/spec/cli/ui-design.md` 的「实现时定下、维护者还没有看过的画法」和 `prd.md` 的 Further Notes 第 17 条）：清单起始一个都不勾，返回修改后上次勾的还在；清单收成的一行勾了三个以上只列前三个；「将安装 N 项」里一个条目算一项；「目录」一行的 `Skill` 把本仓库的和第三方的合在一起数；英文的几句文案。

手动核对（用真实的 `npx` 在临时主目录里装 `emilkowalski/skills` 的 `animate`）的记录在 `research/third-party-trial-record.md`，原始输出在 `research/third-party-trial-raw-output.txt`。只在 macOS 上做了；Windows、Linux 没有实测。

评审（Standards / Spec / Visual 各一轮，改完之后复查一次）之后改的：`columns.test.ts` 里把栏宽写死的几条断言改成只卡三格；一条名不副实的用例改名，另加一条真的让 GitHub 查询失败的；测试架子的返回类型不再放宽；skill 名字的正则放宽到恰好是 skills CLI 不会改动的那些（原先多拒了 `a__b`、`a_`）；补齐上面那六份规范。没有改、留给维护者定的：

- 已知的限制：两个条目里有同名的 skill、或第三方 Skill 和本仓库的 skill 同名时，同一轮里后装的会盖掉先装的而不另问。录入条目时（工单 13）要避开；要不要让目录校验命令查它，另议。
- 汇总里展示的命令不带执行时另加的环境变量（关遥测的两个、清空的 `CLAUDE_CONFIG_DIR`）：设了 `CLAUDE_CONFIG_DIR` 的用户照着命令自己跑，会装到和安装器不同的地方。
- 评审认为是写法问题、没有改的：`catalog.ts` 里宿主限制的校验现在有三份一样的；`ui.ts` 里第三方 Skill 和别的类型有几处相似的拼法；`ThirdPartyStatus` 用 `'unsupported' | boolean[]` 表示；`confirmOverwrites` / `confirmReplacements` 两个名字不够一眼分清。
- 视觉评审的三条，都是口味上的：命令折行可能把 `--agent` 和它的值拆在两行；「将安装 4 项」而小表里有 5 个名字（条目与 skill 的差别）；清单里几条说明都截在要紧的括号里。
- 早先就有、这次更容易碰到的：英文界面里列表收成的那一行在名字长时超过 79 列，被终端折成两行。
