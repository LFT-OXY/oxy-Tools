# 09 — 第三方 Skill：登记、勾选、静默安装

**What to build:** 维护者能在目录里登记第三方 Skill：只写它的仓库、里面有哪些 skill、各自一句说明。用户在混合列表里看到它，行上有「第三方」标记；勾了只含一个 skill 的直接进汇总，勾了含多个的先看到清单、自己勾要哪几个。确认后安装器在后台调用通用的 skill 安装程序把它装进宿主——从头到尾终端上只有安装器自己的画面。这一张只做装到全局。

**Blocked by:** 07
**Status:** ready-for-agent
**Impl:** ready

- [ ] 先改规范：安装 skill（新增第三方 Skill 的契约）、安装 MCP（外部命令执行器的契约）、入口与测试、目录校验与 CI、终端输出、清单与版本。决定的出处是 ADR-0003。
- [ ] `catalog.json` 可以有第三方 Skill 的数组。每项除条目共有的字段和用途、推荐之外，有：来源（GitHub 上的「所有者/仓库」）、其中的 skill 清单（至少一个，每个是 skill 自己声明的名字和中英文说明）、可选的宿主限制（写法同 MCP 的）。名字只在这个数组里唯一。
- [ ] 来源和每个 skill 的名字只收安全的字符（规则见 `prd.md`「读取与校验」）；不合规则的条目被跳过并带原因，目录校验命令有对应的说法。
- [ ] 目录校验命令通过时的那一行里报出第三方 Skill 的个数。
- [ ] 混合列表里第三方 Skill 的类型是 Skill，行上有「第三方」标记；每个所选宿主一栏状态：未装、已装、含多个时「已装几个 / 共几个」、宿主限制之外的显示不支持。状态只看目标位置下有没有那个 skill 的目录。
- [ ] 只含一个 skill 的条目勾选后不再多问；含多个的在列表确认之后出一张清单：每个 skill 的名字、说明、各宿主下的状态，由用户勾选。清单里一个都不勾就确认，这一条不装，其余勾选的照常。
- [ ] 每个要装的 skill 在每个支持它的所选宿主下各是一项。命令经 `npx` 起 skills CLI，版本钉在 1.x：给出来源、要装的 skill 的名字、目标宿主、跳过确认、全局。每个宿主单独一条命令。
- [ ] 这些命令列在「将执行的命令」里，完整展示；展示的和执行的是同一份。
- [ ] 用不经 shell、不接终端的执行方式：命令和参数分开传，它的输出不上屏，也读不到用户的输入。执行器的这种方式多收一样可选的东西：额外的环境变量，这里用来关掉 skills CLI 的遥测。
- [ ] 安装过程中终端上没有 skills CLI 的字符画、框线和它的英文进度，也没有它的提问。
- [ ] 成败看复核：命令结束后目标位置下那个 skill 的目录里有 `SKILL.md` 才算装上。退出状态是 0 而没有 `SKILL.md` 的判失败。
- [ ] 失败的结果行只说哪一步、退出状态几，或「没能运行」加错误码；不转述那个程序的话。一项失败不影响其余项。
- [ ] 目标位置已有同名目录时，确认之后、执行之前逐项另问，缺省不覆盖；没同意的那些不装并在结果里写明跳过。
- [ ] 这一轮有第三方 Skill 时，汇总下方有一行提醒：装的是作者当时的最新版，维护者没有逐版检查。
- [ ] 执行的先后：本仓库的 skill、第三方 Skill、MCP、工具。
- [ ] 测试架子：只记录不执行的命令执行器能在「执行」某条命令时往目标位置放文件或不放，并记下那条命令带了哪些额外的环境变量、用的是哪种执行方式。
- [ ] 经主接缝的测试：单个 skill 的直接装；多个的出清单、勾几个装几个、一个不勾则不装；记录到的命令逐字正确且每个宿主一条；带着关遥测的环境变量；用的是不接终端的方式；退出 0 但没有 `SKILL.md` 判失败；退出非 0 时结果行的写法；已有同名目录时另问且缺省不覆盖；宿主限制；写坏的条目被跳过。
- [ ] 手动核对一次并把结果记进任务目录：在临时主目录里（主目录和宿主的配置目录都指到临时目录并断言）让安装器用真实的 `npx` 装一个第三方 Skill，录下的原始输出里搜不到 skills CLI 的字符画和框线，目标位置有 `SKILL.md`，真实的主目录没有变化。
- [ ] 界面预览页加上带「第三方」标记的列表、第三方 Skill 的清单（部分已装）、含第三方命令与提醒的汇总、一项失败的结果这几格。
- [ ] UI: 第三方 Skill 的清单 / 多个 skill、部分已装 / 80 列 — 每个 skill 一行，有说明和状态。
- [ ] UI: 执行与结果 / 第三方 Skill 一项失败 / 80 列 — 失败的那一行写着退出状态；画面上没有任何框线字符画。
- [ ] 类型检查和全部测试通过；测试在 Node 22.13 上也跑过一遍。
