# 01 — 定下新画面的画法：主菜单、混合列表、安装范围、第三方 Skill 的清单

**What to build:** 维护者在一张对比页上看到四个新画面各自的几种排法，选定一种；选定的画法写进界面设计规范，后面每一张改画面的工单都照它实现。这一张不改安装器的行为。

**Blocked by:** None
**Status:** ready-for-agent
**Impl:** ready

- [ ] 对比页覆盖 `prd.md`「UI and Design」表里这些画面的状态：主菜单（有「推荐」、没有「推荐」）；选择安装范围（提问中、已回答收成一行）；混合列表（四种类型同表、带「第三方」和「推荐」标记的行、外部项目一段、一个宿主与两个宿主、不可选的行）；第三方 Skill 的清单（多个 skill 各带说明与状态、部分已装）；几种类型混在一起的汇总与将执行的命令、结果、外部项目的说明与链接各一格。
- [ ] 混合列表至少给出两种真正不同的排法（例如类型作为一栏，或类型作为分段标题；状态每个宿主一栏，或合成一栏），不是同一种排法换个间距。
- [ ] 每种排法都用目录里最长的真实名字排过一遍（如 `nuyoah-image-reverse-prompt`、`firecrawl-mcp-server`、`oh-story-claudecode`），两个宿主时任何一行不超过 79 列。
- [ ] 沿用「账本」方向：不加边框，状态用词表达，栏对齐，块与块之间空一行，焦点色是洋红；不给颜色新增含义。
- [ ] 中文和英文各排一遍最宽的那个画面；深色、浅色背景各一份。
- [ ] 维护者看过并选定。选定的方向、没选的候选和原因记在任务目录的 `ui-direction.md`（上一个任务有先例）。
- [ ] 界面设计规范按选定的画法改好：「主菜单」「选择条目」「汇总确认」「执行中与结果」几节改写；「应用项目」一节改名外部项目并改成新做法；新增「选择安装范围」「第三方 Skill 的清单」两节；「状态的写法」表加上第三方 Skill 的状态（未装、已装、已装几个 / 共几个、不支持）；写明「第三方」「推荐」两个标记放在哪、什么颜色。
- [ ] 对比页是一次性的，不提交进仓库；要留的只有任务目录里的 `ui-direction.md` 和截图。
- [ ] UI: 混合列表 / 四种类型都有、两个宿主 / 80 列，深色与浅色 — 每一行看得出类型；第三方 Skill 的行上有「第三方」；外部项目都在组件下面且两段之间有分隔；没有一行超过 79 列。
- [ ] UI: 主菜单 / 有「推荐」/ 80 列 — 第一行是「推荐」，下面是各个用途，每行右边有条目数；看不到按类型分的行。
