# 10 — Skill 可以装到项目

**What to build:** 用户选完宿主之后被问一句：装到全局，还是装到项目。光标缺省停在全局，按回车就过。选了项目，本仓库的 skill 和第三方 Skill 就落在他运行安装器时所在的目录里，只对这个目录生效；列表里的状态、汇总里的位置都按项目来。

**Blocked by:** 09
**Status:** ready-for-agent
**Impl:** ready

- [ ] 先改规范（入口与测试、安装 skill、终端输出）。
- [ ] 入口多收一样运行环境的事实：项目目录。正式运行时是当前目录，测试里是一个临时目录；入口仍然不直接碰进程。
- [ ] 进入「推荐」或一个用途后，选完宿主（或不需要问宿主）就问安装范围：全局在前、项目在后，光标起始在全局。每次进入列表都问，不记上一次的选择。回答后收成一行。
- [ ] 界面上不为项目的路径单独设确认。
- [ ] 宿主适配回答项目范围的 skill 目录：Claude Code 是项目目录下的 `.claude/skills`，Codex 是项目目录下的 `.agents/skills`。
- [ ] 本仓库的 skill 装到项目时落在那个目录里；状态判断、版本对比、不是本工具装的目录另问且缺省不覆盖，都按那个目录来，做法与全局时相同。
- [ ] 第三方 Skill 装到项目时命令不带全局选项，并且在项目目录下运行——执行器不接终端的那种方式多收一样可选的东西：在哪个目录下运行。复核和同名目录的询问按项目目录来。
- [ ] 列表和清单里的状态按所选的宿主与安装范围显示。
- [ ] 汇总里各项的位置照常显示；项目范围的写成相对当前目录的路径。
- [ ] 选了项目时，主目录下各宿主的全局 skill 目录没有任何变化。
- [ ] 工具不受安装范围影响：选了项目，工具的状态、命令、汇总里的写法都和选全局时一样。
- [ ] 这一张做完时 MCP 还不能装到项目：选了项目范围，MCP 的行不可选并写明原因；下一张工单补上。
- [ ] 测试架子缺省替用户在安装范围的提问上按回车（全局），现有用例的应答序列不用改；专门测安装范围的用例才自己应答。
- [ ] 经主接缝的测试：提问的两项、顺序、光标起始；选项目后本仓库的 skill 落在项目目录、主目录不变；第三方 Skill 的命令不带全局选项且在项目目录下运行；状态按范围读（全局装过而项目没装过时，项目范围下显示未装）；汇总里的相对路径；工具不受影响。
- [ ] 手动核对一次并把结果记进任务目录：真实的 skills CLI 不带全局选项时，在临时目录里落下的位置与两个宿主适配回答的一致。
- [ ] 界面预览页加上选择安装范围（提问中、已回答）、项目范围下的列表与汇总这几格。
- [ ] UI: 选择安装范围 / 提问中 / 80 列 — 两项依次是全局、项目，光标在全局。
- [ ] UI: 汇总 / 项目范围 / 80 列 — 位置一栏是相对当前目录的路径，不是主目录下的路径。
- [ ] 类型检查和全部测试通过；测试在 Node 22.13 上也跑过一遍。
