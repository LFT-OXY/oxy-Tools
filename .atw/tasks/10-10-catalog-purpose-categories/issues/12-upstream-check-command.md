# 12 — 上游核对命令

**What to build:** 维护者运行一条命令，就知道目录里登记的每个第三方 Skill 和作者仓库的现状还对不对得上：仓库还在不在、有没有改名或归档、里面的 skill 多了还是少了。条目失效时不必等用户来报。

**Blocked by:** 09
**Status:** ready-for-agent
**Impl:** done

- [x] 先改规范：目录校验与 CI 里加一节，写明这条命令的输出、退出状态、怎么测、为什么不进 CI。
- [x] 它是仅供开发的脚本，和目录校验命令放在一处，不进 npm 包。目录的位置由运行的人给，脚本里不写死。
- [x] 对目录里每个第三方 Skill 报告：来源仓库不存在；已归档；已改名（给出新名字）；目录里登记而上游没有的 skill；上游有而目录里没登记的 skill。
- [x] 全都对得上时输出一行通过并以 0 退出；有任何一项对不上时逐条列出并以非零状态退出。
- [x] 它只报告，不改目录文件。
- [x] 不进 CI：它要联网，结果随上游变。
- [x] 上游的仓库名、skill 名是远程数据，打到终端之前去掉控制字符。
- [x] 经辅助接缝的测试：把命令当子进程跑，让它对着本地的假仓库目录（代替 GitHub），只断言标准输出、标准错误和退出状态——全对得上、少了一个 skill、多了一个 skill、仓库不存在这几种情况。联网的那一段不进自动化测试。
- [x] 手动核对一次：对着真实的 GitHub，用一份登记了两三个真实仓库的样例目录跑通（其中一个故意写错一个 skill 名），输出与预期一致。
- [x] 类型检查和全部测试通过。
