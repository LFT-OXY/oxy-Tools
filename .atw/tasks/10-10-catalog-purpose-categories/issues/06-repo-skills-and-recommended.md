# 06 — 本仓库的 skill 进混合列表，「推荐」出现

**What to build:** 主菜单第一行出现「推荐」，进去是本仓库的全部 skill；标了用途的 skill 同时出现在那个用途下。用户在混合列表里勾选 skill（可以和外部项目一起勾），选宿主、看汇总、确认、覆盖前被单独询问、安装、看结果——都和现在装 skill 时一样。Skill 这个旧分组取消。

**Blocked by:** 05
**Status:** ready-for-agent
**Impl:** ready

- [ ] 先改规范（安装 skill、入口与测试、终端输出）。
- [ ] 「推荐」由两部分组成：本仓库的全部 skill（自动，不靠任何标注，也去不掉），加上带推荐标记的其它条目。里面一个条目都没有时，「推荐」这一行不出现。
- [ ] 没有标用途的本仓库 skill 只出现在「推荐」里；标了用途的在「推荐」和那个用途下两处都出现。
- [ ] 进入「推荐」或一个用途后：检测到不止一个宿主才问装进哪些，只问一次；只检测到一个就直接用它。
- [ ] 混合列表里组件在上、外部项目在下；组件按类型分段，段首写着类型（画法见 `ui-direction.md`）；带推荐标记的行看得出来；skill 每个所选宿主各有一栏状态，四种状态的写法不变。
- [ ] 一次勾选 skill 和外部项目：汇总、确认、覆盖前的单独询问、安装、结果照常，最后才是外部项目的说明与链接。
- [ ] 装 skill 的既有行为逐条保留：四种状态与版本对比；不是本工具装的目录逐个另问、缺省不覆盖；钉住来源、按提交下载；下载中途失败时目标位置保持原样；一项失败不影响其余项；出错矩阵里的每一种说法；按 Ctrl+C 的退出。
- [ ] 一个宿主都没检测到时，「推荐」和用途照常可以进入，skill 的行不可选并写明原因。
- [ ] Skill 这个旧分组取消；MCP、工具两个旧分组暂时保留。
- [ ] 现有关于 skill 的用例（安装、状态探测、宿主选择、列宽、间距、提问）搬到新入口下，断言的行为一条不丢。
- [ ] 经主接缝的新增测试：「推荐」有与无；不带任何标注的 skill 在「推荐」里且不在任何用途下；写了用途的两处都有；带推荐标记的外部项目同时出现在「推荐」和它的用途下；skill 与外部项目一起勾选时的先后。
- [ ] 界面预览页加上有「推荐」的主菜单、含 skill 与外部项目的混合列表、混合的汇总与结果这几格。
- [ ] UI: 主菜单 / 有「推荐」/ 80 列 — 第一行是「推荐」；找不到「Skill」这个分组行。
- [ ] UI: 混合列表 / skill 加外部项目、两个宿主 / 80 列，深色与浅色 — 段首写着类型，列表下方有「类型」一行；两个宿主各一栏状态；外部项目在下面单独一段。
- [ ] 类型检查和全部测试通过；测试在 Node 22.13 上也跑过一遍。
