# 02 — 目录认识用途与推荐

**What to build:** 维护者能在目录里维护用途清单、给条目标上用途和推荐标记、给本仓库的个别 skill 另标一个用途。安装器读得懂这些；写坏的条目只跳过那一条并说明原因；目录校验命令查得出每一种写坏的情况。仓库真实的目录里有了 10 个用途和 4 个 skill 的用途。这一张做完，安装器的画面还是原来的四个分组。

**Blocked by:** None
**Status:** ready-for-agent
**Impl:** ready

- [ ] 先改规范：清单与版本（`catalog.json` 的字段契约）、入口与测试（校验表）、目录校验与 CI（新的跳过原因和说法）。然后才改实现。
- [ ] `catalog.json` 可以有：用途清单（有序数组，每项是小写 kebab-case 的标识和中英文名称）；MCP、工具、外部项目条目上的用途（用途清单里的一个标识）和可选的推荐标记（布尔）；本仓库 skill 的可选用途（按 skill 的名字给出）。
- [ ] 都是可选的新增：两个目录文件的格式版本号不升；登记外部项目的那个数组键名不改；skill 清单的格式和内容一个字不动。
- [ ] 本仓库 skill 以外的条目没有用途、或用途不在清单里时，被跳过并各有自己的原因，其余条目照常；被跳过的条目照现有的方式告诉用户。
- [ ] 用途清单本身写坏（不是数组、标识重复、缺名称）时，受影响的条目按「用途不在清单里」处理，整份目录仍读得了。
- [ ] 本仓库的 skill 没有用途是正常的，不跳过。给它写的用途不在清单里时也不跳过，只在目录校验命令里报出来。
- [ ] 没有这些新增内容的旧格式目录读得了、不崩。
- [ ] 目录校验命令对每种新的写坏情况各有一句给人看的说法，并以非零状态退出。
- [ ] 仓库真实的 `catalog.json` 写入 10 个用途，顺序是：开发工作流与规范、Agent 行为约束与输出风格、代码库索引与理解、上下文记忆与 Token 优化、联网搜索与文档检索、浏览器自动化、UI 设计图像与视频、文档处理、提示词与写作、代码审查评估与安全；各有英文名称。
- [ ] 真实目录里 archify 的用途是文档处理，onetake 是 UI 设计图像与视频，unlazy 是 Agent 行为约束与输出风格，shuorenhua 是提示词与写作。其余 9 个 skill 不写用途。
- [ ] 目录校验命令对仓库真实的目录数据通过。
- [ ] 经主接缝的测试：上面每种读取情况；测试架子的样例目录带上用途清单，现有用例不因此丢失断言。经辅助接缝的测试：目录校验命令的每种新说法。
- [ ] 已发布的 0.2.0 版安装器在临时目录里读这份新的真实目录（目录来源指到本地仓库根），照常显示它原来的分组，不报错。
- [ ] 类型检查和全部测试通过。
