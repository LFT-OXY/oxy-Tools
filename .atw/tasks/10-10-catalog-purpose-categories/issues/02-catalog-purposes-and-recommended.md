# 02 — 目录认识用途与推荐

**What to build:** 维护者能在目录里维护用途清单、给条目标上用途和推荐标记、给本仓库的个别 skill 另标一个用途。安装器读得懂这些；写坏的条目只跳过那一条并说明原因；目录校验命令查得出每一种写坏的情况。仓库真实的目录里有了 10 个用途和 4 个 skill 的用途。这一张做完，安装器的画面还是原来的四个分组。

**Blocked by:** None
**Status:** ready-for-agent
**Impl:** done

- [x] 先改规范：清单与版本（`catalog.json` 的字段契约）、入口与测试（校验表）、目录校验与 CI（新的跳过原因和说法）。然后才改实现。
- [x] `catalog.json` 可以有：用途清单（有序数组，每项是小写 kebab-case 的标识和中英文名称）；MCP、工具、外部项目条目上的用途（用途清单里的一个标识）和可选的推荐标记（布尔）；本仓库 skill 的可选用途（按 skill 的名字给出）。
- [x] 都是可选的新增：两个目录文件的格式版本号不升；登记外部项目的那个数组键名不改；skill 清单的格式和内容一个字不动。
- [x] 本仓库 skill 以外的条目没有用途、或用途不在清单里时，被跳过并各有自己的原因，其余条目照常；被跳过的条目照现有的方式告诉用户。
- [x] 用途清单本身写坏（不是数组、标识重复、缺名称）时，受影响的条目按「用途不在清单里」处理，整份目录仍读得了。
- [x] 本仓库的 skill 没有用途是正常的，不跳过。给它写的用途不在清单里时也不跳过，只在目录校验命令里报出来。
- [x] 没有这些新增内容的旧格式目录读得了、不崩。
- [x] 目录校验命令对每种新的写坏情况各有一句给人看的说法，并以非零状态退出。
- [x] 仓库真实的 `catalog.json` 写入 10 个用途，顺序是：开发工作流与规范、Agent 行为约束与输出风格、代码库索引与理解、上下文记忆与 Token 优化、联网搜索与文档检索、浏览器自动化、UI 设计图像与视频、文档处理、提示词与写作、代码审查评估与安全；各有英文名称。
- [x] 真实目录里 archify 的用途是文档处理，onetake 是 UI 设计图像与视频，unlazy 是 Agent 行为约束与输出风格，shuorenhua 是提示词与写作。其余 9 个 skill 不写用途。

## Comments

**2026-10-10 实现记录**

- 字段名是实现时定的：用途清单 `purposes`（每项 `id` + `name.zh` / `name.en`），条目上的 `purpose`、`recommended`，本仓库 skill 的用途 `skillPurposes`（skill 的名字 → 用途的标识）。
- 10 个用途的标识依次是 `dev-workflow`、`agent-behavior`、`codebase-understanding`、`context-memory`、`web-search`、`browser-automation`、`design-media`、`documents`、`prompts-writing`、`review-security`。中文名称照「汇总」文档的原标题，其中三个带顿号（`上下文、记忆与 Token 优化`、`UI 设计、图像与视频`、`代码审查、评估与安全`）——工单和 prd 的列举里没有顿号，是因为列举本身用顿号分隔。
- 工单写「其余 9 个 skill 不写用途」、prd 写「13 个 skill」，仓库 `index.json` 实际是 12 个：4 个写了用途，其余 8 个没写。
- 工单没有规定、实现时定下的三处：用途清单里标识重复时只留第一项（用它的条目不跳过，沿用「重名只留第一条」），由目录校验命令报出来；`recommended` 写了但不是布尔的条目被跳过；`skillPurposes` 里写了 `index.json` 没有的 skill、或整个不是对象，目录校验命令也报。
- 目录校验命令的通过信息多报了用途的个数（`…、10 个用途`）。
- **0.2.0 读新目录的实测**：在 `mktemp -d` 的临时目录里 `npm install oxy-tools@0.2.0`，`HOME`、`CLAUDE_CONFIG_DIR`、`CODEX_HOME` 都指到临时目录，`OXY_TOOLS_CATALOG` 指到本仓库根，在伪终端里跑 `npx --no-install oxy-tools --lang zh`。画面：`目录  12 skill`，没有「条目格式有误」的提醒，主菜单是 `Skill 12` 和 `退出`（真实目录里 MCP、工具、应用项目都还是空的，所以和改动前一样只有这一个分组）；进入 Skill 后照常问装进哪些 AI Agent、列出 skill 与各自的状态。没有出错说明。只看了画面，没有安装任何东西。
- 类型检查通过；全部测试 643 条在 Node 24.15 和 22.13.0 上各跑一遍，都通过；`npm run validate-catalog -- ..` 输出 `目录校验通过：12 个 skill、0 个 MCP、0 个工具、0 个应用项目、10 个用途`。
