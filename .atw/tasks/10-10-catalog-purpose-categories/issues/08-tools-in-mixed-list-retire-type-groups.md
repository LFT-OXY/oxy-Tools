# 08 — 工具进混合列表，按类型的入口全部取消

**What to build:** 四种类型都在混合列表里了。用户可以把工具和别的类型一起勾选；工具的安装命令仍然完整展示、确认后才执行、执行后复核，它自己的输出仍然直接显示。主菜单上只剩「推荐」、各个用途和退出。

**Blocked by:** 07
**Status:** ready-for-agent
**Impl:** ready

- [ ] 先改规范（安装工具、入口与测试、终端输出）。
- [ ] 混合列表里工具只有一个状态（未安装、已安装），与选了哪些宿主无关；不支持这个系统的、需要别的宿主的工具显示为不可选并写明原因，说法不变。
- [ ] 工具的命令列在「将执行的命令」里，和 MCP 的命令在同一处，整行完整展示；展示的和执行的是同一个字符串。
- [ ] 工具的命令整行交给系统的 shell，输入输出直接接在用户的终端上；成功与否只看复核，不看退出状态。
- [ ] 执行的先后：本仓库的 skill、MCP、工具——工具排在最后。每个工具一个以它名字为标题的分区；不止一个工具时结果里再列一遍结论，只有一个时不重复。
- [ ] 一个宿主都没检测到时，工具和别的组件一样不可选并写明原因。
- [ ] 工具这个旧分组取消。主菜单上找不到「Skill」「MCP」「工具」「应用项目」任何一个分组行。
- [ ] 现有关于工具的用例搬到新入口下，断言的行为一条不丢。
- [ ] 经主接缝的新增测试：一次勾选 skill、MCP、工具加一个外部项目——汇总里都有，三种命令的先后，结果各一行，最后是外部项目的链接，没有调用链接打开器。
- [ ] 界面预览页加上四种类型都有的混合列表、含不可选工具的列表、工具排在最后的执行与结果这几格。
- [ ] UI: 主菜单 / 默认 / 80 列 — 只有「推荐」、各用途、退出。
- [ ] UI: 混合列表 / 四种类型都有 / 80 列，深色与浅色 — 段首的类型只会是 Skill、第三方 Skill、MCP、工具、外部项目之一；不可选的工具行上写着原因。
- [ ] UI: 执行与结果 / 含工具 / 80 列 — 工具的执行分区排在别的类型之后。
- [ ] 类型检查和全部测试通过；测试在 Node 22.13 上也跑过一遍。
