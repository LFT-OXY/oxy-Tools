# 07 — MCP 进混合列表

**What to build:** MCP 和 skill、外部项目出现在同一张列表里，用户可以一起勾选、一起确认、一起装。key 怎么问、命令怎么展示、已经配置过的怎么覆盖、Codex 可能当场登录的提醒，都和现在装 MCP 时一样。MCP 这个旧分组取消。

**Blocked by:** 06
**Status:** ready-for-agent
**Impl:** ready

- [ ] 先改规范（安装 MCP、入口与测试、终端输出）。
- [ ] 混合列表里 MCP 每个所选宿主各有一栏状态（未配置、已配置、未知、不支持），写法不变；宿主的配置读不了时的那行提示照旧。
- [ ] 勾选的 MCP 逐个问它要的 key：先显示说明和申请链接，输入不回显；同一个 MCP 的同一个变量一次运行里只问一次；必填的留空就不装这个 MCP 并说明，可选的留空就不带。
- [ ] 汇总之后有「将执行的命令」，每条命令完整展示，key 的位置是占位符；展示的和之后执行的是同一份。
- [ ] 确认可以选执行、返回修改、取消；返回修改时勾选还在。
- [ ] 执行的先后：本仓库的 skill 在前，MCP 在后。一项失败不影响其余项，失败的写法不变。
- [ ] key 的值不出现在终端的任何输出里，不写进任何文件。
- [ ] 带推荐标记的 MCP 同时出现在「推荐」和它的用途下。
- [ ] MCP 这个旧分组取消；工具的旧分组暂时保留。
- [ ] 现有关于 MCP 和 key 的用例搬到新入口下，断言的行为一条不丢。
- [ ] 经主接缝的新增测试：一次勾选 skill、MCP、外部项目——汇总里都有、命令的先后、结果各一行、最后是外部项目的链接。
- [ ] 界面预览页加上含 MCP 的混合列表、带 key 占位符的将执行的命令、混合的结果这几格。
- [ ] UI: 混合列表 / skill 加 MCP、两个宿主 / 80 列 — 两种类型的状态都落在各自宿主的那一栏里，栏对得齐。
- [ ] UI: 汇总与将执行的命令 / 带 key / 80 列 — 命令完整可见，key 的位置是占位符而不是值。
- [ ] 类型检查和全部测试通过；测试在 Node 22.13 上也跑过一遍。
