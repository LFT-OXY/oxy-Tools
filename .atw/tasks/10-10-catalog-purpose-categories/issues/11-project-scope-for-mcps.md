# 11 — MCP 可以装到项目

**What to build:** 用户选了项目范围，MCP 也能装：它的配置写进当前目录，只对这个项目生效。把带 key 的 MCP 装到项目时，确认之前会被明确提醒 key 会以明文写进哪个文件。

**Blocked by:** 07, 10
**Status:** ready-for-agent
**Impl:** ready

- [ ] 第一步先验证 Codex：官方只说项目目录里可以放一份配置、只对受信任的项目生效，它的添加命令没有范围选项。在临时目录里用真实的 Codex 试出一种可靠的写法；结论和选定的写法先记进「安装 MCP」的规范，再动手实现。
- [ ] Codex 的验证不通过时：项目范围下 Codex 那一栏显示不支持并写明原因，不拿没验证过的写法去改用户的文件。这个结果同样记进规范。
- [ ] 同一步核对 Claude Code 对项目里的 MCP 配置是否要用户另行批准才启用；要的话，汇总下方加一行说明。
- [ ] 宿主适配多回答：项目范围的 MCP 怎么添加和移除、去哪看项目里已经配了哪些。
- [ ] Claude Code：添加和移除命令带上它自带的项目范围，并在项目目录下运行；已配置的 MCP 从项目目录的 `.mcp.json` 里看。
- [ ] MCP 的状态按所选范围显示：选项目时看项目里的配置，选全局时看用户级配置。
- [ ] 选了项目范围且这一轮有带 key 的 MCP 时，汇总下方、确认之前有一行警告：key 会以明文写进哪个文件，不要把它提交或发给别人。警告里没有 key 的值。带 key 的 MCP 照样能装。
- [ ] 选了项目范围且这一轮有 MCP 要装进 Codex 时，汇总下方有一行说明：Codex 只对受信任的项目读这份配置。
- [ ] 上一张工单里「MCP 在项目范围下不可选」的临时做法去掉。
- [ ] 全局范围下 MCP 的行为与改动前逐条一致。
- [ ] key 的值不出现在终端的任何输出里。
- [ ] 经主接缝的测试：Claude Code 项目范围的添加与移除命令逐字正确、在项目目录下运行；状态按范围读；带 key 时警告出现在确认之前且不含值；Codex 的说明；全局的用例全部照旧通过。
- [ ] 手动核对一次并把结果记进任务目录：在临时目录里（主目录和两个宿主的配置目录都指到临时目录并断言）用真实的宿主命令把一个 MCP 装到项目，配置出现在项目目录里，用户级配置没有变化。
- [ ] 界面预览页加上项目范围带 key 的警告、Codex 受信任项目的说明这两格。
- [ ] UI: 汇总与将执行的命令 / 项目范围、带 key / 80 列 — 警告在确认提问的上方，写着文件名，不含 key 的值。
