# 02 — Pi 的 MCP：装到全局和项目

**What to build:** 选了 Pi 的用户能把目录里的 MCP 装进 Pi。全局的写进 Pi 的用户级配置，项目的写进当前目录的 `.pi/mcp.json`，都用 Pi 自己的命令（`pi mcp add`、`pi mcp remove`，项目的加 `-l` 并在项目目录下运行）。MCP 那一栏如实显示「未配置」「已配置」「未知」，看的是所选安装范围下的那份配置；用户把 Pi 的配置目录改到别处（`PI_CODING_AGENT_DIR`）时看的是那一份。带 key 的照旧只问一次、用于所选的每个宿主。装到项目时带两句提醒：key 以明文写进 `.pi/mcp.json`；要在这个目录下启动 `pi` 并信任这个项目之后才启用。Pi 不带「添加远程地址的 MCP 时可能当场登录」的提醒——它的添加命令只写配置、不连接服务器。命令的写法和事实的出处见 `research/pi-omp-host-facts.md`。

- [ ] 先改规范：`.atw/spec/cli/` 里安装 MCP 的那一份写上 Pi 的添加、移除命令，两份配置在哪，项目范围的两句提醒，以及它为什么没有登录的提醒。
- [ ] 装到全局：执行的是 `pi mcp add <名字> … -- <命令> <参数…>`，环境变量用 `--env <变量>=<值>` 带上；远程地址的是 `pi mcp add <名字> --url <地址>`。终端界面确认前展示的就是之后执行的那几条，key 的位置是占位符。
- [ ] 装到项目：两条命令都带 `-l`，在项目目录下运行。
- [ ] 状态探测：全局看配置目录下 `mcp.json` 顶层的 `mcpServers`，配置目录缺省是主目录下的 `.pi/agent`，设了 `PI_CODING_AGENT_DIR` 就用它；项目看项目目录下的 `.pi/mcp.json`。文件不存在是一个都没配，读不了或格式不认识是「未知」并有那句读不到配置的说明。
- [ ] 已有同名的 MCP 时汇总里照现有的写法标出来，装的步骤与别的宿主遇到同名时一致。
