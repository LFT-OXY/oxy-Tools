# 04 — omp：检测得到，skill 装得进去，MCP 不装

**What to build:** 可执行路径上有 `omp` 命令的机器上，安装器认出 omp 这个宿主，排在最后，界面上写「omp」。本仓库的 skill 和第三方 Skill 都能装给 omp，装进共用 skill 目录；skills CLI 不认识 omp，交给它的 agent 名借用 `pi`。同时选了 Codex、Pi、omp 时汇总、进度、结果里合成一行「Codex、Pi、omp」。

omp 的 MCP 安装器不装：不为 omp 出 MCP 的安装项；选了 omp 且列表里有 MCP 时，MCP 那几栏的说明里多一句——中文「安装器装不了 omp 的 MCP：请在 omp 里用 /mcp add 添加」，英文对应，宿主名和添加办法取自宿主适配。只选了 omp 时所有 MCP 不可选，行上的原因是「需要别的 AI Agent」。任何情况下安装器不执行 `omp` 命令，不读也不写 omp 的配置文件。

**2026-10-12 重切**：这一张原先还要求四个宿主都选了时各个画面在 80 列和 1280 宽下排得下、排不下就停下来报告。实现时核对出五处排不下，任务回到 specify，维护者定了版式（`prd.md`「四个宿主时的版式」），那五处分给了工单 06（列表的状态按 skill 目录归组）、07（没检测到的宿主合成一句、开场引导的勾选整组换行）、08（汇总里位置另起一行、网页界面的汇总里宿主那一格加宽）。这一张**不改版式**：它做出来的列表是每个所选的宿主一栏、omp 的 MCP 那一栏写「不支持」，本机信息里没检测到的宿主各写各的——这几样到工单 06、07 才换成 `prd.md` 定的样子，这一张的审查不把它们算作缺漏，也不把四个宿主时排不下的那五处算作缺漏。
