# 安装器新增 Pi 和 omp 两个宿主

> 术语以仓库根 `GLOSSARY.md` 为准：正文说「宿主」，界面文案里它显示为「AI Agent」。本任务引入的词「共用 skill 目录」已经写进术语表。
> 相关的设计决定：ADR-0005（Pi 和 omp 的 skill 装进共用 skill 目录）；仍然管着的有 ADR-0001（安装器自成一体）、ADR-0002（目录运行时现拉）、ADR-0003（第三方 skill 由 skills CLI 装）、ADR-0004（缺省网页界面，终端界面留作退路）。
> 本 spec 的决定来自 2026-10-12 的两轮访谈，连同查到的事实逐条记在同目录的 `research/pi-omp-host-facts.md`；「Further Notes」里单列的推断没有经维护者逐条确认。
> **2026-10-12 修订**：实现到工单 04 时核对出四个宿主有五处画面排不下，任务退回本阶段，维护者逐处定了版式——见「Implementation Decisions」里的「四个宿主时的版式」。跟着改的有：用户故事 26、43，「MCP 的状态与不可选的原因」第一条，「共用 skill 目录」里讲列表状态的那一条，「UI and Design」，验收标准，「Further Notes」第 6 条。工单 01–03 已经照修订前的写法做完，其中列表的状态栏、卡片上的状态、本机信息的宿主那一行要跟着改。

## Problem Statement

安装器只认识 Claude Code 和 Codex 两个宿主。维护者自己和目录面向的用户里，有人用的是 Pi 或 omp：

- **只装了 Pi 或 omp 的人用不了安装器。** 安装器说「没有检测到 Claude Code 或 Codex，暂时装不了组件」，目录里的 skill 和 MCP 一样都装不上。
- **同时装着几个的人只能管到其中两个。** Pi 和 omp 里的 skill、MCP 仍要自己照各家的文档手动放、手动配。

## Solution

- 安装器多认两个宿主：**Pi** 和 **omp**，在界面上排在 Claude Code、Codex 之后。检测到了就能选，和现有的两个一样参与「装进哪些 AI Agent」。
- **Skill 和第三方 Skill**：Pi 和 omp 的都装进共用 skill 目录——Codex 已经在用的那个。所以 Codex、Pi、omp 在 skill 上是连着的：装给其中一个，另外两个也看得到。界面用一句话把这件事告诉用户；同时选了其中几个时，同一个 skill 只装一次，汇总和结果里合成一行。
- **MCP**：Pi 的可以装到全局，也可以装到项目，用 Pi 自己的命令。omp 的安装器不装：列表里不为它出 MCP 的状态栏，用一句说明写明要在 omp 里用 `/mcp add` 自己添加。
- 两套界面（网页界面、终端界面）都这样；装的东西、装的方式两边一样。

## User Stories

### 检测与选择宿主

1. 作为只装了 Pi 的用户，我想安装器检测到 Pi 并直接往里装，这样我不用为了用安装器再装一个 Claude Code 或 Codex。
2. 作为只装了 omp 的用户，我想安装器检测到 omp 并让我装 skill，这样目录里的 skill 我也用得上。
3. 作为用户，我想界面上的宿主按 Claude Code、Codex、Pi、omp 的先后排列，这样原来的两个位置不变。
4. 作为用户，我想界面上写的是「Pi」和「omp」，这样和我平时敲的命令、看到的名字对得上。
5. 作为用户，我想没检测到的宿主照旧标着「未检测到」，不能选，这样我知道安装器认识它、只是这台机器上没有。
6. 作为检测到其中几个宿主的用户，我想安装器照旧说明哪些没检测到、组件只装进哪些，这样四个宿主时这句话仍然读得通。
7. 作为一个宿主都没检测到的用户，我想出错说明里列出全部四个名字，这样我知道装哪一个都行。
8. 作为检测到不止一个宿主的用户，我想照旧能勾选装进其中哪几个，这样我可以只管 Pi 而不动别的。
9. 作为网页界面的用户，我想开场引导里和页面顶上都能看到并勾选 Pi 和 omp，缺省的勾选方式和现在一样。
10. 作为已经在用安装器的 Claude Code 或 Codex 用户，我想这次改动之后我原来的用法、装到的位置都不变。

### 把 skill 装进 Pi 和 omp

11. 作为 Pi 用户，我想选了全局时本仓库的 skill 装进主目录下的 `.agents/skills`，这样 Pi 在任何项目里都读得到。
12. 作为 Pi 用户，我想选了项目时 skill 装进当前目录下的 `.agents/skills`，这样它只对这个项目生效。
13. 作为 omp 用户，我想 skill 装到同样的两个位置，这样 omp 读得到。
14. 作为用户，我想 Pi 和 omp 下 skill 的状态（未装、已装、版本不同、不是本工具装的）和 Codex 的判断方式一样，这样我看到的状态是可信的。
15. 作为用户，我想目标位置已有不是本工具装的同名 skill 时照旧另问、缺省不覆盖，这样我自己放的东西不会被悄悄换掉。
16. 作为 Pi 用户，我想第三方 Skill 也能装给 Pi，装到同一个共用 skill 目录。
17. 作为 omp 用户，我想第三方 Skill 也能装给 omp，尽管装它的 skills CLI 并不认识 omp。
18. 作为终端界面的用户，我想确认前照旧看到将要执行的那条 skills CLI 命令，执行的就是我看到的那一条。

### 共用 skill 目录

19. 作为同时选了 Codex 和 Pi 的用户，我想同一个 skill 只装一次，这样不会对同一个目录重复下载、重复覆盖。
20. 作为同时选了 Codex、Pi、omp 的用户，我想汇总里这个 skill 只有一行，宿主那一格写「Codex、Pi、omp」，这样我一眼看出它是一份东西。
21. 作为用户，我想安装进度和结果里也是一行，合计的成功、失败、跳过数按行算，这样数字和我看到的行数对得上。
22. 作为同时选了 Claude Code 和 Pi 的用户，我想汇总里是两行（Claude Code 一行，Pi 一行），因为它们装到两个不同的目录。
23. 作为同时选了四个宿主的用户，我想每个 skill 是两行：Claude Code 一行，「Codex、Pi、omp」一行。
24. 作为用户，我想共用 skill 目录里已有不是本工具装的同名 skill 时只被问一次要不要覆盖，而不是每个宿主问一遍。
25. 作为用户，我想第三方 Skill 在共用 skill 目录上同样只执行一条命令、只出一行结果。
26. 作为用户，我想挑选的列表里共用同一个 skill 目录的几个宿主在 skill 上合成一栏（栏名「Codex、Pi、omp」），状态只写一份，这样我一眼看出它们是同一份东西，四个宿主时列表也排得下。（2026-10-12 修订：原先是每个所选的宿主各一栏、三栏写的一样，四个宿主时 80 列排不下。）
27. 作为只勾了 Pi 的用户，我想在挑选时看到一句说明「Codex、Pi、omp 共用同一个 skill 文件夹：装给一个，另外两个也看得到」，这样装完后 Codex 里也出现这个 skill 时我不会意外。
28. 作为只选了 Claude Code 的用户，我不想看到这句说明，因为它和我无关。
29. 作为英文界面的用户，我想这句说明有对应的英文。
30. 作为同时装给 Claude Code 和 omp 的用户，我接受 omp 会从两个目录各读到一份同名的 skill，由 omp 自己取舍，安装器不为此多做什么。

### Pi 的 MCP

31. 作为 Pi 用户，我想把目录里的 MCP 装到全局，安装器替我执行 Pi 自己的添加命令。
32. 作为 Pi 用户，我想把 MCP 装到项目，配置写进当前目录的 `.pi/mcp.json`。
33. 作为 Pi 用户，我想 MCP 那一栏如实显示「未配置」「已配置」，看的是所选安装范围下 Pi 的那份配置。
34. 作为把 Pi 的配置目录改到了别处（设了 `PI_CODING_AGENT_DIR`）的用户，我想安装器看的是我真正在用的那份配置。
35. 作为用户，我想 Pi 的配置读不了或格式不认识时那一栏写「未知」并说明读不到，而不是当作没配过。
36. 作为用户，我想 Pi 里已有同名的 MCP 时汇总里照旧标出来，这样我知道这次是替换。
37. 作为要填 API key 的用户，我想 key 只问一次、用于所选的每个宿主（包括 Pi），值不显示、不写进安装器自己的任何文件。
38. 作为把带 key 的 MCP 装到项目的用户，我想照旧被提醒 key 会以明文写进 `.pi/mcp.json`，这样我不会把它提交出去。
39. 作为把 MCP 装到项目的 Pi 用户，我想被提醒它要我在 Pi 里信任这个项目之后才启用：在这个目录下启动 `pi` 时它会问。
40. 作为终端界面的用户，我想确认前看到将要执行的 `pi mcp …` 命令，key 的位置是占位符。
41. 作为用户，我想 Pi 的命令失败时这一项标为失败并说明，别的项照常装。
42. 作为用着没有 `pi mcp` 命令的旧版 Pi 的用户，我想这一项照普通的失败报告，安装器不事先检查 Pi 的版本。

### omp 的 MCP

43. 作为同时选了 omp 和别的宿主的用户，我想 MCP 照旧装进别的宿主；MCP 的状态里不为 omp 另出一栏——它永远装不了，那句说明已经讲了。（2026-10-12 修订：原先是 omp 那一栏每行写「不支持」。）
44. 作为选了 omp 的用户，我想在 MCP 列表旁看到一句说明：安装器装不了 omp 的 MCP，要在 omp 里用 `/mcp add` 添加，这样我知道原因和出路。
45. 作为只选了 omp 的用户，我想所有 MCP 都不可选并带着原因，而不是勾了之后什么都没发生。
46. 作为选了 omp 的用户，我想汇总和结果里没有「装进 omp」的 MCP 行，安装器不执行任何动 omp 配置的命令，也不改写 omp 的配置文件。
47. 作为没选 omp 的用户，我不想看到关于 omp 的 MCP 的那句说明。

### 说明文档与发布

48. 作为读 README 的人，我想看到安装器支持的四个宿主，以及「Pi 和 omp 的 skill 装进共用 skill 目录」「omp 的 MCP 不装」这两件事。
49. 作为读 `cli/README.md`（npm 页面上显示的那一份）的人，我想中英两段都写了这些。
50. 作为维护者，我想版本号升到 0.5.0，发布到 npm 由我自己执行。
51. 作为维护者，我想发布前在虚拟机里用真实的 Pi 和 omp 各走一遍，拿到一份要核对什么的清单。

## Implementation Decisions

### 宿主适配

- 宿主适配多两份，追加在现有两份之后；先后就是界面上的先后：Claude Code、Codex、Pi、omp。
- **Pi**：标识 `pi`，显示名「Pi」；以 `pi` 命令在不在可执行路径上判断在不在。全局的 skill 目录是主目录下的 `.agents/skills`，项目范围的是项目目录下的 `.agents/skills`。交给 skills CLI 的 agent 名是 `pi`，不另带环境变量。
- **Pi 的 MCP**：
  - 用户级配置是配置目录下 `mcp.json` 顶层的 `mcpServers`；配置目录缺省是主目录下的 `.pi/agent`，可由 `PI_CODING_AGENT_DIR` 改到别处。
  - 项目范围的配置是项目目录下的 `.pi/mcp.json`，同样是顶层的 `mcpServers`。
  - 添加：`pi mcp add <名字> [--env <变量>=<值>]… -- <命令> <参数…>`；远程地址的是 `pi mcp add <名字> --url <地址>`。移除：`pi mcp remove <名字>`。项目范围的在两条命令上加 `-l`，并在项目目录下运行。
  - 项目范围的带着「要用户批准之后才启用」的提醒，启动宿主的命令是 `pi`。
  - 不带「添加远程地址的 MCP 时可能当场登录」的提醒：`pi mcp add` 只写配置、不连接服务器。
- **omp**：标识 `omp`，显示名「omp」；以 `omp` 命令在不在可执行路径上判断在不在。两个 skill 目录与 Pi 相同。交给 skills CLI 的 agent 名借用 `pi`（skills CLI 不认识 omp，而 `pi` 落在同一个目录），不另带环境变量。
- **omp 没有 MCP 配置**：宿主的接口现在假定每个宿主都有用户级的 MCP 配置，要改成可以没有。没有的宿主另带一句「在这个宿主里自己添加 MCP 的办法」（omp 的是 `/mcp add`），供界面的说明用。

### MCP 的状态与不可选的原因

- 「不由安装器装 MCP 的宿主」在界面上没有 MCP 的状态可写：两套界面都不为它出 MCP 的状态栏（网页界面是卡片上的那一段），见「四个宿主时的版式」第 1 条。内部仍要和「条目不支持这个宿主」「只能装到全局」分得开，因为说明和不可选的原因不同。
- 列表里 MCP 那几栏的说明多一句，排在「只能装到全局」那一句之后、「读不到配置」那一句之前：所选的宿主里有不由安装器装 MCP 的，且列表里有 MCP 时显示。中文：「安装器装不了 omp 的 MCP：请在 omp 里用 /mcp add 添加」；英文对应。宿主名和添加办法取自宿主适配，不写死在文案里。
- 一个 MCP 在所选的每个宿主下都装不了时不可选，原因照现有的规则定：其中有只是装不到所选范围的，原因是「只能装到全局」；否则是「需要别的 AI Agent」。只选了 omp 时落在后一种。
- 算计划时不为这样的宿主出 MCP 的项。

### 共用 skill 目录

- 算计划时，所选的宿主按「在所选安装范围下的 skill 目录」归组：目录相同的是一组，一组里同一个 skill 只出一项。本仓库的 skill 和第三方 Skill 都这样。
- 一项的宿主那一格写这一组里各宿主的名字，照界面上的先后、用并列的写法连起来（中文「Codex、Pi、omp」）。位置、状态、版本各只有一份。
- 第三方 Skill 的一组只执行一条 skills CLI 命令，agent 名和环境变量取这一组里排在最前的那个宿主的。条目用 `hosts` 限定了宿主时，一组里只算它支持的那些；一个都不支持就不出这一项。
- 覆盖前另问、缺省不覆盖的规则不变，按项问，所以一组只问一次。
- 进度和结果按项报；合计的成功、失败、跳过数按项算。
- 列表里的状态同样按 skill 目录归组，一组一栏（2026-10-12 修订，见「四个宿主时的版式」第 1 条；原先是每个所选的宿主一栏、不合并）。
- 不特别处理 Claude Code 的目录与共用 skill 目录之间的事（omp 两边都读）。

### 共用 skill 目录的说明

- 所选的宿主里至少有一个的 skill 目录是共用 skill 目录、且列表里有本仓库的 skill 或第三方 Skill 时，在列表的说明里显示一句固定的话。中文：「Codex、Pi、omp 共用同一个 skill 文件夹：装给一个，另外两个也看得到」（维护者 2026-10-12 在工单 03 的审查后改短的：原文是「…装给其中一个…」，在终端界面折成两行、第二行只剩两个字；工单 03 里引的仍是原文）；英文对应。三个名字是固定的，不看检测到了哪几个。
- 两套界面都显示：终端界面和 MCP 那几栏的说明打在同一处，这一句排在最前；网页界面随正在看的那张列表的说明发给页面。

### 四个宿主时的版式（维护者 2026-10-12 定的）

工单 04 核对出四个宿主在 80 列的终端和 1280 宽的页面上有五处排不下（排不下的样子记在 `.atw/spec/cli/ui-design.md`、`.atw/spec/cli/web-ui-design.md` 文末「加上 omp 这个宿主之后」，截图在任务目录的 `screenshots/04-*`）。维护者逐处定了，两套界面都算在内：

1. **列表里的状态按 skill 目录归组。**
   - **Skill 和第三方 Skill**：所选的宿主按所选安装范围下的 skill 目录归组（和算计划时是同一种归组），一组一栏。栏名是这一组里各宿主的名字，照界面上的先后并列（「Codex、Pi、omp」，英文 `Codex, Pi, omp`）；状态只写一份。**只要所选的宿主里有两个以上落在同一个目录就合并**，不等到四个都选：选了 Claude Code、Codex、Pi 时是「Claude Code」「Codex、Pi」两栏。第三方 Skill 条目用 `hosts` 限定了宿主时，一组里有它支持的宿主就照目录写状态，一个都不支持才写「不支持」。
   - **MCP**：仍是每个宿主一栏，各看各的配置；**不由安装器装 MCP 的宿主（omp）不出栏**——列表上方那句说明已经讲了原因和出路。只选了 omp 时 MCP 照旧不可选，原因写在状态的位置。
   - **终端界面**：表头那一行写 Skill 的栏。MCP 的栏和它不同时，MCP 那一段的标题行上写它自己的栏名（接在 `── MCP` 后面，和下面的状态对齐），这一段不写说明一栏（说明全文照旧在列表下方）。两者的栏相同时标题行上不另写，和现在一样——只选 Claude Code、选了 Claude Code 和 Codex 都是这种，画面不变。列表里没有 Skill 和第三方 Skill 时，表头直接写 MCP 的栏。四个宿主都选了时的样子（维护者看着选的）：

     ```
        名称                 Claude Code     Codex、Pi、omp   说明
        ── Skill
      □ archify              已装 2.16       已装 2.16        推荐 · 生成架构图…
      □ explanation          0.9.0 → 1.0.0   已装 1.0.0       推荐 · 把任何内容…
      □ pr                   非本工具安装    未装             推荐 · 撰写 PR（…
        ── MCP               Claude Code     Codex        Pi
     ▸□ markitdown           未配置          未配置       已配置
      □ excel                已配置          不支持       不支持
      □ mistral-ocr          未配置          未配置       未配置
     ```

   - **网页界面**：卡片底部的状态同样——Skill 和第三方 Skill（连同含多个 skill 的条目里各个 skill 的小格）一组一段（「Claude Code 已装 2.16　Codex、Pi、omp 已装 2.16」），MCP 是每个装得了 MCP 的宿主一段、没有 omp 的那一段。
   - 汇总、进度、结果不变：工单 03 起已经是一组一行。
2. **没检测到的宿主合成一句。** 终端界面本机信息里「AI Agent」那一行、网页界面左栏的本机信息、网页界面只检测到一个宿主时顶上和开场引导里写在旁边的那几个：检测到的照旧各写各的（名字加 `✓`），排在前面；没检测到的把名字并列起来、后面只写一次「未检测到」（「Codex、Pi、omp – 未检测到」，英文 `Codex, Pi, omp – not detected`），排在后面。只有一个没检测到时就是它一个名字。
3. **网页界面的开场引导：宿主的勾选放不下时整组到下一行。** 勾选在提问的旁边排不下时，几个勾选一起排到提问的下一行，不让最后一个单独掉下去；排得下时（两个、三个宿主）和现在一样。
4. **终端界面的汇总：位置放不下时另起一行。** 一行连「位置」一栏超出第 79 列时，位置这一格另起一行写整条路径，不截断、不从中间折开；放得下的行和现在一样。中英文都这样。这同时了结工单 01 时记为已知问题的那一处（英文界面里长路径被终端折断）。另起的那一行缩进到哪、和已有的「备注另起一行」怎么并排，由实现者照现有先例定，出预览留到验收时给维护者看。
5. **网页界面的汇总：宿主那一格加宽**到中文「Codex、Pi、omp」一行放得下（现在的栏宽 96px，它要 103px 上下），1280 和 1024 两种窗口下都不折行、不截断。

### 其余

- 检测、选择宿主的流程不改：只检测到一个时不问；开场引导和页面顶上的宿主勾选照现有规则带缺省。说明没检测到哪些、组件只装进哪些的那两句文案已经按名字列表写，四个宿主时照用。
- 目录文件的格式不改。条目的 `hosts` 字段现在可以写 `pi`、`omp`。
- 更新 `README.md`、`cli/README.md`（中英各一段），以及 `.atw/spec/cli/` 下讲宿主、skill 安装、MCP 安装的几份规范。
- `cli/` 的版本号升到 0.5.0。

## Testing Decisions

- 好的测试只看外部行为：终端上打出了什么、页面收到了什么画面状态、主目录和项目目录下落了什么文件、执行了哪些外部命令（命令、参数、环境变量、运行目录）。不测内部怎么归组、类型长什么样。
- 接缝用现有的那一个：安装器的入口，由测试工具喂进假的主目录、假的可执行路径（放上空的 `pi`、`omp` 文件就算检测到）、假的外部命令执行器和预先排好的回答。网页界面用现有的页面测试工具走同一个入口。不新增接缝。
- 要覆盖的行为：
  - 只检测到 Pi、只检测到 omp、四个都检测到时的宿主行和说明。
  - Pi、omp 下 skill 装到全局和项目的位置。
  - 共用 skill 目录上只装一次、汇总和结果合成一行、合计数、只问一次覆盖。
  - Claude Code 与共用 skill 目录各一行。
  - 第三方 Skill 给 Pi、给 omp、给一组时执行的那一条命令。
  - 共用 skill 目录那句说明出现和不出现的条件。
  - Pi 的 MCP：全局和项目的添加、移除命令，状态探测（含 `PI_CODING_AGENT_DIR`、读不了的配置），带 key 的参数，项目范围的两条提醒。
  - omp 的 MCP：栏里「不支持」、说明、只选 omp 时不可选、不执行任何 `omp` 命令、不写 omp 的配置文件。
  - 中英文案各一遍。
- 参照现有的测试：宿主检测与装进 Codex 的那一组、安装范围的那一组、MCP 与带 key 的 MCP 的那两组、第三方 Skill 的那一组、列宽的那一组，以及网页界面对应的几组（开场引导、装到哪里、MCP、第三方 Skill、安装）。
- 现有测试里凡是选了 Codex 的，列表上会多出共用 skill 目录的那句说明，要跟着改期望。
- 测试在本机当前的 Node 和最低支持的 Node 22.13 上各跑一遍；另用 `TMPDIR=/tmp` 跑一遍，提前重现 CI 上 Linux 的短临时目录。
- 不在本机用真实的 Pi 和 omp 验证：会改宿主的真实配置。真机走查由维护者在虚拟机里做。

## Acceptance Criteria

- [ ] 可执行路径上有 `pi` 时安装器检测到 Pi，有 `omp` 时检测到 omp；界面上的先后是 Claude Code、Codex、Pi、omp。
- [ ] 只检测到 Pi 或只检测到 omp 时，本仓库的 skill 能装到全局和项目，位置分别是主目录和项目目录下的 `.agents/skills`。
- [ ] 第三方 Skill 能装给 Pi 和 omp；执行的 skills CLI 命令里 agent 名是 `pi`。
- [ ] 所选的宿主里有几个共用同一个 skill 目录时，同一个 skill 只装一次（本仓库的只写一次、第三方的只执行一条命令），汇总、进度、结果各一行，宿主那一格列出这几个名字；合计数按行算；覆盖只问一次。
- [ ] 所选的宿主里有 Codex、Pi、omp 之一且列表里有 skill 或第三方 Skill 时，两套界面都显示共用 skill 目录的那句说明；只选 Claude Code 时不显示。
- [ ] Pi 的 MCP 能装到全局和项目：执行的是 `pi mcp add`（项目加 `-l`、在项目目录下运行），状态看的是对应的那份 `mcp.json`，`PI_CODING_AGENT_DIR` 生效。
- [ ] 把 MCP 装到项目的 Pi：带 key 时提醒明文写进 `.pi/mcp.json`；提醒要在这个目录下启动 `pi` 并批准之后才启用。
- [ ] omp 的 MCP：两套界面都不为 omp 出 MCP 的状态栏；选了 omp 且列表里有 MCP 时显示那句说明；只选 omp 时 MCP 都不可选；任何情况下安装器不执行 `omp` 命令、不读写 omp 的配置文件。

- [ ] 本机信息里没检测到的宿主合成一句（两套界面）；网页界面的开场引导里勾选放不下时整组到下一行；终端界面的汇总里位置放不下时另起一行；网页界面的汇总里宿主那一格放得下「Codex、Pi、omp」。
- [ ] 终端界面 80 列下，四个宿主都选了、只检测到其中一个、一个都没检测到这几种情形，中英文都没有一行超出第 79 列被终端折断（呈现层照规矩折的说明、提醒、命令、原因不算）。
- [ ] 只选 Claude Code、或只检测到 Claude Code 时，两套界面的画面和落下的文件与改动前一样（写别的宿主没检测到的那几处除外）；网页界面顶上那一条不比改动前多出一行。
- [ ] 中英文案齐全。
- [ ] `README.md`、`cli/README.md`、`.atw/spec/cli/` 下相关的规范已更新；`GLOSSARY.md` 和 ADR-0005 已在访谈时写好，与实现一致。

## Further Notes

以下是写 spec 时顺着推的，维护者没有逐条确认：

1. **只选 omp 时 MCP 一行上的原因写「需要别的 AI Agent」**，不是那句完整的说明：行上只放得下一个短词，完整的那一句在列表的说明里。维护者的原话是「原因同样写这一句」。
2. **共用 skill 目录的说明只在列表里有 skill 或第三方 Skill 时显示**：只有 MCP、工具、外部项目的列表里它无关。
3. **原来只用 Codex 的用户也会看到这句说明**，里面提到他没装的 Pi 和 omp。这是照「三个里至少勾了一个就显示、三个名字固定」定的。
4. **选了 omp 的用户在终端界面会看到命令里写着 `--agent pi`**。这是借名的结果，不另加解释。
5. **合计数按项算**：同时选了 Codex、Pi、omp 时，一个 skill 在合计里算 1 项，不是 3 项。
6. **终端界面四栏状态在 80 列下排得下**是要在实现时核对的：现有的列宽是按所选的宿主算的，栏多了说明那一栏会变窄甚至不显示。排不下时回到 specify 改。——**2026-10-12 核对出来排不下，已经回到 specify 改了**，见「四个宿主时的版式」；这一条不再是没确认的推断。新版式里还没有实际量过、要在实现时核对的：英文界面下 MCP 三栏连名称放不放得下；合成一句之后只检测到 Claude Code 时网页界面顶上那一条是不是回到一行。仍排不下时照旧停下来报告。
7. **没有实际运行验证、要进虚拟机走查清单的**：
   - 没装 Pi、只装了 omp 的机器上，`npx skills add … --agent pi` 仍把 skill 装进 `.agents/skills`。
   - omp 读得到共用 skill 目录里的 skill；同时有 Claude Code 的同名 skill 时它只用一份、不报错。
   - Pi 读得到共用 skill 目录里的 skill。
   - `pi mcp add` 和 `pi mcp remove`，全局的和带 `-l` 的，带 `--env` 的；装到项目后启动 `pi` 时它确实问要不要信任。
   - Windows 上 `pi` 命令能不经 shell 起来（它是 npm 装的命令）。
8. **规范文档**：`.atw/spec/cli/` 下的更新在实现的最后做，和代码一起提交。
