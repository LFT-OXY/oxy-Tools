# 15 — 左栏的用途列表加高，当前的用途更显眼

**What to build:** 左栏的用途列表每一行高一些，不显得挤、好点中；当前的用途一眼看得出来。维护者验收时（2026-10-12）在真实的页面上看到的：每行约 30px、显得小；当前的用途只是 `#F2F2F2` 压在侧栏底色 `#FAFAFA` 上，分辨不出。原话和现状见 `research/acceptance-feedback.md` 第 2 节，定下的画法见 `prd.md`「UI and Design」的「左栏的用途列表」。这一张只动左栏的用途列表：左栏的宽度、字号、本机信息、切换语言、「推荐」下面那条线，选中的卡片和分段控件里选中的那一格，都不动。

**Blocked by:** None — can start immediately
**Status:** ready-for-agent
**Impl:** doing

- [ ] 先改规范：网页界面的设计规范里，颜色表加一个只给当前的用途用的底色（深色、浅色各一个值，写明它和侧栏底色的对比度），「抬一档的底色」的用处里去掉「当前的用途」；左栏版式那一条写上每行的高和当前的用途的新画法。
- [ ] 用途名只占一行的行不低于 36px 高；字号不变（13px）；用途名折成两行的行跟着高，条目数照旧留在第一行的右边。
- [ ] 当前的用途用那个更深一档的灰底，字照旧是前景色、粗一档。它的底色和侧栏底色的对比度在深色、浅色下都不低于 1.15:1（起点：浅色 `#E6E6E6`、深色 `#26282C`；照真实的画面调，调了就把数写回规范）。不用前景色的底加反白的字，不加竖线。
- [ ] 鼠标移上去、键盘焦点的画法照旧，和当前的用途分得开（焦点仍是那一圈前景色的描边）。
- [ ] 网页界面的预览重新生成：87 格都过脚本自己的检查（两种窗口下没有放不下的地方）。1024×768、英文界面下左栏的十个用途、本机信息和切换语言照旧够得着——放不下时左栏自己滚动，不把哪一样裁掉。
- [ ] 量一遍并记下：当前的用途那一行的高、它的底色和侧栏底色在深色与浅色下的对比度。
- [ ] UI: 浏览 / 条目最多的用途、两个宿主 / 1280×800，深色与浅色 — 用途名只占一行的行不低于 36px；当前的用途不放大也认得出是哪一行。
- [ ] UI: 浏览 / 英文界面 / 1024×768，深色与浅色 — 用途名折成两行的行排得齐，条目数在第一行右边；左栏最下面的本机信息和切换语言看得到或滚得到。
- [ ] 把上面几格的截图拿给维护者看：`prd.md` 的验收标准写的是「维护者在真实的页面上看过，认可行高和当前的用途的样子」。他没有认可之前这一条不打勾，工单里如实写。
- [ ] 类型检查和全部测试通过；测试在 Node 22.13 上也跑过一遍。
