# 02 — 预备：把两套界面共用的部分从终端的流程里分出来

**What to build:** 终端界面的交互流程里现在写在一起的三件事分开：逐步提问（终端界面独有）、把勾选算成要装的每一项、逐项执行并报告进度。后两样，连同「推荐和各个用途里有什么、怎么排」「每个条目可不可选、原因是什么」，成为不依赖提问器和呈现层的共用部分，终端界面改为经它们走。用户看不到任何变化。

**Blocked by:** None
**Status:** ready-for-agent
**Impl:** done

- [x] 先改规范：CLI 层总览里写明多出来的这几块各管什么、终端界面怎么用它们。
- [x] 「算计划」只要目录、所选的宿主、安装范围、勾选（含第三方 Skill 里挑了哪几个 skill）和填过的 key 的变量名，就给出要装的每一项：每个组件在每个宿主下一项，连同位置、状态、将执行的命令、要不要另问覆盖、缺哪个必填的 key。它不提问、不往终端上打东西。
- [x] 「执行」只要计划和一个进度的接收方，就照现在的先后逐项去装（本仓库的 skill、第三方 Skill、MCP、工具），每一项的开始、结局、跳过都报给接收方。终端界面的接收方是现在的呈现层。
- [x] 「列表里有什么、怎么排」「每个条目在所选宿主和安装范围下的状态、可不可选与原因」也是不依赖提问器的共用部分。
- [x] key 的规矩不变：值只在内存里，只交给安装动作，不进计划、不进进度的报告。
- [x] 终端界面对外的行为一点不变：`cli/test/` 下现有的测试**一条都不改**，全部通过。
- [x] 界面预览页重新生成，和改之前逐格相同（还原成纯文本后比较）。
- [x] 不为共用的部分单独写测试：它们经入口被测到。
- [x] 类型检查和全部测试通过；测试在 Node 22.13 上也跑过一遍。
