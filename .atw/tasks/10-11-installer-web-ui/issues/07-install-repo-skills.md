# 07 — 在网页界面里装本仓库的 skill

**What to build:** 第一条完整的线。用户在不同用途下勾选本仓库的 skill，已选的一直看得见、可以当场去掉；去汇总，看到将安装的每一项（装进哪个宿主、什么位置、是新装、更新还是覆盖），不是本工具装的目录逐项决定覆盖不覆盖；确认后在页面上看每一项的进度和结果；装完可以接着挑下一批，状态已经是新的。装的结果和用终端界面装出来的一样。宿主仍是检测到的全部、安装范围仍是全局。

**Blocked by:** 05
**Status:** ready-for-agent
**Impl:** done

- [x] 先改规范：网页界面的契约补上勾选、已选、汇总、确认、进度、结果、继续挑选的意图和画面状态，以及「展示的和执行的是同一份」怎么保证。
- [x] 勾选是意图，状态在安装器这边：换用途时之前勾的还在；一个条目同时在「推荐」和它的用途下时，一处勾了另一处也是勾上的；不可选的条目勾不上（意图被拒绝）。
- [x] 页面上一直看得到已选了哪些、一共几个，能在那里直接去掉某一个；已选为空时去不了汇总。
- [x] 汇总经共用的「算计划」得出：每个 skill 在每个宿主下一项，带位置、版本与状态；有会覆盖的就有那句提醒。
- [x] 不是本工具装的目录在汇总里逐项决定，缺省不覆盖；没同意的那些不装，结果里写明跳过。
- [x] 汇总带一个标识，确认安装时要带回它。确认前安装器重新探测一遍：和汇总时不一样就不装，改发新的汇总；带着旧标识的确认不装。
- [x] 汇总上能返回修改，勾选还在。
- [x] 安装经共用的「执行」，进度推给页面：等待、正在装、装好了、没装上、跳过。一项失败不影响其余，失败的写明原因和下一步，用的是和终端界面同一套说法。
- [x] 向 GitHub 查询失败：页面上有出错说明，本仓库的 skill 一个都不装，安装器不退出。
- [x] 结果里有合计。继续挑选：回到浏览，状态重新探测过，已选清空。单项失败不改变退出状态。
- [x] 页面只发条目的名字和选项；意图里带了命令、路径之类的东西一律不认。
- [x] 经主接缝的新增测试：跨两个用途各勾一个，一次装上，主目录里的东西与终端界面装出来的一样；更新与覆盖的状态；非本工具安装的缺省不覆盖 / 同意后覆盖；旧标识的确认不装；汇总之后状态变了不装；一项失败其余照常；向 GitHub 查询失败；继续挑选后状态是新的；勾不上不可选的条目；换语言后勾选不变。
- [x] 预览里加上：已选了几个的浏览、汇总（含要逐项决定的覆盖）、安装中、全部装好的结果、有没装上的结果、向 GitHub 查询失败。
- [x] UI: 浏览 / 已选了几个 / 1280×800 与 1024×768 — 已选的数量和去汇总的按钮都在屏幕上，不用滚动去找。
- [x] UI: 汇总 / 有要逐项决定的覆盖 / 1280×800 — 每一项装到哪、是新装还是覆盖看得清；覆盖的那几项缺省没有勾。
- [x] UI: 安装中、结果 / 有没装上的 / 1280×800 — 每一项的结局一眼看得出，没装上的带着原因和下一步。
- [x] 类型检查和全部测试通过；测试在 Node 22.13 上也跑过一遍。
