# 10 — 在网页界面里装 MCP、填 key

**What to build:** MCP 可以和别的组件一起勾选、一起装。要 key 的 MCP 在页面上填：每个变量写明是做什么用的、必填还是可选、去哪申请，输入框不显示内容；同一次运行里填过的不用再填。汇总里看得到各种提醒（不列将执行的命令）。填的 key 不出现在页面的任何别处、终端、网址和任何答复里。装到项目时 Codex 的 MCP 不可选并写明只能装到全局。

**Blocked by:** 08
**Status:** ready-for-agent
**Impl:** ready

- [ ] 先改规范：网页界面的契约补上填 key 的意图和「填了没有」的画面状态；安装 MCP 的规范里「key 的值不许去的地方」加上网页界面的几处（网址、答复、画面状态、浏览器的记忆）。
- [ ] 状态每个所选宿主一个（未配置、已配置、未知、不支持），写法不变；宿主的配置读不了时的提示页面上也有。
- [ ] 安装范围选了项目，而所选的宿主里支持它的都只能把 MCP 装到全局：不可选，原因是「只能装到全局」；有项目范围配置的宿主装进项目目录里的那一份。
- [ ] 勾了要 key 的 MCP：页面上逐个变量给出说明、必填还是可选、申请链接（新标签页打开）。输入框不显示内容，不让浏览器记住或自动填。
- [ ] key 的值只经请求的正文传给安装器；之后的画面状态里只有「填了没有」。同一次运行里填过的写明「已填」，可以换一个；继续挑选下一批时不用再填。
- [ ] 必填的没填：页面写明这个 MCP 不会装，汇总里不算它，其余照常；可选的没填就不带。
- [ ] 汇总里不列将执行的命令，画面状态里也没有（维护者 2026-10-11 定的）；执行的命令和终端界面一样。提醒齐全（「key 以占位符显示」那一条随命令一起没有了）：key 会以明文写进项目里的哪个文件（说变量名和文件，不说值）、哪个宿主要另行批准才启用、哪个宿主会当场打开浏览器登录、哪个 MCP 因为缺 key 不装。
- [ ] 执行在第三方 Skill 之后；已配置的、状态未知的怎么装不变；失败的写法不变，原因里没有 key 的值。
- [ ] 经主接缝的新增测试：本地进程的、远程地址的、带 key 的各一条正常路径；必填的没填；可选的没填；同一次运行里第二批不再要求填；换一个 key；Codex 装到项目不可选及原因；装到项目的命令与运行目录；每种提醒各一条；命令非零退出；**填的值不出现在任何答复、画面状态、终端输出、交给链接打开器的网址里**（整份都查）；换语言后填过的 key 还在。
- [ ] 预览里加上：填 key（没填、已填、必填的没填）、带各种提醒的汇总。生成之后在生成物里搜假装填的那个值，一处都没有。
- [ ] UI: 填 key / 必填与可选各一个、一个已填 / 1280×800 — 每个变量的说明、必填还是可选、申请链接都看得到；已填的只显示「已填」，看不出长度。
- [ ] UI: 汇总 / 带 key 的 MCP、装到项目 / 1280×800 — 没有将执行的命令；明文与批准的提醒看得到。
- [ ] 类型检查和全部测试通过；测试在 Node 22.13 上也跑过一遍。
- [ ] 工单 08 留下的：已选里「现在装不了」的机制（`SelectedView.unavailable`、不进汇总、改回去恢复、一个会装的都没有时去不了汇总）现在只认本仓库的 skill（`web-ui.ts` 的 `unavailableOf`、`installable`）；这一类勾得上之后要把它泛化到这一类，并补上工单 08 没法做的测试、预览和截图（已选里有现在装不了的）。
