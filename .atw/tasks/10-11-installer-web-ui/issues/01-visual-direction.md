# 01 — 定下网页界面的样子

**What to build:** 维护者在一张对比页上看到网页界面的几种视觉方向，选定一种；选定的方向记进任务目录的 `ui-direction.md`，写成网页界面的设计规范，`prd.md` 的「UI and Design」随之补全，后面每一张改页面的工单都照它实现。这一张不改安装器的行为。

**Blocked by:** None
**Status:** ready-for-agent
**Impl:** done

- [x] 对比页至少给出两种真正不同的方向（信息怎么组织、条目是卡片还是行、已选放在哪），不是同一种方向换个配色。
- [x] 每种方向都画出这几个画面：浏览与挑选（两个宿主、有不可选的条目、已选了几个）、填 key、汇总（有要逐项决定的覆盖、有提醒）、安装中、结果（有没装上的）。（原先还要求汇总「有命令」；维护者 2026-10-11 选方向时定下网页界面的汇总不列将执行的命令。）
- [x] 拿最坏的内容排，不只拿好看的样例：目录里最长的条目名、条目最多的用途（20 条）、外部项目最多的用途、两个宿主都带版本的状态、一条长链接。内容取自仓库真实的目录。（原先还有「一条长命令」；汇总不列命令之后没有地方排它，改看最长的安装位置折不折得开。）
- [x] 中文、英文各排一遍；深色、浅色各一份；1280×800 和 1024×768 各看一遍。
- [x] 沿用 OXY 像素风大标志的形状；状态的词沿用界面设计规范里「状态的写法」。（原先要求沿用大标志的渐变和洋红的焦点色；维护者 2026-10-11 选方向时改定：网页界面里不用紫色，大标志是单色的，按钮和选中用黑白。）
- [x] 交给维护者选时把每种方向的代价说全（哪种状态下会挤、条目再多时怎么办）。
- [x] 维护者看过并选定。选定的方向、没选的候选和原因、维护者说的喜欢与不喜欢，记在任务目录的 `ui-direction.md`。
- [x] 另立一份网页界面的设计规范：颜色与含义、字号与间距、各个画面的版式要点、深浅色、不可选与出错的画法、放不下时的退路。`prd.md` 的「UI and Design」按选定的方向补全。
- [x] 界面设计规范（现有的那份）开头写明它只管终端界面，「不做全屏界面、不为好看自写交互控件」两处随之改写。
- [x] 对比页是一次性的，不提交进仓库；要留的只有任务目录里的 `ui-direction.md` 和截图。
- [x] UI: 浏览与挑选 / 条目最多的用途、两个宿主 / 1280×800，深色与浅色 — 每条说明完整，没有一处「…」；外部项目和组件一眼分得开，外部项目上没有勾选框；已选的数量和去汇总的按钮都在屏幕上。
- [x] UI: 浏览与挑选 / 同上 / 1024×768 — 没有横向滚动条，去汇总的按钮看得见。
- [x] UI: 汇总 / 有要逐项决定的覆盖、有提醒 / 1280×800 — 没有将执行的命令；要逐项决定的覆盖就在它那一行下面，缺省不勾。（截图里摆成一条勾了、一条没勾，为了两种样子都看得到。原先是「命令整条看得到」，随维护者 2026-10-11 的决定改写。）
- [x] UI: 开场动画 / 进行中的定格 / 1280×800 — 敲出的命令、一行行打出来的单色大标志看得到。（维护者 2026-10-11 加的要求。）
