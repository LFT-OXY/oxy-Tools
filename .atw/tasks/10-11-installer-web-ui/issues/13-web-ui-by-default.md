## Comments

### 2026-10-12 实现记录

**手动核对。** 打包好的安装器（`node dist/bin.js`，macOS，Node 24.15）放在伪终端里跑，`PATH` 上是一个假的 `open`（只把收到的网址记进文件，不弹浏览器），主目录和宿主的配置目录都指到临时目录：

| 怎么运行 | 结果 |
|----------|------|
| 不带参数 | 假的 `open` 收到一个 `http://127.0.0.1:<端口>/?token=…` 的网址；终端上有「已在浏览器打开」，没有语言提问；Ctrl+C 以 130 退出 |
| 环境里有 `SSH_CONNECTION` | 没有调用 `open`；大标志之后直接是语言提问；没有多出任何说明 |
| 环境里只有 `SSH_TTY` | 同上 |
| `--terminal` | 同上 |
| `SSH_CONNECTION` 加 `OXY_TOOLS_WEB=1` | 同上：那个变量不再起作用 |
| `--help` | 「选项」里有 `--terminal` 那一行；没有调用 `open`；以 0 退出 |

没有做的：让真实的默认浏览器弹出来（真实的 `open` 那一支是工单 03 核对过的，这次没有动它）；真的从另一台机器经 `ssh` 连进来运行（这里是给环境变量造出来的）；Windows 和 Linux 上的真机。

**实现时定下、维护者没有确认的：**

1. 「现有的测试一条都不改」和「`OXY_TOOLS_WEB` 拿掉」对五条用例不能同时成立：`web-ui.test.ts` 四条、`web-lifecycle.test.ts` 一条是本任务工单 03、11 加的，靠那个开关在没有页面脚本的情况下进网页界面。做法是把它们的那一个参数换成架子新加的 `web: true`（另有一条的标题从「不带临时开关」改成「架子缺省带着 --terminal」），断言都没动。没有选的做法：让架子继续认 `env` 里的 `OXY_TOOLS_WEB`——字面上一条都不用改，但测试里会一直留着一个产品已经不认的变量名。`prd.md` 的「Testing Decisions」里记了这件事。
2. 帮助里 `--lang` 那一行仍是「界面语言；缺省时启动后询问」。缺省改成网页界面之后这句话只对终端界面成立（网页界面不在终端上问语言）。工单没有要求改它，改它要动一条现有的测试和包的 README，所以没有动；记在界面设计规范末尾，等维护者定，或并进工单 14 的文档核对。
3. `cli/README.md` 的选项表里还没有 `--terminal`：两份 README 归工单 14。
4. 架子新加的 `web: true` 在环境变量里放的是 `DISPLAY=:0`（架子的平台缺省是 `linux`）；用例在 `env` 里给的盖过它。
