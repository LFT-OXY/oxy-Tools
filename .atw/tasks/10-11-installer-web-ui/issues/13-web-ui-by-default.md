# 13 — 缺省改成网页界面

**What to build:** 不带任何开关运行安装器，打开的就是网页界面。远程连接、没有桌面的机器上自动用终端界面；`--terminal` 强制用终端界面。开发期间的临时开关拿掉。

**Blocked by:** 06, 09, 10, 12
**Status:** ready-for-agent
**Impl:** ready

- [ ] 先改规范：入口与测试（启动顺序、启动参数表加 `--terminal`、环境变量表加判断用到的那几个、拿掉临时开关、用哪个界面的判断先后）；帮助的文字。
- [ ] 用终端界面的情形，按这个先后判断：给了 `--terminal`；`SSH_CONNECTION`、`SSH_TTY`、`SSH_CLIENT` 任一非空；系统不是 macOS 也不是 Windows 且 `DISPLAY` 和 `WAYLAND_DISPLAY` 都为空。都不是就用网页界面。判断只看入口收到的环境变量和平台。
- [ ] 这三种情形下直接是终端界面：没有调用链接打开器，没有起本机的网页，照旧问语言；终端上不为此多说一句。
- [ ] 进入网页界面之后才知道的两种（网页起不来、链接打开器拒绝）照工单 03 的做法。
- [ ] `--help` 里有 `--terminal` 和一句说明（中英）；`--help`、`--version`、参数有误、没有交互式终端这四种情况和现在一样，不打开浏览器。
- [ ] 环境变量 `OXY_TOOLS_WEB` 拿掉：设了它不再有任何作用。
- [ ] 测试架子缺省仍走终端界面（由架子带上 `--terminal`），现有的测试一条都不改；给了页面脚本的走网页界面。
- [ ] 经主接缝的新增测试：有桌面的 macOS、Windows、带 `DISPLAY` 的 Linux 上不带参数——打开了网页界面、没有语言提问；三个远程连接的变量各一条；没有 `DISPLAY` 和 `WAYLAND_DISPLAY` 的 Linux；只有 `WAYLAND_DISPLAY` 的 Linux 用网页界面；`--terminal`；`--terminal` 与 `--lang` 同给；`--help` 的输出。
- [ ] 界面预览页（终端的）的帮助那一格跟着更新。
- [ ] 手动核对（记进工单的评论）：在有桌面的 macOS 上不带参数运行，默认浏览器打开网页界面；经远程连接运行，直接是终端界面。
- [ ] 类型检查和全部测试通过；测试在 Node 22.13 上也跑过一遍。
