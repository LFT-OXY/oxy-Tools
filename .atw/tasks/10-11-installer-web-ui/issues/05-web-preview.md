# 05 — 网页界面的预览

**What to build:** 维护者运行一条命令，得到网页界面的预览：每个要看的状态一格，深色、浅色各一份，画面是真实的页面在真实的浏览器里渲染出来的。之后每一张改页面的工单都往里加格子，改完对着网页界面的设计规范看一遍。它是仅供开发的脚本，不随 npm 包发布。

**Blocked by:** 04
**Status:** ready-for-agent
**Impl:** doing

- [ ] 先改规范：网页界面的设计规范里写明预览怎么生成、怎么用、场景怎么写，以及「改了页面就生成并看一遍、加了状态就加场景」的规矩。
- [ ] 每个场景经安装器入口把安装器驱动到某个状态（样例目录、临时的主目录和项目目录、假的外部命令执行器），页面在真实的浏览器里渲染后拍下来。预览从不碰真实的主目录和网络，不真的执行命令。
- [ ] 用什么驱动真实的浏览器在这一张里定，写进规范并写明理由；它只是开发依赖或开发机上的工具，不进 npm 包，不进 CI。
- [ ] 生成物不提交，不随 npm 包发布；脚本不引用 `cli/` 以外的文件。
- [ ] 每格拍 1280×800，深色、浅色各一份；另能指定 1024×768 拍同一个场景。
- [ ] 已有的状态都有场景：骨架的几种结束状态（已完成、安装器已退出、口令不对）、浏览（一个宿主、两个宿主、一个都没有、有不可选的条目、用途下只有外部项目、条目最多的用途），中文与英文。
- [ ] 样例里有一条长名字、一条长说明、一条长链接。
- [ ] 带 key 的场景（工单 10 加）生成之后，在生成物里搜假装填的那个值，应当一处都没有——这条规矩先写进规范。
- [ ] 终端界面的预览页照旧生成，两条命令互不影响。
- [ ] 类型检查和全部测试通过。
