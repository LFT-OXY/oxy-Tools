## Problem Statement

用户运行安装器，进入一个用途，看到的是一张挤在 80 列终端里的表：Skill、第三方 Skill、MCP、外部项目排在一起，每条说明都被截成「…」，表的上方还压着已回答的三行提问和一条提醒，下方又是类型、说明全文和按键提示。维护者自己看了都觉得密密麻麻、看不过来。

- **终端排不开。** 一行只有 80 列，名字、每个宿主的状态、说明要分着用；说明只能截断，完整的那一句要把光标移到那一行才看得到。
- **目录的大头是只能看的东西。** 110 个条目里 64 个是外部项目（2026-10-11），它们只有说明和链接。终端里的链接点不了，说明又被截断，而它们和能装的组件混在同一张勾选表里。
- **一次只能看一个用途。** 想装的东西分在几个用途下，就得进去、装完、回主菜单、再进下一个，每次重答一遍「装进哪些 AI Agent」「装到哪里」。

## Solution

- 运行安装器，它在本机起一个只有这台机器能访问的网页，并用默认浏览器打开。挑选、看汇总、确认、看安装进度和结果，都在这一页里完成。
- **一页到底**：用途、条目、「装进哪些 AI Agent」「装到哪里」同时在页面上，随时能改；已选的条目一直看得见；可以跨用途一起挑，一次确认、一次装完。说明不截断，外部项目的链接可以直接点。
- **终端界面留着当退路**：远程连接、没有桌面、浏览器打不开时，安装器自动用原来的终端界面；用户也可以用一个启动参数强制用它，或在网页界面开着时按一个键切过去。终端界面的画面和行为这次不改。
- 装的东西、装的方式两套界面完全一样：变的只是在哪里挑、在哪里看。只有一处有意不同——网页界面的汇总不把将执行的命令列给用户看，终端界面照旧列。

## User Stories

### 启动与退路

1. 作为用户，我想运行安装器后浏览器自动打开网页界面，这样我不用在终端里读表。
2. 作为用户，我想终端里留着一行说明——网页界面已在浏览器打开、它的网址、怎么改用终端界面——这样浏览器没有弹出来时我知道该怎么办。
3. 作为用户，我想目录读不了时在终端里就看到出错说明，浏览器不被打开，这样不会对着一张空白的网页。
4. 作为远程连接到服务器的用户，我想安装器自动用终端界面，这样不会在一台我看不到屏幕的机器上打开浏览器。
5. 作为在没有桌面的 Linux 上运行的用户，我想安装器自动用终端界面。
6. 作为用户，我想浏览器打不开或本机的网页起不来时，安装器说明一句原因然后改用终端界面，而不是退出。
7. 作为用户，我想用一个启动参数强制用终端界面，这样自动判断错了的时候我有办法。
8. 作为用户，我想网页界面开着、还没开始安装时，在终端里按一个键就改用终端界面，这样浏览器开在了别处或我改了主意时不用重新运行。
9. 作为用户，我想改用终端界面之后网页上写明「已改用终端界面，请回到终端」，这样我不会继续在一张失效的页面上操作。
10. 作为用户，我想 `--help`、`--version`、参数有误、没有交互式终端这四种情况和现在一样，不打开浏览器。

### 找条目

11. 作为用户，我想页面上一直看得到「推荐」和各个用途，每个旁边写着条目数，这样我随时能换一个用途看。
12. 作为第一次用的用户，我想打开页面时看到的是「推荐」（它里面有条目时），这样我知道先装什么。
13. 作为用户，我想没有条目的用途不出现。
14. 作为用户，我想一个用途下的组件按类型分开（Skill、第三方 Skill、MCP、工具），这样我知道勾了它会发生什么。
15. 作为用户，我想第三方 Skill 看得出内容直接来自作者，不是维护者检查过的那一份。
16. 作为用户，我想每个条目的说明完整显示，不被截断。
17. 作为用户，我想带推荐标记的条目看得出来，并排在同类的前面。
18. 作为用户，我想外部项目和能装的组件分开显示，并写明只给链接、不安装，这样我不会以为勾了它就会装上。
19. 作为用户，我想点外部项目的链接就在新的标签页里打开，安装器的页面留在原处。
20. 作为用户，我想页面上看得到本机检测到了哪些宿主、目录里有多少条目，以及目录里有几个条目因为格式有误被跳过。

### 宿主与安装范围

21. 作为检测到两个宿主的用户，我想在页面上勾选装进哪些宿主，改了之后每个条目的状态马上跟着变。
22. 作为只检测到一个宿主的用户，我想页面直接写明装进它，不让我选。
23. 作为用户，我想在页面上选装到全局还是项目，缺省全局，项目那一项写着是哪个目录。
24. 作为用户，我想改了宿主或安装范围之后已选的条目还在，其中变得装不了的留在已选里并写明原因，不算进将安装的项。
25. 作为一个宿主都没检测到的用户，我想照样能逛目录、点外部项目的链接，组件都写明「需要 AI Agent」。

### 状态与不可选

26. 作为用户，我想每个组件在每个所选宿主下的状态都写出来（未装、已装的版本、可更新、非本工具安装、已配置、不支持……），用的词和终端界面一样。
27. 作为用户，我想装不了的组件勾不上，并当场看得到原因（需要 AI Agent、需要别的 AI Agent、只能装到全局、不支持当前系统）。
28. 作为用户，我想状态是现查的：打开页面、改了宿主或安装范围、装完一批之后都重新查。

### 挑选

29. 作为用户，我想在不同用途下勾选条目，换用途时之前勾的还在。
30. 作为用户，我想页面上一直看得到已选了哪些条目、一共几个，并能在那里直接去掉某一个。
31. 作为用户，我想含多个 skill 的第三方 Skill 让我当场挑要其中哪几个，一个都不挑就是不装它。
32. 作为用户，我想一个条目同时在「推荐」和它的用途下出现时，在一处勾了另一处也是勾上的。

### 填 key

33. 作为用户，我想勾了要 key 的 MCP 之后在页面上填，每个变量写明是做什么用的、必填还是可选、去哪申请（链接可点）。
34. 作为用户，我想填 key 的输入框不显示内容。
35. 作为用户，我想必填的 key 没填时，页面写明这个 MCP 不会装，其余的照常装。
36. 作为用户，我想同一次运行里填过的 key 不用再填，页面写明「已填」，并且可以换一个。
37. 作为用户，我想我填的 key 不出现在页面的任何别处、终端上、网址里，也不被浏览器记下来。

### 汇总与确认

38. 作为用户，我想开始安装之前看到汇总：将安装哪些组件、各装进哪个宿主、装到什么位置、是新装、更新还是覆盖。
39. 作为用户，我想汇总只告诉我要装什么、装到哪、会不会覆盖，不把将要执行的命令列给我看。（这一条原先是「开始安装之前看到将要执行的每一条命令」；维护者 2026-10-11 看对比页时改定：「这个用户根本不关心，所以不需要展示给他看」。终端界面照旧列出命令。）
40. 作为用户，我想汇总里带着和终端界面一样的提醒（「key 以占位符显示」那一条除外，它说的是命令里的占位符）：会覆盖已有的、第三方 Skill 内容来自作者、key 会以明文写进项目里的哪个文件、哪个宿主要另行批准才启用、哪个宿主会当场打开浏览器登录、哪个 MCP 因为缺 key 不装。
41. 作为用户，我想不是本工具装的目录、以及第三方 Skill 目标位置已有的同名目录，逐项让我决定覆盖不覆盖，缺省不覆盖。
42. 作为用户，我想在汇总上能返回修改，勾选和填过的 key 都还在。
43. 作为用户，我想看汇总期间机器上的状态变了的话，安装器不照旧的汇总装，而是给我看新的汇总。

### 安装与结果

44. 作为用户，我想点了开始安装后在页面上看到每一项的进度：等待、正在装、装好了、没装上。
45. 作为用户，我想一项失败不影响其余项，失败的写明原因和下一步。
46. 作为用户，我想工具的安装命令在终端里跑的时候，页面写明「这一项正在终端里安装，请看终端」，跑完后页面上有它的结论。
47. 作为用户，我想装完后看到合计（装好几项、没装上几项、跳过几项）。
48. 作为用户，我想装完后可以接着挑下一批，状态已经是新的，已选清空。
49. 作为用户，我想向 GitHub 查询失败时页面上看得到出错说明，本仓库的 skill 不装，其余的照常装。

### 退出

50. 作为用户，我想页面上有「完成」按钮，点了安装器才退出，页面写明可以关掉这一页。
51. 作为用户，我想直接关掉页面后安装器过几秒自己退出，终端回到提示符。
52. 作为用户，我想刷新页面不会让安装器退出，刷新后回到刷新前的样子（勾选、所在的步骤都在）。
53. 作为用户，我想安装中关掉页面时这一批照样装完，结果打在终端里。
54. 作为用户，我想在终端按 Ctrl+C 时安装器退出，页面写明安装器已退出。
55. 作为用户，我想安装器已经退出之后，留着的页面不会假装还能用。

### 语言

56. 作为用户，我想页面先按系统语言显示，用网页界面时终端不再问语言。
57. 作为用户，我想在页面上切换中文和 English，切换后页面上的一切文字——包括状态、原因、提醒、条目说明——都换过来，勾选不丢。
58. 作为用户，我想 `--lang` 仍然有效：页面一打开就是那种语言。

### 安全

59. 作为用户，我想这个网页只有我这台机器访问得到，同一个网络里的别的机器打不开它。
60. 作为用户，我想我浏览器里开着的别的网站没法指挥安装器装东西或读到它的状态。
61. 作为用户，我想页面不向互联网上的任何地方发请求（不加载外面的字体、脚本、图片，不做统计），它只和本机的安装器说话。
62. 作为用户，我想页面只能告诉安装器「选了哪些条目、怎么选的」，要执行的命令始终由安装器照目录自己拼，页面改不了。

### 维护

63. 作为维护者，我想网页界面随 npm 包一起发布，用户不用多装任何东西。
64. 作为维护者，我想终端界面的画面和行为不变，现有的测试不用改就能证明这一点。
65. 作为维护者，我想在选定页面的样子之前先看到几种并排的方向，用真实目录里最坏的内容排（最长的名字、条目最多的用途、中英文）。
66. 作为维护者，我想改了页面之后能生成一份预览，每个状态一格、深色浅色各一份，对着设计规范看。
67. 作为维护者，我想文档（两份 README、CLI 层的规范）写的是有两套界面之后的样子。

### 开场

68. 作为用户，我想页面第一次打开时先看到一段两三秒的开场动画——像在终端里敲下那条命令、大标志一行行打出来——然后才是挑选的页面。
69. 作为用户，我想点一下或按任意键就能跳过开场；刷新页面、断开重连时不再重播。
70. 作为在系统里开了「减少动态效果」的用户，我想不播开场，页面直接出现。

## Implementation Decisions

### 用哪个界面

- 启动顺序：解析启动参数 → 参数有误、`--help`、`--version`、没有交互式终端各自处理并退出 → 打大标志 → **定下用哪个界面** → 网页界面不问语言，终端界面照旧问 → 读取目录 → 本机信息 → 进入所选的界面。目录读不了时还没有打开浏览器。
- 用终端界面的情形，按这个先后判断：
  1. 给了启动参数 `--terminal`。
  2. 环境变量里有远程连接的痕迹（`SSH_CONNECTION`、`SSH_TTY`、`SSH_CLIENT` 任一非空）。
  3. 系统不是 macOS 也不是 Windows，且 `DISPLAY` 和 `WAYLAND_DISPLAY` 都为空。
  4. 本机的网页起不来，或链接打开器拒绝（系统上没有打开命令，或它很快以非零状态结束）——这两种是进入网页界面之后才知道的，安装器在终端上说明一句原因，然后照终端界面的流程从语言提问接着走。
- 判断只看入口收到的环境变量和平台，不直接碰 `process`。
- 标准输入或标准输出不是终端时仍然拒绝运行，和现在一样。

### 网页界面开着时的终端

- 本机信息之后是一个新的块：网页界面已在浏览器打开、网址（整条写在一行上）、按键提示（`t` 改用终端界面、Ctrl+C 退出）。它的画法先写进界面设计规范，再实现。
- 等按键是**提问器的一种新提问**（待命），不另开一条读键盘的路：它在网页界面那边结束时可以被收回。安装进行中它不在——工具的安装命令要接管终端的输入输出。
- 按 `t`：关掉本机的网页，页面显示已改用终端界面；页面上的勾选丢弃；终端从语言提问接着走，目录不重读。
- 网页界面这边结束时终端上各有一行说明：点了「完成」、页面关了、改用了终端界面。
- 工具的分区照现在的样子打在终端上。安装中页面关了，这一批的结果照终端界面「结果」分区的样子打在终端上。除此之外，网页界面开着时终端上不重复页面上的内容。

### 本机的网页

- 用 Node 自带的 HTTP 服务，不加运行时依赖。只监听本机回环地址，端口由系统挑一个空闲的。
- 每次运行生成一个随机的口令，带在交给浏览器的网址里。凡是读状态或引起动作的请求都必须带着它，比较时不泄露时间差；不带或不对的一律拒绝，答复里不带任何状态。
- 另外两道：请求的 `Host` 必须是本机回环地址加这个端口；改变状态的请求如果带着 `Origin`，它必须是页面自己的。不发任何允许跨来源访问的头。
- 页面的静态文件里没有口令、没有用户的任何数据。所有答复都不许缓存。
- 页面带内容安全策略：只许加载和连接它自己的来源。页面里没有指向外面的字体、脚本、样式、图片、统计。外部项目和申请 key 的链接是普通的链接，在新标签页打开，不带来源信息。
- 交给浏览器的那个网址经现有的链接打开器打开——它从「留着不用」变成「只用来打开网页界面」。外部项目的链接仍然不由安装器打开，由用户在页面上点。

### 页面与安装器之间

- **状态在安装器这边**：所选的宿主、安装范围、勾选、第三方 Skill 里挑的 skill、填过的 key、走到哪一步、开场动画播过没有，都在安装器的内存里。页面是它的一个显示：刷新或再开一个标签页，看到的是同一个状态。
- 页面发给安装器的是**意图**：选宿主、选安装范围、勾上或去掉一个条目、挑第三方 Skill 里的 skill、填一个 key、同意覆盖某一项、要汇总、确认安装、返回修改、继续挑选、完成、换语言。意图里只有条目的名字和选项，**没有命令、路径或任何会被原样执行的东西**。
- 安装器发给页面的是**整份画面状态**，每次变化推一次：用途与数量、当前用途下的条目（类型、说明、推荐标记、每个所选宿主下的状态、可不可选与原因）、已选、汇总（各项、提醒、要逐项决定的覆盖）、进度、结果、出错说明。**将执行的命令不在画面状态里**：页面不展示它，安装器就不把它发出去。推送用一条长连接，它同时是「页面还开着」的依据。
- **说了什么由安装器定，怎么排由页面定**：状态的词、不可选的原因、提醒、出错的原因与下一步，用的是和终端界面同一套说法、同一份中英文案，随画面状态发给页面；页面自己的文字只有版式上固定的那些（按钮、栏名、空状态的话）。这样经入口的测试断得到用户读到的字，两套界面也不会各说各的。
- 换语言是一个意图：安装器按新的语言重发画面状态，勾选不变。终端上的语言不跟着变，它在启动时就定了（系统语言或 `--lang`）。
- key 只经请求的正文传给安装器，之后的画面状态里只有「填了没有」；它不进网址、不进任何答复、不进终端、不进日志。输入框不让浏览器记住或自动填。安装器这边沿用现在的规矩：值只进内存、命令参数和宿主的配置。
- **展示的和执行的是同一份**：汇总带一个标识，确认安装时要带回它。安装器确认前重新探测一遍；结果和汇总时不一样（状态变了、多了一项要覆盖），就不装，改发新的汇总。页面上展示的是要装的各项和提醒，不含命令；命令仍由安装器照这同一份计划去执行。

### 两套界面共用的部分

- 交互流程里现在写在一起的三件事要分开：逐步提问（终端界面独有）、**把勾选算成要装的每一项**（每个组件在每个宿主下一项，连同位置、状态、命令、要不要另问覆盖、缺哪个 key）、**逐项执行并报告进度**。后两样两套界面共用，是这次要立起来的深模块：给它目录、所选的宿主、安装范围、勾选和填过的 key，它给出计划；给它计划和一个进度的接收方，它逐项去装。
- 「推荐」和各个用途里有什么、怎么排，「每个条目可不可选、原因是什么」，也是共用的，不在页面里再写一遍。
- 终端界面经这些共用的部分走，对外的行为不变：现有的测试一条都不改，就是它的凭据。
- 一批里的规矩和终端界面一样：执行先后是本仓库的 skill、第三方 Skill、MCP、工具；一项失败不影响其余；必填的 key 没填的 MCP 不装并写明；向 GitHub 查询失败时本仓库的 skill 都不装、其余照常；成败看复核，不看命令的退出状态；单项失败不改变退出状态。
- 和终端界面不一样的只有这几处：一批可以跨用途；宿主和安装范围是页面上的选项，不是每进一个用途问一次；外部项目不勾选（见下）；覆盖的逐项询问在汇总里一次答完，不是确认之后再一个个问；汇总里不列将执行的命令。

### 外部项目

- 网页界面里外部项目不能勾选：说明完整显示，链接可点。终端界面里「勾了之后在最后列出说明与链接」是因为那里的说明被截断、链接点不了，网页界面没有这个需要。

### 页面的生命周期

- 页面第一次连上之前，安装器一直等着（终端上有网址和按键提示），不因为没人连而退出。
- 连上过之后，所有页面都断开满 5 秒：空闲时以 0 退出；安装中则把这一批装完，结果打在终端上，再以 0 退出。5 秒之内重新连上（刷新）就当没断过。
- 安装中断开满了 5 秒、而这一批装完之前页面又连回来了：也当没断过——安装器不退出，进度和结果照常在页面上（维护者 2026-10-12 定的：原文没有说这种情形，照字面做的话重新打开的页面会在装完那一刻变成「安装器已退出」）。一批装完时没有页面连着、之后页面也没有回来的，结果同样打在终端上（装完前一两秒才关页面的也在里面）。
- 「完成」：安装器以 0 退出，页面显示可以关掉这一页。终端按 Ctrl+C：照现在的规矩以 130 退出；页面发现连接断了，显示安装器已退出。
- 同一台机器上同时开两个安装器互不相干：各有各的端口和口令。它们对宿主配置的影响和现在同时开两个终端界面一样，不另做处理。

### 页面用什么做

- 页面用 TypeScript 写，和安装器共用「意图」和「画面状态」的类型定义：两边对不上在类型检查时就会报出来。
- 用一个小的声明式界面库（Preact），由一个只在开发时用的打包工具（esbuild）打成静态文件放进构建产物。两样都是开发依赖：**npm 包的运行时依赖一个都不加**，包里多的只是几个静态文件。样式手写，不用现成的样式框架。
- 选它们的理由：这一页有十来种状态要随安装器的推送重画，手工改页面元素容易漏；声明式的写法「状态是什么就画什么」正对上「状态在安装器这边」的做法。没有选「不用任何库、不打包」，是因为那样省掉的只是两个开发依赖，换来的是自己维护一套重画的办法。
- 页面的全部源码、构建脚本、静态资源都在 `cli/` 里；构建和测试只扫 `cli/` 内部；构建产物不提交（ADR-0001）。

### 文档与规范

- CLI 层的规范：总览（多了哪几块、测试接缝怎么用）、入口与测试（启动顺序、`--terminal`、用哪个界面的判断、链接打开器现在用来做什么、测试架子的新用法）、界面设计（现有的规定写明只管终端界面；网页界面开着时终端上那个新的块）、终端输出（待命的提问）。另立一份网页界面的设计规范，内容来自选定的视觉方向；再立一份网页界面的契约（意图、画面状态、安全上的几道、生命周期）。
- 两份 README 改成有两套界面的说法：运行要求、它会打开浏览器、怎么强制用终端界面。

## UI and Design

- **视觉方向是「利落」**（维护者 2026-10-11 选定，过程与没选的候选见 `ui-direction.md`）：参照 Linear、Vercel 这一类当下的开发工具，黑白灰，线极细，字小而准。数值、部件和每个画面的版式要点在 `.atw/spec/cli/web-ui-design.md`，后面的工单照它实现；要改画面先改那份规范。
- **版面**：三栏——左边用途（一竖列，带条目数），中间条目（卡片，两张一排），右边已选（名字全列，「去汇总」固定在底部）。宿主和安装范围在中间一栏顶上贴着不动的那一条里。填 key 是盖在页面上的对话框；汇总、安装中、结果是从右边滑出的面板。
- **颜色**：彩色只有说状态的那三种（绿、黄、红）；按钮和选中用前景色（深色页面上是白，浅色页面上是黑）。**不用紫色**。OXY 大标志在网页界面里是单色的，跟着页面走；终端里的大标志不变。
- **开场动画**：页面第一次打开时先播约两秒半——黑底上敲出 `$ npx oxy-tools`，大标志一行行打出来，淡出，卡片依次浮上来。它盖在页面上面，不拖慢页面连上安装器；只在这次运行第一次打开时播，可以跳过，系统开了「减少动态效果」时不播。
- **汇总里不列将执行的命令**（见故事 39）。
- 维护者说过的喜欢与不喜欢：要卡片；要现代、流行的长相；不要密密麻麻；说明不要截断；不要紫色系和一眼像 AI 做的样式；不要成排的圆角标签当用途的导航；不要复古风。
- 对比页要拿最坏的内容排，不只拿好看的样例：目录里最长的条目名、条目最多的用途（20 条）、外部项目最多的用途、两个宿主都带版本的状态、一条长链接；中文、英文各一遍；深色、浅色各一遍。（原先还有「一条长命令」；汇总不列命令之后改看最长的安装位置折不折得开。）
- 必须有的画面与状态：
  - 浏览与挑选：有宿主 / 一个宿主都没有；一个宿主 / 两个宿主；全局 / 项目；用途下只有外部项目；有不可选的条目；已选为空 / 已选了几个 / 已选里有现在装不了的。
  - 第三方 Skill 里挑 skill；填 key（没填、已填、必填的没填）。
  - 汇总：有要逐项决定的覆盖；各种提醒；没有要逐项决定的事时的样子。
  - 开场动画：进行中、被跳过、减少动态效果时不播。
  - 安装中：等待、正在装、工具在终端里装。
  - 结果：全部装好、有没装上的、有跳过的、向 GitHub 查询失败。
  - 结束：已完成、安装器已退出、已改用终端界面、口令不对。
- 目标视口：桌面 1280×800 是主要的；1024×768 不能坏（没有横向滚动条，主要的按钮看得见）。不为手机和平板设计。
- 跟随系统的深色与浅色。全部操作可以只用键盘完成，焦点看得见。
- 状态的词、条目的标记、成功失败跳过的符号沿用界面设计规范（终端的那份）；颜色的含义在网页界面的设计规范里定。
- 能在截图上核对的验收标准：
  - 1280×800 下，一个 20 条的用途里每条说明都完整，没有一处「…」。
  - 任何时候已选的数量和「去汇总」的按钮都在屏幕上，不用滚动去找。
  - 外部项目和组件一眼分得开，外部项目上没有勾选框。
  - 不可选的条目上看得到原因，不用把鼠标移上去。
  - 汇总里没有将执行的命令；要逐项决定的覆盖就在它那一行下面。
  - 彩色只有说状态的那三种（绿、黄、红），没有紫色；大标志是单色的。
  - 1024×768 下没有横向滚动条。
  - 深色和浅色下文字与背景的对比都看得清。

## Testing Decisions

- **好的测试只断言对外的行为**：给定目录、主目录和项目目录的初始状态、运行环境，以及用户做了什么，看用户读到了什么、执行了哪些命令、目录里多了什么、退出状态是多少。不为内部模块单独写测试。
- **接缝还是那一个：安装器入口。** 不为网页界面另开接缝，也不加新的可替换依赖：
  - 测试里的链接打开器照旧只记录，它记下的网址就是网页界面的地址；测试拿着它**扮演浏览器**，经真实的本机 HTTP 发意图、收画面状态。
  - 测试架子加一种用法：给一段「在页面上做什么」的脚本（勾哪些、选哪个范围、填什么 key、确认、完成），断言画面状态里的字（状态、原因、提醒）、记录到的命令、主目录和项目目录、终端输出、退出状态。
  - 待命的提问经提问器这个已有的可替换依赖来：预设应答里多一种「按 t」。（工单 11 做成的样子：这个键由页面的脚本来按——`terminal.press('t')`——不排进 `answers`。待命在浏览器打开的那一刻就问出去了，排进 `answers` 的话页面还没连上它就答了。仍然只经提问器，没有加可替换的依赖。）
  - 架子缺省仍走终端界面，现有的测试一条都不改；要测网页界面的用例才给页面脚本。
- **要测的行为**：
  - 用哪个界面：四种退回终端界面的情形各一条；`--terminal`；链接打开器拒绝、本机网页起不来各一条（终端上有那句原因，之后是语言提问）。
  - 网页界面的整条流程：每种组件各一条正常路径；跨用途一批装；两个宿主；装到项目（落点、Codex 的 MCP 不可选及原因）；改了宿主或范围后状态重查、装不了的留在已选里；第三方 Skill 里挑 skill；带 key 的 MCP（填了、必填的没填、同一次运行里再用）；覆盖的逐项决定（缺省不覆盖）；工具在终端里装；一项失败不影响其余；向 GitHub 查询失败。
  - 展示的和执行的是同一份：确认时带旧的标识、汇总之后状态变了，都不装。画面状态和任何答复里都没有将执行的命令；记录到的命令与用终端界面装同样的东西时逐条相同。
  - 安全：不带口令、口令不对、`Host` 不对、`Origin` 是别的网站，各一条，答复里没有任何状态；监听的地址是回环地址；页面的静态文件里没有指向外面的地址，答复带着内容安全策略；填的 key 不出现在任何答复、终端输出和网址里。
  - 生命周期：完成；连上后断开满时限（空闲、安装中各一条）；时限内重连；没连上过不退出；Ctrl+C；按 `t`。时限在测试里可以调短。
  - 语言：缺省跟系统语言、`--lang`、页面上切换后状态的词跟着换而勾选不变；用网页界面时终端没有语言提问。
- **页面本身不写自动化测试**：页面只管把画面状态画出来、把操作变成意图，规则都在安装器这边、经入口测到；页面和安装器对不对得上靠共用的类型定义。观感靠预览加视觉评审把关，和终端界面一样：界面预览页扩到网页界面——经入口把安装器驱动到每个要看的状态，在真实的浏览器里各拍一格，深色浅色各一份。
- **发布前在本机核对**多几行：打出来的包装到临时项目里，页面的静态文件都在、打得开；真实的浏览器里把整条流程走一遍（临时主目录，同现有的做法）；远程连接下自动用了终端界面。
- 可以照着写的先例：安装范围、混合列表、带 key 的 MCP、第三方 Skill、启动这几组现有的测试，以及用假的 GitHub 替换网络的做法。

## Acceptance Criteria

- [ ] 在有桌面的 macOS 上不带参数运行，默认浏览器打开网页界面；终端上有网页界面的那个块，没有语言提问。
- [ ] 在网页界面里跨两个用途勾选一个本仓库的 skill、一个第三方 Skill、一个带 key 的 MCP，一次确认后都装上；宿主的配置和 skill 目录与用终端界面装出来的一样。
- [ ] 汇总里没有将执行的命令，发给页面的画面状态里也没有；实际执行的命令与用终端界面装同样的东西时逐条相同。填的 key 在页面、终端、网址、任何答复里都搜不到。
- [ ] 页面第一次打开时播开场动画，约两秒半；点一下或按任意键跳过；刷新不重播；系统开了「减少动态效果」时不播；开场不推迟页面连上安装器。
- [ ] 一个 20 条的用途里没有被截断的说明；外部项目没有勾选框，链接在新标签页打开。
- [ ] 带着 `SSH_CONNECTION` 运行、在没有 `DISPLAY` 的 Linux 上运行、带 `--terminal` 运行，都直接是终端界面，浏览器没有被打开。
- [ ] 链接打开器拒绝时，终端上有一句原因，接着是终端界面。
- [ ] 不带口令的请求、别的网站发来的请求都被拒绝；本机的网页只监听回环地址。
- [ ] 点「完成」后安装器以 0 退出；关掉页面 5 秒后安装器以 0 退出；安装中关掉页面，这一批装完、结果在终端上；刷新页面不退出、状态还在。
- [ ] 页面上切换语言后全部文字换过来，勾选不丢；`--lang en` 时页面一打开就是英文。
- [ ] 现有的测试一条都没有改，全部通过。
- [ ] `npm pack --dry-run` 里有页面的静态文件；用户装下来的包和改之前一样。（原先是「`package.json` 的运行时依赖和改之前一样」。工单 11 在 `dependencies` 里多写了一行 `@inquirer/core`：终端上待命的那一行是拿它写的，它本来就随四个提示子包装着，`npm ls` 里的包一个没多。维护者 2026-10-12 认可，这一条改成看装下来的包。）
- [ ] 页面的样子与维护者选定的视觉方向「利落」一致（`.atw/spec/cli/web-ui-design.md`），预览里每个状态一格、深浅各一份，「UI and Design」里能在截图上核对的几条都满足。
- [ ] 两份 README 和 CLI 层的规范写的是有两套界面之后的样子；`.atw/spec/cli/ui-design.md` 里「不做全屏界面」的规定写明只管终端界面。

## Out of Scope

- 终端界面的任何改动：画面、流程、文案都不动（「把外部项目从勾选表里分出去」不做）。新增的只有网页界面开着时终端上的那个块，和退回终端界面时的那句原因。
- 公开的目录网站，或任何「不装也能逛」的页面。
- 从另一台机器的浏览器打开网页界面（远程机器上的用户用终端界面）。
- 没有交互式终端时运行安装器：仍然拒绝。
- 手机和平板的视口。
- 搜索、筛选、排序。
- 卸载、更新管理，或任何终端界面没有的安装能力。
- 记住上一次的选择（宿主、安装范围、语言、勾选）：安装器仍然不为这些写任何文件。
- 把工具的安装命令的输出搬到页面上。
- 用真实浏览器的自动化测试进 CI。
- 发 npm 版本（升版本号、发布另做；这次的行为变化够得上一个新的次版本号）。

## Further Notes

下面这些是写 spec 时的推断，访谈里没有逐条问过维护者：

1. 强制用终端界面的启动参数叫 `--terminal`（访谈里只作为例子提过）。
2. 认出「打不开浏览器」的三条依据（远程连接的环境变量；非 macOS、非 Windows 且没有 `DISPLAY` 和 `WAYLAND_DISPLAY`；打开命令拒绝）。访谈里说的是「多数情况认得出」，没有在真机上实测过；认不出的情形（比如远程桌面里的终端、WSL）靠终端上的网址和 `t` 兜底。
3. 目录在打开浏览器之前读：读不了就不开浏览器。代价是浏览器晚一两秒弹出来。
4. 外部项目在网页界面里不能勾选，只显示说明和链接。
