## 交互库：`@inquirer/prompts`

排除过程：`enquirer` 与 `prompts` 自 2023 年后没有再发版，先排除。剩下 `@clack/prompts` 1.8.1 与 `@inquirer/prompts` 8.7.3（2026-10-09 查自 npm），两者都装到仓库之外的临时目录，用同一份数据在无头终端里实际跑过。

| | `@clack/prompts` | `@inquirer/prompts` |
| --- | --- | --- |
| 提示的符号与配色 | 写死，没有主题接口 | 前缀、图标、活动行、禁用样式、说明、按键提示都能配 |
| 不可选条目的原因 | 只有布尔值，原因借 `hint` 显示，固定加删除线 | `disabled` 直接接受原因文字 |
| 已回答后显示什么 | 整行标签原样重复 | `short` 可给简称 |
| 按键提示 | 固定英文，只能关掉 | `keysHelpTip` 可本地化 |
| 不可选的分隔行（当表头用） | 不支持 | 支持 |
| 光标所在行的说明全文 | 没有位置 | `description` 显示在列表下方 |

选 inquirer 的理由：PRD 要求所有终端输出经同一个呈现层决定配色、符号、间距、边框和标题区，clack 的提示部分不让呈现层决定；账本的表头、列表下方的说明全文和可本地化的按键提示也只有 inquirer 做得出来。

设计稿用到四个提示：`select`、`checkbox`、`password`、`confirm`。

交给工单 02 处理的四件事，结论如下（2026-10-09，工单 02）：

1. **只装用到的提示子包，不装整个 `@inquirer/prompts`。** 在临时目录里实测：四个子包（`select`、`checkbox`、`password`、`confirm`）连同依赖共 14 个包、约 0.7MB；整个 `@inquirer/prompts` 是 25 个包、约 1.7MB，多出来的是用不到的编辑器、搜索等提示和它们带的编码库。每个子包在第一个用到它的工单里加进依赖；工单 02 只用到 `@inquirer/select`。
2. **最低版本上外层粗体不会自动重申，呈现层自己补。** 在 Node 22.13.0 上实测：`styleText('bold', …)` 包住一段带暗淡片段的文字时，片段的收尾码 `\x1b[22m` 之后不再有 `\x1b[1m`，后半行的粗体就丢了；Node 24.15.0 会自动重申。所以活动行的样式在每个 `\x1b[22m` 之后自己补一个 `\x1b[1m`，两个版本上结果一致（在 24 上只是多一个重复的码，没有可见影响）。全部测试和构建产物也在 22.13.0 上跑过。
3. **没有 Unicode 时的退路已做成预览页的五个场景**（启动与加载、主菜单、skill 列表、skill 详情后返回、出错），**维护者已过目并认可**（2026-10-09）。除了“符号的含义”一表右栏的退路，实现时还补了一处表里没有的：按键提示里的 `↑↓` 和 `⏎` 是交互库写死传进来的，退路里换成文字（中文「上下键」「回车」，英文 `up/down`、`enter`）。
4. **环境里只要有 `NO_COLOR` 就完全不带样式——颜色、粗体、暗淡都没有；`FORCE_COLOR` 一概不理会，所以两者同时设置时以 `NO_COLOR` 为准。** 维护者已定（2026-10-09）。视觉评审提过另一种做法：只去颜色、保留粗体和暗淡，好留住层级；维护者看过后仍选完全无样式。做法见下面“颜色”一条。

实测得到、实现时要照做的事：

- **颜色**：呈现层只用 `node:util` 的 `styleText` 上色，不引入别的上色库。**上不上色由呈现层自己判断，不交给 Node**，标准输出和标准错误各判各的：这个流是终端、且环境里没有 `NO_COLOR` 这个变量（照 `prd.md` 的字面，只要存在就算，哪怕为空）时上色，其余情况不上色；`FORCE_COLOR` 一概不理会，所以它和 `NO_COLOR` 同时设置时以 `NO_COLOR` 为准，输出不是终端时它也不能强行开色。判断好之后调 `styleText` 时关掉它自带的检测（`validateStream: false`）。这样做的前提是**交互库自己不上色**：传给每个提示的主题要把用到的样式函数全部盖掉（前缀、光标、提问、回答、活动行、说明、按键提示），否则没盖到的那一处会按 Node 的规则上色——Node 以 `FORCE_COLOR` 为准，看的是 `process.stdout` 而不是实际写入的流——两边就不一致了。`select` 已全部盖掉；之后加 `checkbox`、`password`、`confirm` 时逐个核对。界面预览页用假流驱动，因为上色与否由呈现层按传入的环境判断，不需要另设 `FORCE_COLOR`。
- **活动行**：`theme.style.highlight` 收到的是整行，活动行的样式是整行加粗。行内已有暗淡或粗体的片段时，它们的收尾码（`\x1b[22m`）会把外层的粗体一并关掉；Node 22.13 不会自动重申（见上面第 2 条），所以呈现层在每次收尾后补一次。
- **表头**：用 `Separator` 放一行暗淡的列名。它前面只有一个空格，而单选的条目前面有两格、多选有三格，列名要相应多缩进。
- **不可选条目**：`theme.style.disabled` 收到的也是整行，原因文字夹在里面。整行压暗但原因要保持正常亮度，做法是把原因用一对零宽空格圈出来，压暗时跳过这一段。不能靠行内收尾码来做，原因同上一条。单选里不可选的行，行首是 inquirer 写死的 `-`，改不了。
- **禁用项会被光标落到**：`select` 的光标默认停在第一项，哪怕它是禁用的。没有检测到宿主时要用 `default` 把光标放到「应用项目」。
- **输出流会被关掉**：每个提示结束时 inquirer 会结束传给它的输出流。真实终端不受影响；界面预览页用假流驱动时，要给每个提示一个新的流。
- **隐藏输入**：`prd.md` 要求输入不回显。`password` 设 `mask: false`、`toggleMask: false`：屏幕上不出现任何字符，也不暴露长度，提问后面只有一句固定的提示（用 `theme.style.maskedText` 换成本地化的文字）。不关 `toggleMask` 的话，用户按 Ctrl+T 就能把 key 显示出来。
- **加载与进行中的符号由呈现层自己转**：inquirer 的转动符号只存在于提示内部，加载目录和安装进行中用不上。维护者已决定让它转动（`prd.md` 的范围条款同步改了）：呈现层在一行的行首轮换一个符号，帧与节奏照搬 inquirer 的默认值（`⠋ ⠙ ⠹ ⠸ ⠼ ⠴ ⠦ ⠧ ⠇ ⠏`，每 80 毫秒一帧），结束时把这一行改写成结果。除此之外不做任何动画。输出不是终端时不转，只打印文字。

## 版式的总规则

- **按 80 列设计**，每行右侧留一列不用，避免顶满时终端自己折行（通栏横线、分区标题线和大标志右端的产品名除外，它们正好到第 80 列）。更窄的终端不专门适配。
- **宽度按显示宽度算**：汉字和全角标点占两列，其余占一列，对齐和截断都按这个算。
- **折行由呈现层做**：西文按词断，中文可在任意两字之间断，行首不放收尾标点。不依赖终端自己折。
- **截断用 `…` 收尾**，只截列表里的说明；名字、状态、路径、命令从不截断。
- **栏宽按内容定**：每一栏取这一栏里最长的一格再加两格间隔，名字栏也是；剩下的宽度给说明。不写死栏宽，目录里出现更长的名字时版式不用改。
- **不用表情符号**：不同终端对它的宽度算法不一致，会把对齐打乱。
- **不做全屏界面**：所有输出顺着往下打，已回答的提问收成一行留在屏幕上。

## 颜色的含义

只用终端的标准命名色，真实色值由用户自己的终端配色决定。这个方向以黑白为主，颜色很少。

| 颜色 | 含义 | 用在哪 |
| --- | --- | --- |
| 青 `cyan` | 当前焦点 | 提问标记 `?`、光标 `▸`、已勾选的框 `■`、进行中标记。**只用在符号上，不用在文字上** |
| 绿 `green` | 已就绪 | 已装、已配置、已安装、检测到的 `✓`、成功 |
| 黄 `yellow` | 需要留意 | 版本不同、非本工具安装、覆盖、命令里的 key 占位符、注意 |
| 红 `red` | 失败与出错 | 失败、`✗`、出错的标题 |
| 暗淡 `dim` | 次要信息 | 表头、横线、键值行的键、未装、未配置、不支持、按键提示、禁用条目 |
| 粗体 `bold` | 主要信息 | 产品名、提问、分区标题、光标所在行；黄色和红色的词一律同时加粗（覆盖、注意、失败、版本不同、非本工具安装） |
| 下划线 `underline` | 链接 | 申请地址、应用项目地址 |

四条硬规则，来自对比度的实测（两套代表性配色，近似 VS Code 默认的深色与浅色终端；4.5:1 是正文字号下通行的可读门槛）：

| | 正文 | 暗淡 | 红 | 绿 | 黄 | 蓝 | 洋红 | 青 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 深色背景 | 11.1 | 3.7 | 3.4 | 7.2 | 13.1 | 3.6 | 3.9 | 6.3 |
| 浅色背景 | 11.2 | 2.7 | 5.1 | 5.4 | 3.1 | 7.7 | 5.4 | 3.4 |

1. **除了绿，没有一种命名色在两种背景上都达到 4.5:1**；而且这只是两套配色，换一套终端配色连绿也未必达标。所以名字、说明、命令和汇总里的位置一律用终端的默认前景色，颜色只落在状态词和符号上；每种状态的文字本身就不同，不靠颜色区分。
2. **只用八个基本色，不用亮色变体，也不显式指定黑和白**：亮色在浅色背景上发虚，白字在浅色背景上看不见。次要信息用 `dim`，不用灰（亮黑）——灰在不少深色配色里几乎贴着背景。
3. **`dim` 只给真正次要的东西**：它在浅色背景上只有 2.7:1。一句话说明不算次要，用默认前景色；不可选条目的原因是用户最需要读的字，也用默认前景色。
4. **黄色和红色的词同时加粗**：黄在浅色背景上只有 3.1:1，加粗后才不至于比旁边的普通字更弱。

**已知的弱点，尚未解决**：「未装」「未配置」「不支持」和不可选条目的名字是暗淡的，黄色的词即使加粗也只有 3.1:1，它们在浅色背景上都偏淡。这是有意的取舍——暗淡表示“退后”，含义不靠它传达——但两轮视觉评审都指出了它，维护者没有就这一点表过态。可行的改法：这几个状态词改用默认前景色；黄色的词改成默认色粗体，黄色只留在行首的标记上。要不要改由维护者定。

## 状态的写法

状态一律用词表达，放在自己的一栏里。**不显示颜色时文字一字不变**，不需要另一套写法。状态栏里用短词「已装」省栏宽；结果行说的是刚做完的动作，写「已安装」。

| 对象 | 状态 | 写法 | 颜色 |
| --- | --- | --- | --- |
| skill | 未安装 | `未装` | 暗淡 |
| skill | 已安装（本工具装的） | `已装 2.16` | 「已装」绿，版本号默认色 |
| skill | 已安装且与清单版本不同 | `2.0.0 → 2.1.0`（已装的在左，清单的在右） | 黄，粗体 |
| skill | 已存在但不是本工具装的 | `非本工具安装` | 黄，粗体 |
| MCP | 未配置 | `未配置` | 暗淡 |
| MCP | 已配置 | `已配置` | 绿 |
| MCP | 未知 | `未知` | 默认色 |
| MCP | 这个宿主不支持 | `不支持` | 暗淡 |
| 工具 | 未安装 | `未安装` | 暗淡 |
| 工具 | 已安装 | `已安装` | 绿 |

选了两个宿主时每个各占一栏，栏名就是宿主的名字；只选一个时只有一栏。

## 符号的含义

| 符号 | 含义 | 没有 Unicode 的终端里退成 |
| --- | --- | --- |
| `?` `✓` | 提问中 / 已回答 | `?` `+` |
| `▸` | 光标所在行 | `>` |
| `■` `□` `–` | 多选：已勾选 / 未勾选 / 不可选 | `[x]` `[ ]` `[-]` |
| `-` | 单选里不可选的行（inquirer 写死的行首） | 不变 |
| `✓` `✗` `–` | 成功 / 失败 / 跳过 | `+` `x` `-` |
| `⠋ ⠙ ⠹ …` | 进行中，转动（帧见交互库一节） | `-` `\` `\|` `/` |
| `──` | 分区横线，标题嵌在线里 | `--` |
| `→` `·` `…` | 版本变化 / 分隔 / 截断 | `->` `-` `...` |
| `$` | 正在执行的命令 | 不变 |
| 实心方块 | OXY 大标志 | ASCII 字符画（见下） |

右边这一栏是实现方提出的退路，没有在设计稿里画出来；工单 02 把它做进了界面预览页（标题以「没有 Unicode」开头的场景），**维护者已过目并认可**（2026-10-09）。按键提示里的 `↑↓`、`⏎` 在退路里换成文字，见“交互库”一节第 3 条。

是否支持 Unicode 沿用 inquirer 自己的判断（Windows 上只有 Windows Terminal、VS Code 等算支持；其他系统上只有 Linux 的内核控制台算不支持）。inquirer 没有把这个判断导出来，呈现层照它的条件自己写了一份，按传入的环境变量和系统判断。退回 ASCII 不只是为了字形：这些符号在 Unicode 里属于宽度不定的一类，中文旧版控制台可能把它们按两列画，通栏横线就会超出一行。

## 横线、分区与键值行

- **通栏横线**：80 列、暗淡。只用在三处：大标志下方、本机信息下方、结果表与合计之间。通栏横线后面如果紧跟分区标题（如启动后立刻出错），中间空一行，两条线不贴在一起。
- **分区标题**：`── 标题 ───…` 到行尾，标题粗体、线暗淡。汇总、将执行的命令、key 的说明、正在安装与结果、每个工具的执行、应用项目详情、出错，各是一个分区。出错的标题是红色粗体，以「出错：」开头。分区标题上方空一行（画面的第一行除外）。
- **键值行**：缩进两格，键占 10 列、暗淡，值用默认色；值过长时折行，续行与值的左缘对齐。提醒用键值行表达，键是黄色粗体的「注意」。
- **表格**：表头一行暗淡的列名，之后每行各栏按显示宽度补齐；同一条目的后续行不重复名字。
- 没有边框。一条线只做一件事，不叠双线。

## 各画面的版式要点

### 帮助

`--help` 的输出：第一行是粗体的产品名，后面跟暗淡的版本号和暗淡的一句话说明（与标题区一致）；之后「用法」「选项」「环境变量」各一个分区，分区里是两栏的表，第一栏按最长的一格定宽，第二栏过长时折行。输出不是终端时没有颜色，文字和横线照旧。

### 加载

大标志和通栏横线之后一行：缩进两格，青色的转动符号、「正在读取目录」、暗淡的省略号。读完后这一行被本机信息取代。

### 出错

所有出错共用一个版式（下面是其中一种）：

```
── 出错：GitHub 限流 ───────────────────────────────────────────────────────────
  原因      未登录的查询每小时限 60 次，约 37 分钟后恢复
  下一步    稍后再试
            或设置访问令牌后重新运行：export GITHUB_TOKEN=<你的令牌>
```

- 分区标题是红色粗体的「出错：是什么」，与上方的内容之间空一行；下面是键值行「原因」和「下一步」，出路不止一条时各占一行。不出现堆栈。
- **出错说明写到标准错误**，其余输出写到标准输出。这样 `npx oxy-tools | cat` 或 `> 文件` 时，说明仍然出现在终端上，而不是进了管道或文件。
- 「没有交互式终端」时不打印大标志。标准错误还接在终端上就照常上色；它也被重定向时没有颜色，文字和横线照旧。
- 工单 02 落地的出错：无法读取目录、目录格式有误、目录格式版本不受支持、没有交互式终端、无法识别的参数，以及兜底的意外错误。出问题的网址或路径单独占一行，接在「原因」下面、与值的左缘对齐，不截断也不折行（路径里可能有空格和汉字，折开就没法复制了）。

### 英文界面

版式不变，文字换成英文。状态词：`installed`、`unmanaged`、`none`；表头与键：`Group`、`Items`、`About`、`Catalog`、`Notice`；按键提示：`move`、`select`、`all`、`invert`、`confirm`。英文说明更长，列表里截得更多，全文同样在光标所在行的下方给出。
