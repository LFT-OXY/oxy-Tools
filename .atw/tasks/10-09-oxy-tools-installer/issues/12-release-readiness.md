**通过的**

- 包的内容：`npm pack` 打出 22 个文件——`dist/` 下 19 个 `.js`，加 `package.json`、`README.md`、`LICENSE`；44 KB。装进一个临时项目后 `npx --no-install oxy-tools --version` 输出 `0.1.0`，`--help` 正常。

- 真实终端：macOS「终端.app」，Pro（深色）和 Basic（浅色）各走一遍 skill（含版本不同、非本工具安装、未同意覆盖）、带 key 的 MCP、工具、出错；另在 Basic 下设 `NO_COLOR` 走一遍。文字都清晰可读，各栏对齐。截图在 `screenshots/12-real-terminal-*`（30 张）。看到两条弱点，已记进 `ui-design.md`：大标志的方块在这两套配色的字体行距下行间露缝；Basic 下不加粗的绿色状态词偏淡。

- 三种出错：`… </dev/null | cat`（没有交互式终端）、`catalog.json` 的 `version` 写成 99、`sandbox-exec` 禁网后走缺省的 GitHub 来源——各有原因和下一步，退出状态 1，没有堆栈。

**没在真实宿主上验、只在隔离环境里走通的**（上面没打勾的三条）

隔离环境是：临时主目录，`CLAUDE_CONFIG_DIR`、`CODEX_HOME` 指向临时目录，执行的是真实的 `claude`（2.1.295）和 `codex`（0.162.0）。

- 用**真实的目录来源**（推送后的 GitHub `main`）把 `retro` 装进两个 skill 目录：内容与仓库里的 `skills/retro` 逐文件一致，安装标记的 `commit` 是 `62fd98c…`；再进列表两栏都是「已装 1.0.0」。**没验的**：两个宿主真的加载得到它。
- 事先放的同名目录：列表里是「非本工具安装」，汇总里「另行确认」，是否题缺省否，回车之后那个目录原样没动。**没验的**：在维护者真实的 skill 目录上。
- 样例目录（两个 MCP、两个工具、一个应用项目）：两个 MCP 经宿主自己的命令写进了临时的 `.claude.json` 和 `config.toml`；带 key 的给出申请链接，输入不回显，终端的原始输出里搜不到填的值，值只在宿主的配置里；工具展示命令、确认后执行、复核「已可用」。**没验的**：写进真实的用户级配置并在宿主里看到；应用项目真的打开浏览器；验收后的移除。

**维护者手动走这三条的办法**

1. `npx oxy-tools`（发布前在 `cli/` 下 `npm start`）→ Skill → 两个 AI Agent 都选 → 勾一个 skill → 开始安装。然后在 Claude Code 里看 `/skills`、在 Codex 里看它列出的 skill，确认有它；再运行一次安装器，看它显示「已装 <版本>」。
2. 先手动建 `~/.claude/skills/<另一个 skill 的名字>/SKILL.md`，再进列表：那一栏应是「非本工具安装」；勾它、开始安装，被单独问到时直接回车（缺省否），目录应原样。
3. 照 `.atw/spec/cli/index.md`「发布前在本机核对」写一份样例目录（MCP 的名字取 `oxy-sample-*` 这样不会和已有的撞车的），`OXY_TOOLS_CATALOG=<样例目录> npm start`，装 MCP、工具，打开一个应用项目；用 `claude mcp get <名字>`、`codex mcp get <名字>` 看得到之后，用 `claude mcp remove --scope user <名字>`、`codex mcp remove <名字>` 移除。
