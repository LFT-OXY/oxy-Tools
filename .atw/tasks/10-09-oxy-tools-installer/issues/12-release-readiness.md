# 12 — 发布前验收

**What to build:** 在真实环境里确认安装器可以发布：打出的包是干净的，两个真实宿主上装得上，A Team Workflow 没有被影响。

这张工单需要维护者在场：它会真的改动维护者机器上 Claude Code 和 Codex 的用户级 skill 目录与 MCP 配置，动手前须先说明将改动什么并取得确认；最后的 `npm publish` 由维护者本人执行，不在代理的操作范围内。

**Blocked by:** 11
**Status:** ready-for-agent
**Impl:** ready

- [ ] 打出的 npm 包里只有构建产物和必要的说明、许可证文件，不含任何 skill 内容、目录数据、测试或其他多余文件。
- [ ] 再确认一次 `oxy-tools` 这个包名在 npm 上可用。
- [ ] 在维护者的机器上，用真实的目录来源把 `index.json` 里的一个 skill 装进 Claude Code 和 Codex，两个宿主都能加载到它；再次运行时它显示为已安装并带版本号。
- [ ] 对机器上一个事先就存在的同名 skill 目录，安装器显示"不是本工具装的"，不经单独确认不会覆盖。
- [ ] 把目录来源指向一份含 MCP、工具、应用项目样例条目的本地目录：MCP 能写进两个宿主的用户级配置并能在宿主里看到；带 key 的 MCP 给出申请链接且输入不回显；工具在展示命令并确认后执行并复核；应用项目能打开链接。验收后把样例 MCP 从两个宿主里移除。
- [ ] 生成界面预览页，把全部画面与 `ui-direction.md` 的选定方向逐一对照，修正画面之间不一致的地方（只统一，不重新设计）。
- [ ] 在真实终端里分别用一套深色和一套浅色配色各走一遍主要流程，文字都清晰可读；设置 `NO_COLOR` 后界面仍可用。
- [ ] 断网、目录格式版本过高、没有交互式终端三种情况下，安装器给出说明并以非零状态退出。
- [ ] 在一个临时项目里运行 `atw init` 的额外 skill 步骤，仍能列出并装上 `index.json` 里的 skill。
- [ ] CI 在 macOS、Linux、Windows 上全部通过。
- [ ] `prd.md` 的 Acceptance Criteria 逐条核对完毕，未通过的项已如实列出。
