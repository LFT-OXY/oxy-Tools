# 11 — 规范、README 与许可证

**What to build:** 仓库的文档跟上它的新形态：以后来改这个仓库的人（和代理）能从规范里读到安装器这一层怎么写、目录数据的契约是什么、哪些东西是对 A Team Workflow 的承诺；来访者能从 README 看懂这个仓库的两个用途。

**Blocked by:** 04, 06, 07, 09, 10
**Status:** ready-for-agent
**Impl:** ready

- [ ] `.atw/spec` 新增 CLI 一层的规范，写的是已经落地的真实做法：包的自成一体规则（ADR-0001 的三条）、入口与五样可替换依赖、两个测试接缝及其用法、目录校验命令。
- [ ] CLI 层规范里有一份界面设计规则，内容取自 `ui-direction.md`（颜色与符号的含义、各类画面的版式要点、深浅色与无颜色时的要求），并写明界面预览页的生成命令和用法；任务归档后以这份规则为准。
- [ ] skills 层的概述从"本仓库是 agent skill 分发仓库"改为"本仓库是目录加安装器"，并指向新增的 CLI 层。
- [ ] 清单与版本文档补上 `catalog.json` 的字段契约、格式版本号的兼容规则（新增可选字段不升版本号，不兼容改动必须升）。
- [ ] 同一文档写明对 A Team Workflow 的三条承诺，以及"改动这三样之前必须先看 A Team Workflow"：`main` 分支根目录的 `index.json` 及每条的 `name`、`version`、`path`、`description`；`path` 下有 `SKILL.md`；仓库可整包下载，不提交依赖目录和构建产物。
- [ ] 忽略规则覆盖 `cli/` 的依赖目录和构建产物，仓库里没有提交它们。
- [ ] 仓库根新增一份简短的 README：仓库的两个用途（目录、安装器）、怎么运行安装器、许可证按目录分别归属。
- [ ] `cli/` 有自己的 README（即 npm 页面上显示的那份）和 MIT 许可证文件；包描述里的仓库信息指向本仓库的 `cli/` 子目录。
- [ ] 文档里的术语与 `GLOSSARY.md` 一致，不与 ADR-0001、ADR-0002 矛盾。
- [ ] 规范里引用的命令都实际跑过，输出与文档描述一致。
