# 09 — 带 API key 的 MCP

**What to build:** 用户安装需要 API key 的 MCP 时，安装器告诉他去哪申请，等他把 key 粘贴回来后随配置写进宿主。key 只出现在宿主自己的配置里。

**Blocked by:** 08
**Status:** ready-for-agent
**Impl:** done

- [x] MCP 条目可声明环境变量列表，每项含变量名、是否必填、中英文说明、申请链接；环境变量只适用于本地进程方式，远程地址方式的条目带环境变量时校验不通过。
- [x] 安装含环境变量的 MCP 时逐个提问，显示说明和申请链接，输入不回显。
- [x] 必填项留空时跳过该 MCP 并在结果里说明原因，其余选中项照常安装；可选项留空时不传该变量。
- [x] 同一次运行里同一个变量只问一次，用于所有选中的宿主。
- [x] key 只作为参数传给宿主的添加命令；安装器不把它写入任何文件。
- [x] 汇总里展示的命令中，key 的值以占位符显示。
- [x] key 的值不出现在任何终端输出里，包括结果和错误信息。
- [x] 以上行为都有经主接缝的测试：必填留空被跳过、可选留空不传、两个宿主只问一次、记录到的命令带着用户输入的值、全部终端输出里不出现该值。
- [x] UI: 填写 key / 必填项 — 输出里有该变量的说明和申请链接。
- [x] UI: 汇总确认 / 含 key — 命令里 key 的位置是占位符。
- [x] UI: 界面预览页 / 本工单新增的画面与状态 / 深色与浅色 — 已作为场景加入预览页，且与 `ui-direction.md` 的选定方向一致。

## 实现时定下的事（维护者尚未逐条确认）

- 条目里环境变量的字段名是 `env`，每项是 `name`、`required`、`description`（`zh`、`en`）、`url`。`required` 必须写成布尔值，不猜缺省。变量名只收字母、数字和下划线，不以数字开头；同一条里不许重名。`env` 可省略；远程地址的条目带了**非空**的 `env` 才不通过，写一个空数组不算。校验报错里某一项的字段写成 `env[0].name`（下标从 0 数起）。
- 两个宿主带环境变量的写法对照了各自的 `--help`，并用 claude 2.1.295、codex 0.162.0 在临时配置目录里实测：`claude mcp add --scope user <名字> -e <变量>=<值> -- <命令…>`、`codex mcp add <名字> --env <变量>=<值> -- <命令…>`。一个变量一个 `-e` / `--env`，跟在名字后面（Claude Code 的 `-e` 能连收几个值，放在名字前面会把名字收进去）。值里带 `=`、`&`、`+`、`/` 都原样进了配置。Codex 对 `--url` 加 `--env` 直接报错。
- **「同一个变量只问一次」按「MCP + 变量名」记，不是只按变量名。** 两个 MCP 用了同名的变量（`API_KEY` 这类泛名字）时各问各的：只按变量名记的话，第二个 MCP 会不声不响拿到第一个服务的 key。同一个 MCP 装进两个宿主只问一次，这一点照规格做了。这和规格那句话的字面有出入，**需要维护者确认**。
- 「一次运行」取的是整个进程：返回修改后再确认、装完回主菜单再装，填过的都不再问（留一行「本次运行已填写，不再询问」）。留空的不算填过，回头再选时重新问——可选项因此每次返回都会再问一遍。填过的在这次运行里改不了，粘贴错了要退出重来。
- 必填的留空之后，这个 MCP 后面的变量不再问。它不在汇总和命令里；命令之后多一行「注意  <MCP> 缺少必填的 <变量>，这次不安装」（评审后加的）；结果里每个宿主一行「跳过 未填写必填的 <变量>」，计入合计。勾上的全都因此被跳过时，不显示汇总、不问执行不执行，直接给出结果并回主菜单——这时没有「返回修改」的机会，要重新进一次分组。
- 粘贴进来的值去掉首尾空白，此外不做任何校验。
- 值只有三个去处：内存里的 `Session.keys`、执行那一刻拼出来的命令参数、宿主自己的配置。命令里只留变量名（`KeyArgument`），展示时画成占位符，呈现层的函数从不收值。
- 提问回答之后从屏幕上擦掉（`clearPromptOnDone`），由呈现层另写一行结局；`@inquirer/password` 设 `mask: false`、`toggleMask: false`。
- 命令没能起来时，失败的原因只取错误码；错误没带错误码就只说「添加命令没能运行」，不取它的消息（评审后改的：原先退而取消息，消息里可能带着整条命令）。执行器当场抛出的也算这一项失败，不成为「意外错误」。这条对不带 key 的 MCP 同样生效。
- 结果分区数行数时改成按终端上实际占的行数算（评审后改的）：跳过的原因里有目录给的变量名，一个比一行还长的词会被终端折开，原先按条数算会把「结果」的标题改写到别的行上。这段代码 skill 的结果也在用。
- 新增一个运行时依赖 `@inquirer/password`（连同它带的 `@inquirer/ansi` 等都是已有子包共用的）。

## 评审后没有改的

- key 的值不校验就成了一个参数。它是用户自己输入的，不是远程数据；但 `cross-spawn` 对全局装的 `.cmd` 只转义一次，值里有双引号（比如连引号一起粘贴）时在 Windows 上可能传错。拒绝、剥掉引号还是不管，**需要维护者定**。
- key 作为命令行参数传给宿主，命令运行的那一瞬间本机别的进程看得到。这是规格定的做法。
- `typeof arg !== 'string'`（判断命令里的一项是不是 key）散在 `flow.ts`、`install-mcp.ts`、`ui.ts` 三处；`McpJob` 用空的 `steps` 加 `missingVariable` 表示这一项不装。
- 上一张工单留下的几条（`CommandRunner` 的两个参数、`McpStatus` 里的 `unsupported`、`ui.mcpSummary` 与 `ui.installSummary` 各写一份）照旧。
- 视觉评审认为回答之后应当把整个 key 的分区收成一行；没有改，安装器不回头改已经打出去的行。结果里「跳过」和原因之间只隔一格，是工单 06 定下的画法，没有动；只把英文的原因改短了（`no value for <变量>`）。

## 没有验证的

- 用真实的 `claude`、`codex` 和正式的命令执行器，在临时的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 下经安装器端到端走了新装和覆盖两遍：值进了两个宿主的配置，覆盖那一遍没有再问必填的 key，输出里没有值，安装器没有写任何文件。**第一次跑的时候临时目录只传给了入口、没有设在进程环境上，两条添加命令写进了真实的 `~/.claude.json` 和 `~/.codex/config.toml`（一条叫 `oxy-probe-keyed` 的探针，值是编的）；发现后当场用宿主的移除命令撤回，复核过两边都没有它了。**
- Windows 上带 key 的参数经 `cmd.exe` 起 `.cmd` 的那一支没有在真机上跑过。
- 没有用真实的、需要 key 的 MCP 服务器验证过装上之后宿主起得来（目录里还没有真实条目）。
- 测试在本机的 macOS 上用 Node 24 和 22.13.0 各跑过一遍；Linux 和 Windows 要等推送后由 CI 跑。
