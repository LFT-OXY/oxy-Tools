# 02 — 标志上色，焦点色换成洋红

**What to build:** 用户在支持 24 位色的终端里看到从左到右由粉到紫到蓝的渐变大标志；终端不支持时整个标志是终端自己的洋红；设了 `NO_COLOR` 时不上色。提问标记、光标、已勾选的框、转动符号一律换成洋红，和标志是一个色系。

**Blocked by:** 01
**Status:** ready-for-agent
**Impl:** ready

- [ ] 先改规范：界面设计规范的颜色表里，青色那一行换成洋红（含义不变：当前焦点，只用在符号上）；「只用八个基本色」「大标志不上色」写明标志渐变这一个例外、三个色标和两档退路；「符号的含义」里大标志一行跟着改。终端输出规范的「上不上色」写明标志的例外和 `COLORTERM` 的判断。然后才改实现。
- [ ] 环境变量 `COLORTERM` 等于 `truecolor` 或 `24bit` 时，标志的每个方块带 24 位的前景色；否则整个标志用洋红（八个基本色之一）。不做 256 色的近似。
- [ ] 渐变按列算，同一列的方块同色，最左一列是 `#E255C0`，最右一列是 `#3D8FE6`，中间经过 `#8B5CF6`。算法取自原型：

  ```js
  const STOPS = ['#E255C0', '#8B5CF6', '#3D8FE6'];
  // t 是这一列在标志里的位置：列号 ÷（标志的宽 − 1），最左是 0，最右是 1
  const scaled = t * (STOPS.length - 1);
  const index = Math.min(STOPS.length - 2, Math.floor(scaled));
  // 这一列的颜色 = 第 index 个色标到第 index + 1 个色标之间，红、绿、蓝各自按 (scaled − index) 线性过渡
  ```

- [ ] 「这个流是终端、且环境里没有 `NO_COLOR`」才带样式，标志也受它管：设了 `NO_COLOR`（哪怕为空）或输出不是终端时，原始输出里一个样式码都没有，画面文字与带样式时一字不差。
- [ ] 没有 Unicode 的终端里，ASCII 字符画仍是粗体、不上色：不画渐变，也不用洋红。
- [ ] 提问标记 `?`、光标 `▸`、已勾选的 `■`、转动符号是洋红；安装器的输出里不再有青色的样式码。交互库自带的样式没有漏出青色的（主题要盖全）。
- [ ] 状态词和结果符号的绿、黄、红，暗淡、粗体、下划线的用法都不变；名字、说明、命令仍是默认前景色。
- [ ] 经主接缝的测试：有 `COLORTERM=truecolor` 时原始输出里有 24 位色的前景色码，标志最左一列是 `#E255C0`、最右一列是 `#3D8FE6`；`COLORTERM=24bit` 同样；没有 `COLORTERM` 时没有 24 位色的码、标志带洋红的码；`NO_COLOR` 与 `COLORTERM` 同时设置时一个样式码都没有；整段输出里没有青色的码。
- [ ] 测试在 Node 22.13 上也跑过一遍（样式码与 Node 版本有关）。
- [ ] 界面预览页读得出单元格 24 位的前景色并照样画出来；新增「标题区 · 渐变」「标题区 · 洋红（没有 `COLORTERM`）」「标题区 · 不显示颜色」的场景。
- [ ] UI: 标题区 / 渐变 / 深色与浅色 — 标志最左一列是粉、中间是紫、最右一列是蓝，同一列上下同色；两种背景上三段颜色都看得清。
- [ ] UI: 标题区 / 洋红 / 深色与浅色 — 整个标志一个颜色，和焦点符号同色。
- [ ] UI: 主菜单、多选列表、加载中 / 默认 / 深色与浅色 — `?`、`▸`、`■`、转动符号是洋红；画面上没有青色。
