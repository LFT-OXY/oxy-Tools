# 05 — 块与块之间空一行

**What to build:** 用户看任何一个画面时，提问和它的选项、分区标题和它的内容、已回答的提问和下一块、说明和按键提示之间都隔着一行，一眼分得出哪一块是哪一块。条目与条目之间不插空行，一屏仍然放得下整张列表。

**Blocked by:** 03
**Status:** ready-for-agent
**Impl:** done

- [x] 先改界面设计规范：「版式的总规则」或「横线、分区与键值行」里写明下面四条空行的规则，以及「任何地方不出现连着两行空行」。然后才改实现。各节的画面示例留给工单 06 统一重画。
- [x] 规则 1：提问与它下面的表或选项之间空一行。用到每一个单选和多选，包括语言提问、主菜单、选择宿主、三类组件的列表、应用项目列表、汇总之后的确认。做法限于交互库给的口子（空行接在提问的末尾，不放进列表：维护者 2026-10-10 改定，原先写的是列表第一行放一个空白的分隔行）。是否题和隐藏输入下面没有选项，不受影响。
- [x] 规则 2：分区标题下方空一行。用到每一个分区：汇总、将执行的命令、key 的说明、正在安装与结果、每个工具的执行、应用项目详情、出错、帮助的三个分区。「正在安装／结果」分区里，最后一行结果与收尾的通栏横线之间也空一行。
- [x] 规则 3：已回答的提问与下一块（本机信息、下一个提问、分区）之间空一行；连着的几行已回答的提问之间不空。
- [x] 规则 4：列表下方，光标所在行的说明全文与按键提示之间空一行；「这一项现在选不了」「请输入 y 或 n」那一行在同一个位置，同样处理。没有说明时，列表与按键提示之间仍只有原来的那一行空行。
- [x] 任何地方都不出现连着两行空行：规则之间、规则与原有的空行（退出与分组之间、回到主菜单时、通栏横线后面紧跟分区标题时）叠在一起时只留一行。（留下一处原有的限制：列表滚动的那一页恰好停在「退出」「返回」上方的空白分隔行时，它与列表下方的空行相连；应用项目多到一屏放不下才碰得到，记在界面设计规范里。）
- [x] 条目与条目之间不插空行；表头与条目之间不空行。
- [x] 「正在安装」的标题在结束时仍被改写成「结果」，且落在原来那一行上；标题下方的空行还在。往上数几行的算法把新增的空行算进去。
- [x] 列表一屏放多少行的算法把新增的空行算进去：在 24 行的终端里，提问那一行不被顶出屏幕，条目没超过一屏（15 个，维护者 2026-10-10 定）时列表不滚动。
- [x] 工具的执行分区里，命令自己的输出仍然原样透传、顶格、不加样式；空行只加在分区标题下方。
- [x] 按键提示整行仍在 79 列以内；中文与英文界面同一套规则。
- [x] 提问实际打到终端上的东西（空白的分隔行、说明与按键提示之间的空行）用真实交互库加脚本按键的跑法核对；标题改写后的画面用无头终端还原来断言。现有测试里断言空行位置的相应改掉。
- [x] UI: 主菜单 / 默认 / 80 列，深色与浅色 — `Language / 语言` 那一行与本机信息之间空一行；「选择分组」与表头之间空一行；没有连着两行空行。
- [x] UI: skill 多选列表 / 光标在有说明的条目上 — 已回答的两行与提问之间空一行；提问与表头之间空一行；说明全文与按键提示之间空一行。
- [x] UI: skill 多选列表 / 在不可选的条目上按空格 — 「这一项现在选不了」与按键提示之间空一行。（skill 列表里没有不可选的条目，用 MCP 列表取证。）
- [x] UI: 汇总 / 含覆盖项 — 分区标题与表头之间空一行；「开始安装吗」与三个选项之间空一行。
- [x] UI: 结果 / 有成功、失败、跳过 — 标题是「结果」且在原位；标题与第一行结果之间、最后一行结果与通栏横线之间各空一行。
- [x] UI: 填写 key、工具的执行、应用项目详情、出错、帮助 / 默认 — 每个分区标题下方恰好空一行。
- [x] UI: 24 行的终端 / 条目较多的多选列表 — 提问那一行在屏幕上。
