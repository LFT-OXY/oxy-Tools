# 安装器启动画面改版：语言选择、渐变大标志、去标语、放宽间距

> 术语以仓库根 `GLOSSARY.md` 为准：正文说「宿主」，界面文案里它显示为「AI Agent」。安装器自成一体的三条规矩见 ADR-0001。
> 本 spec 的决策来自 2026-10-10 的访谈（Q1–Q14），除「Further Notes」里单列的六条推断外，都经维护者逐条确认。选定的画面见同目录的 `ui-direction.md`。

## Problem Statement

用安装器的人启动 `oxy-tools` 之后遇到三件事：

- **语言是替他猜的。** 界面语言按系统语言环境判断。系统是英文、人读中文的（或反过来），得先知道有 `--lang` 这个参数才改得了。
- **启动画面不好看。** OXY 大标志是不上色的实心方块，靠左摆着，右下角压着产品名、版本号和一句「策展式 AI 工具链安装器」，下面一条横线。维护者想要图 1（omp）那样的观感：渐变的像素标志居中，四周留白。那句标语他不想在终端上看到。
- **画面太密。** 提问紧跟着表头，分区标题紧跟着内容，已回答的提问紧跟着下一问，栏与栏只隔两格。字挤在一起，看不清哪一块是哪一块。

## Solution

- 启动后先打出居中的渐变大标志，下面是产品名和版本号；紧接着第一问就是语言：`中文` 还是 `English`。光标默认停在按系统语言猜出的那一项上，猜对了按一下回车就过。给了 `--lang` 就不问。
- 大标志从左到右由粉过渡到紫再到蓝。终端不支持 24 位色时整个标志是终端自己的洋红；设了 `NO_COLOR` 时不上色。
- 「策展式 AI 工具链安装器」不再出现在终端上。
- 「当前焦点」的颜色由青换成洋红，和标志呼应。
- 所有画面在块与块之间让出一行，表的栏间隔加到三格。条目与条目之间不插空行。

## User Stories

### 语言

1. 作为用户，我想启动后第一问就让我选语言，这样不用先知道 `--lang` 也能用我读得懂的界面。
2. 作为用户，我想语言的选项写成 `中文` 和 `English`，不随界面语言变，这样读哪种语言的人都认得出自己的那一项。
3. 作为用户，我想提问本身写成双语的 `Language / 语言`，这样没选之前我也知道它在问什么。
4. 作为系统语言是中文的用户，我想光标默认停在 `中文` 上，这样按一下回车就过去了。
5. 作为系统语言不是中文的用户，我想光标默认停在 `English` 上，理由同上。
6. 作为用户，我想选完之后这一问收成一行留在屏幕上，这样回头看得到自己选了什么。
7. 作为用户，我想选了哪种语言，之后的目录说明、菜单、提问、出错说明就全是哪种语言。
8. 作为用户，我想语言提问上的按键提示用系统语言写，这样它大概率是我读得懂的那种。
9. 作为写脚本或熟悉参数的用户，我想给了 `--lang zh` 或 `--lang en` 就不再问，这样可以跳过这一步。
10. 作为用户，我想 `--help` 和 `--version` 不问语言，直接给出结果。
11. 作为用户，我想参数写错时直接看到出错说明，而不是先被问语言。
12. 作为在管道或重定向里运行的用户，我想没有交互式终端时照旧只看到出错说明，不出现语言提问。
13. 作为用户，我想在语言提问上按 Ctrl+C 能干净退出，和别的提问一样。
14. 作为用户，我不希望安装器为了记住语言在我的主目录里多写一个配置文件。

### 标题区

15. 作为用户，我想一启动就看到居中的 OXY 大标志，语言提问排在它后面，这样第一眼看到的是产品。
16. 作为用户，我想标志从左到右由粉到紫到蓝，这样启动画面有辨识度。
17. 作为用户，我想标志下方隔一行写着产品名和版本号，这样知道自己在用哪一版。
18. 作为维护者，我不想在终端上看到「策展式 AI 工具链安装器」这句话，无论是标志旁边还是 `--help` 里。
19. 作为在 npm 上搜到这个包的人，我想包的介绍里仍然写着它是干什么的。
20. 作为用户，我想标志下面不再贴着一条横线，这样标志周围是留白的。
21. 作为用宽窗口的用户，我想标志按 80 列居中，而不是按窗口的实际宽度，这样它和下面靠左排的内容不脱开。
22. 作为用户，我想大标志仍然一次运行只出现一次，回到主菜单时不重复。

### 颜色与各种终端

23. 作为终端支持 24 位色的用户，我想看到真正的渐变。
24. 作为终端不支持 24 位色的用户，我想标志是终端自己配色里的洋红，而不是一堆对不上的颜色或乱码。
25. 作为设了 `NO_COLOR` 的用户，我想标志和别的输出一样完全不带样式，文字一字不差。
26. 作为用旧式控制台（没有 Unicode）的用户，我想标志仍是 ASCII 字符画，摆法和新的一致。
27. 作为用深色终端的用户，我想标志的三段颜色和洋红的焦点符号都清楚。
28. 作为用浅色终端的用户，我想同上。
29. 作为用户，我想提问标记、光标、已勾选的框、转动符号的颜色和标志是一个色系。
30. 作为用户，我想「已装」「失败」「注意」这些状态词的颜色含义不变，这样以前的认知还管用。
31. 作为用户，我想名字、说明、命令这些正文仍是终端的默认前景色，这样在哪种背景上都读得清。

### 间距

32. 作为用户，我想提问和它下面的表或选项之间空一行，这样一眼分得出问题和选项。
33. 作为用户，我想分区标题下面空一行，这样标题不压着内容。
34. 作为用户，我想已回答的那几行和下一块之间空一行，这样分得出哪些是过去的、哪个是现在的。
35. 作为用户，我想光标所在行的说明全文和按键提示之间空一行，这样两者不连读。
36. 作为用户，我想表里栏与栏隔得开一点，这样状态和说明不挤在一起。
37. 作为用户，我想条目之间不插空行，这样一屏仍然放得下整张列表。
38. 作为用户，我想每一类画面的间距是同一套规则，而不是有的松有的紧。
39. 作为用英文界面的用户，我想得到同样的间距。
40. 作为用户，我想按键提示仍然一行写完，不被终端折行。

### 维护

41. 作为维护者，我想界面设计规范先于实现改好，这样规范和画面不会各走各的。
42. 作为维护者，我想界面预览页上看得到渐变的标志和语言提问，这样不用启动真实终端也能核对。
43. 作为改安装器的人，我想现有的测试不必每一条都多答一次语言，这样测试读起来仍然只说它关心的事。
44. 作为改安装器的人，我想渐变、洋红、不上色三档各有测试卡着，这样改上色的逻辑时不会悄悄坏掉一档。

## Implementation Decisions

### 启动顺序与语言

- 顺序是：解析启动参数 → 参数有误、`--help`、`--version`、没有交互式终端这四种情况照旧处理并退出 → 打大标志 → 没给 `--lang` 就问语言 → 读取目录 → 本机信息 → 主菜单。
- 入口的签名不变：五样可替换的外部依赖、系统语言环境、输出流等都照旧。语言提问用提问器现有的单选，不加新的提示种类，不加依赖。
- 系统语言的判断方法不变（`LC_ALL`、`LC_MESSAGES`、`LANG`，都为空时看系统语言环境）。它现在有三个用途：语言提问上光标的起始位置；语言提问的按键提示用哪种语言；不问语言的那四种情况下输出用哪种语言。
- 语言提问的文案和两个选项是固定的字，不放进按语言分的文案里：提问 `Language / 语言`，选项依次是 `中文`、`English`。
- 界面语言在一次运行的中途才定下来。大标志和语言提问用按系统语言建的呈现层；选定之后的一切输出用选定的语言。「画面上是否已经有内容」这个状态要跨过这次切换——分区标题上方空不空行靠它判断。
- 语言的选择只存在于这次运行的内存里。安装器不新增配置文件，不往主目录写任何与语言有关的东西。
- 在语言提问上按 Ctrl+C，和别的提问一样以 130 退出。

### 标题区

- 字形不变（5 行实心方块，宽 25 列）。标志每一行左边补空格，使整个标志在 80 列里居中；不看终端的实际宽度。
- 标志上方空一行；标志下方空一行，然后是居中的 `oxy-tools <版本号>`，产品名粗体、版本号暗淡；再空一行。标志下面不画通栏横线。
- 标语从中英两份文案里去掉。它在终端上的两处用法——标志旁边、帮助的第一行——随之消失；帮助的第一行只剩产品名和版本号。
- 包的 README 和包描述里的介绍文字不动。

### 上色

- 「这个流是终端、且环境里没有 `NO_COLOR`」才带样式，这条判断不变，标志也受它管。
- 在它之上新增一条只管标志的判断：环境变量 `COLORTERM` 等于 `truecolor` 或 `24bit` 时画渐变，否则整个标志用洋红（八个基本色之一）。不做 256 色的近似。
- Node 自带的样式函数只有命名色，渐变的样式码由呈现层自己拼：每个方块一个 24 位的前景色。这是「上色只用 Node 自带的样式函数」这条规矩唯一的例外，只用在标志上。
- 渐变按列算，同一列的方块同色。算法取自原型：

  ```js
  const STOPS = ['#E255C0', '#8B5CF6', '#3D8FE6'];
  // t 是这一列在标志里的位置：列号 ÷（标志的宽 − 1），最左是 0，最右是 1
  const scaled = t * (STOPS.length - 1);
  const index = Math.min(STOPS.length - 2, Math.floor(scaled));
  // 这一列的颜色 = 第 index 个色标到第 index + 1 个色标之间，红、绿、蓝各自按 (scaled − index) 线性过渡
  ```

- 没有 Unicode 的终端里标志是 ASCII 字符画，粗体，不上色（不画渐变，也不用洋红）。
- 焦点色由青换成洋红，四处：提问标记、光标、已勾选的框、转动符号。改完之后安装器的输出里不再有青色。
- 状态词和结果符号的绿、黄、红，暗淡、粗体、下划线的用法都不变。

### 间距

五条规则，用到每一类画面：

1. 提问与它下面的表或选项之间空一行。做法限于交互库给的口子：列表的第一行放一个空白的分隔行。是否题和隐藏输入下面没有选项，不受这条影响。
2. 分区标题下方空一行。「正在安装／结果」分区里，最后一行结果与收尾的通栏横线之间也空一行。
3. 已回答的提问与下一块（本机信息、下一个提问、分区）之间空一行。连着的几行已回答的提问之间不空。
4. 列表下方，光标所在行的说明全文与按键提示之间空一行。「这一项现在选不了」那一行和说明是同一个位置，同样处理。
5. 表的栏间隔由两格改成三格：主菜单、三类组件的列表、应用项目列表、汇总、将执行的命令、结果行、帮助里的两栏表。

随之要顾到的三处：

- 「正在安装」的标题在结束时要回头改写成「结果」，往上数几行是按标题下面打出的行数算的；标题下方多出的空行要算进去。
- 列表一屏放多少行的算法要把新增的分隔行和空行算进去，免得列表比以前更早开始滚动、或把提问顶出屏幕。
- 汇总里备注的放法规则不变（每一条都放得下才成一栏，否则都另起一行）；栏间隔变宽后会更常另起一行，这是预期之内的。

任何地方都不出现连着两行空行。不做整体左缩进：交互库把光标和勾选框写死在行首。

### 规范先行

- 界面设计规范先改，再改实现，然后生成界面预览页对照。要改的内容：标题区一节的画法；颜色表里青色的那一行换成洋红；「只用八个基本色」「大标志不上色」加上标志渐变这一个例外和它的两档退路；「通栏横线只用在三处」去掉大标志下方；「栏宽…再加两格间隔」改成三格；各节的画面示例按新的间距重画；帮助第一行的说明；文末「还没经维护者确认的画法」里这次确认过的移出去。
- 终端输出规范里「上色只用 Node 自带的样式函数」加上标志的例外和 `COLORTERM` 的判断。
- 入口规范里启动参数 `--lang` 的行为、语言环境变量的用途、启动顺序跟着改。
- 包的 README 里 `--lang` 的说明（中英各一处）改成「缺省时启动后询问」的意思；帮助里同一句也改。

## UI and Design

选定的方向、没选的候选和原因、四个画面的画法都在 `ui-direction.md`，这里只列要点：

- **方向**：结构取图 1（无边框、渐变标志居中、留白分区），不做图 2 的边框面板。正文各画面仍是现行的「账本」画法，只改焦点色和间距。
- **维护者选的**：标志候选 01（现字形、从左到右渐变）；间距「适中」一档。
- **没选的**：斜向渐变（5 行高看不出差别）；3×3 大像素字形（X 不像字母、退成纯洋红时太重）；「宽松」一档（每个画面多 4 到 6 行，表头与条目之间隔了空行对不上）。

必须有的画面与状态：

| 画面 | 状态 |
|------|------|
| 标题区 | 渐变；洋红（没有 `COLORTERM`）；不上色（`NO_COLOR`）；ASCII 字符画（没有 Unicode） |
| 语言提问 | 提问中，光标在 `中文`；提问中，光标在 `English`；已回答收成一行；给了 `--lang` 时不出现 |
| 主菜单、条目列表、汇总、结果 | 新间距下的默认状态，中文与英文 |
| 其余画面（选择宿主、填写 key、将执行的命令、工具的执行、应用项目、出错、帮助） | 新间距下各一格 |

目标尺寸：80 列的终端，深色和浅色背景各一。

适用的设计规则：`.atw/spec/cli/ui-design.md`（本任务会先改它）和 `.atw/spec/cli/terminal-output.md`。

界面验收标准（在界面预览页或真实终端的画面上能核对的）：

- 标志的最左一列是粉、中间是紫、最右一列是蓝；同一列上下同色。
- 标志左右两侧的空白相等（差不超过一列）；产品名与版本号那一行同样居中。
- 标志与产品名之间恰好空一行；产品名与下面的语言提问（或已回答的那一行）之间恰好空一行；标志下面没有横线。
- 画面上找不到「策展式 AI 工具链安装器」或 `Curated AI toolchain installer`。
- `?`、`▸`、`■`、转动符号是洋红；画面上没有青色。
- 每个提问与它的第一行选项或表头之间恰好空一行；每个分区标题与它下面的第一行内容之间恰好空一行。
- 任何地方没有连着两行空行。
- 表里相邻两栏之间，最长的一格后面恰好是三格空白。
- 按键提示在一行之内，不超过 79 列。
- 浅色背景上，标志的三段颜色和洋红的符号都看得清。

## Testing Decisions

- **好的测试只断言对外的行为**：给定目录、主目录的初始状态、环境和一串应答，看终端上输出了什么、退出状态是多少。不为内部模块单独写测试。
- **接缝仍只有现有的那一个**：安装器入口，经测试架子的 `run(...)`。不新增接缝。观感仍由界面预览页加视觉评审把关，它经同一个入口驱动安装器。
- **测试架子缺省替用户在语言提问上按回车**，也就是接受光标起始所在的那一项。这样现有的测试不用改应答序列，它们靠环境变量和系统语言环境决定界面语言的写法也继续成立——光标的起始位置就是按那个判断的。专门测语言提问的用例才自己应答。用真实交互库加脚本按键的那种跑法同样缺省先按一次回车。
- **样式码是这次要断言的对外行为**。现有先例是 `startup.test.ts` 里「颜色」一组：断言原始输出里有没有样式码。照这个做法新增：有 `COLORTERM=truecolor` 时原始输出里有 24 位色的前景色码，且第一个是 `#E255C0`、标志最右一列是 `#3D8FE6`；没有 `COLORTERM` 时没有 24 位色的码、有洋红的码；`NO_COLOR` 时一个样式码都没有，且画面文字与带样式时相同；整个输出里没有青色的码。
- **语言提问要有的用例**：不带 `--lang` 时第一问是它，两项的字和顺序；系统语言是中文时光标起始在 `中文`，否则在 `English`；选了与系统语言不同的那一项后，后面的画面是选定的语言；带 `--lang` 时不问；`--help`、`--version`、参数有误、没有交互式终端时不问；在它上面按 Ctrl+C 以 130 退出；回答后收成一行。先例是 `startup.test.ts` 的「语言」一组和 `prompts.test.ts`。
- **提问实际打到终端上的东西**（空白的分隔行、说明与按键提示之间的空行、洋红的符号）用真实交互库加脚本按键的跑法核对，先例是 `prompts.test.ts`。
- **回头改写标题**的行为用无头终端还原画面来断言（先例：`screenLines`）：结束后「结果」的标题在原来「正在安装」的那一行上，标题下方的空行还在。
- 现有测试里断言栏间隔、空行、标语、大标志位置的要跟着改；断言文字内容的不该受影响。
- 样式码与 Node 版本有关，测试要在 Node 22.13 上再跑一遍。

## Acceptance Criteria

- [ ] 交互式终端里不带 `--lang` 启动：大标志之后第一问是 `Language / 语言`，两项依次是 `中文`、`English`；系统语言是中文时光标起始在 `中文`，否则在 `English`。
- [ ] 选了哪种语言，之后的全部画面就是哪种语言；回答收成一行留在屏幕上。
- [ ] 带 `--lang zh` 或 `--lang en` 启动时不出现语言提问。
