# 第三方 skill 不收进仓库，由 skills CLI 装

第三方 skill 的内容留在作者的仓库，目录只按仓库登记；用户选中后，安装器调用 `npx skills add`（Vercel 的 skills CLI）把它装进宿主。本仓库自己的 skill，以及此前已经整包收进来的四个（archify、onetake、unlazy、shuorenhua）不变，仍由安装器复制。起因是要收录的第三方 skill 有三十来个仓库、上百个：逐个整包引入要搬运、改目录名、跟进上游更新，而其中约一半（插件型的、本体是另一个程序的）复制进来也不完整。

**Status**: accepted

**Considered Options**:

- 整包收进本仓库（此前的规则）。好处是用户装到的就是维护者看过的那一份，上游改名、删库都不影响。被放弃是因为人工成本，以及它对仓库的影响：安装器装任何 skill 前都要列出整个仓库的文件树，列表被 GitHub 截断就一个都不装，而待收录的仓库里有一个 skill 就带 13016 个文件。
- 安装器自己从上游仓库按提交号下载。好处是能钉住版本，状态探测和覆盖前的询问也能与本仓库的 skill 一致。没有选是因为要为别人的仓库再做一遍下载、限流和各种目录布局的识别（一个仓库多个 skill、仓库根就是 skill），这些 skills CLI 已经做了；调查的 20 个仓库里有 11 个的官方安装说明写的就是它。
- 逐个照抄各仓库的官方安装方式。没有选是因为做法不统一：插件命令只适用于 Claude Code，有的仓库根本没有可执行的命令。

**Consequences**:

- 用户装到的是作者当时的最新版，维护者没有逐版检查；条目会因为上游改名、删库而失效，要等有人反馈才知道。界面上第三方 skill 自成一段，段首写明内容直接来自作者；确认之前另有一行提醒。
- 安装器依赖 skills CLI 的参数和行为（2026-10-10 在 macOS 上实测 1.7.2）：带齐 `--skill`、`-a`、`-y` 时不提问；`--json` 给出机器可读的结果，但不能与 `--list` 同用；遇到同名目录直接覆盖，不询问；默认带遥测。所以调用前由安装器自己判断是否覆盖并询问，调用时关掉遥测。
- 调用时必须切断它的输入输出：不切断，它会把自己的字符画和框线打到终端上。
- 插件型的 skill 这样装上没有 hooks，不会自动触发；条目的说明里写明完整功能要按官方方式装插件。
- 装法没有实际试通过的条目，先作为外部项目登记，试通了再改成组件。
