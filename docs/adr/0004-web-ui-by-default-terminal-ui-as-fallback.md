# 安装器缺省打开本机的网页界面，终端界面留作退路

安装器启动后在本机起一个只有这台机器能访问的网页，用默认浏览器打开，从挑选、确认到安装进度和结果都在网页界面里完成；打不开浏览器的机器（远程连接、没有桌面）上改用原来的终端界面。起因是终端界面排不开：一个用途下各种类型的条目挤在一张 80 列的表里，说明被截断，维护者看了觉得用户看不过来；而目录 110 条里有 64 条（2026-10-11）是只给链接的外部项目，正是终端最不擅长展示的。

**Status**: accepted

**Considered Options**:

- 只改终端界面的排版（把外部项目从勾选表里分出去、说明不截断）。好处是改动最小、所有机器都能用。没有选是因为好看的上限仍是终端。
- 公开的目录网站，挑好后生成一条命令贴进终端。好处是不装也能逛、链接能转发。没有选是因为它看不到这台机器上装了什么，而目标只是让正在安装的人挑得舒服，不是对外展示。
- 网页界面只管挑选，确认和安装回终端。好处是工作量小。没有选是因为用户要在两个窗口之间来回跳。

**Consequences**:

- 两套界面要一起维护，但不要求行为一样：网页界面一页到底，可以跨用途一起挑、一次确认、一次装完；终端界面仍是逐步提问、一次一个用途。定下这件事时终端界面原样不动。
- 此前「不做全屏界面、不为好看自写交互控件」的规定（`.atw/spec/cli/ui-design.md`）只管终端界面。
- 安装器要自己判断这台机器打不打得开浏览器，判断不出来时也得有退路：终端里始终留着网址和改用终端界面的办法，另有启动参数强制用终端界面。
- 工具的安装命令要接管终端的输入输出，仍在终端里跑，网页界面只提示去看终端。
- 网页界面的汇总不把将执行的命令列给用户看（维护者 2026-10-11 定的：用户不关心），终端界面照旧「先展示再执行」。执行的命令两边是同一份，仍由安装器照目录自己拼。代价是用网页界面的人在确认之前看不到这台机器上将要运行哪些命令，要看只能改用终端界面。
- 本机的这个网页能替用户执行安装命令，所以它必须拒绝别的网站和别的机器发来的请求。
- API key 也在网页界面里填，不为它切回终端：值只留在内存里交给安装动作，不存进浏览器，不写任何文件。浏览器扩展理论上读得到页面里的输入，维护者接受这个风险——那把 key 本来就是从同一个浏览器里的服务商页面上复制来的。
