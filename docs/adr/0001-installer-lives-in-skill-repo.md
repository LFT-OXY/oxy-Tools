# 安装器先放在本仓库的 cli/ 子目录

安装器的源码放在本仓库的 `cli/` 下，从该子目录发布到 npm，而不是另开一个仓库。安装器刚起步时，条目格式、目录数据和安装代码会一起反复改，放在一处最省事；真正难搬的是目录数据（见 ADR-0002），代码放哪以后可以再改。

**Status**: accepted

**Considered Options**: 安装器独立成仓库、目录数据留在本仓库。好处是许可证、体积和提交历史都不混；被搁置是因为起步阶段每次改条目格式都要跨两个仓库，还要为新仓库再配一套规范和术语表。

**Consequences**:

- 为了以后能原样搬走，`cli/` 守三条规矩：自带 `package.json`，仓库根目录不放；只通过公开网址读目录，不引用 `cli/` 以外的文件（维护者预览时可以用环境变量把目录来源指到一个本地目录，那是用户给的路径，不是代码对仓库文件的引用）；测试和构建只扫 `cli/` 内部（`skills/` 下的上游整包自带测试和 `package.json`，不能被扫进来）。
- 本仓库不再是纯 skill 分发仓库：`cli/` 用 MIT，各 skill 沿用各自的许可证，需按目录分别声明。
- 不提交 `node_modules` 和构建产物——A Team Workflow 安装额外 skill 时会把整个仓库下载下来。
- 搬出去的信号：条目格式稳定了，或有外部贡献者开始改 `cli/`，或许可证混放带来了实际麻烦。
